## 1. 背景与目标

### 1.1 背景

当前触底锁定为**固定 500ms 缓冲**（`LOCK_DELAY_MS=500`，AC-03.5；game.js 顶部常量、verify-game.cjs §r18 锚点）：方块触地后 `lockTimer` 按真实流逝时间累计，满 500ms 即锁定。此语义下：

- 缓冲期内成功**横向移动/旋转**（含踢墙命中）**不重置**计时（仅当动作使方块**脱离触底**时才清零）——玩家在触底瞬间无法通过连打方向键/旋转争取最后的落位微调，操作手感生硬；
- 另一方面，若简单改成「每次成功动作都重置」，玩家可沿地面往复滑动无限拖延锁定，破坏节奏与公平。

推荐方案（已确认执行）：「触底后 500ms 固定」+ **缓冲期成功移动/旋转重置至满额** + **每方块重置上限 15 次**，被拒动作不重置不发声，软降触底/硬降两条立即锁定路径保持原样。

### 1.2 目标

- 触底缓冲期内的每次**成功**横向移动/旋转，把锁定缓冲计时**重置回满额**（重新计满 500ms 才锁定），给玩家最后一次落位微调机会；
- 防无限拖时间：**每方块重置上限 15 次**（`LOCK_MOVE_RESET_MAX`，旋转与移动计入同一上限）；
- 预算为 **per-piece 会话内存**（随出生/hold/restart 归零），杜绝「悬空滑出再落地」反复吃缓冲；
- **零回归**：软降触底立即锁定、硬降立即锁定两条路径不变；r18 T-spin 窗口判据、combo/B2B 链迁移、触控=键盘回放路径不变；ui/audio/persist/style 零 diff、代码头 VERSION 不动。

### 1.3 行为变化（取代声明）

| 项目 | 现状（AC-03.5） | 本需求后 |
|---|---|---|
| 触底缓冲语序 | 触底后 ≤500ms 固定（固定计时，成功动作不重置） | 触底后 500ms 固定；缓冲期间每次成功移动/旋转重置至满额 |
| 重置预算 | 无上限（仅脱离触底清零） | 每方块至多 15 次（旋转+移动同一上限），随出生/hold/restart 归零 |
| 被拒动作 | 不发声、无效 | 不重置缓冲、不消耗预算、不发声（不变扩展） |
| 软降触底 / hardDrop | 立即锁定、不走缓冲 | **保持不变**（立即锁定、不消耗预算） |
| r18 T-spin 窗口 / 链迁移 / 触控回放 | — | **零回归**（AC-6/7） |

## 2. 用户故事与验收标准

### US-1 缓冲重置与上限（P0）

> 触底后玩家仍可在 500ms 内通过成功移动/旋转争取最后落位；预算耗尽后无法继续拖延。

- **AC-1（P0）成功移动/旋转重置满额**：触底缓冲期内（方块触底、`lockTimer` 累计中），每次**成功的横向移动或旋转**（含踢墙命中）把锁定缓冲计时**重置回满额**（重新计满 `LOCK_DELAY_MS=500` 才锁定）；成功动作使方块脱离触底时沿用既有清零路径（回合到「悬空」态）。脚本断言（tick 上限 250ms、`lockTick=2×250ms`）：触底 → `tick(250)` → 成功移动 → 再 `tick(250)` **不锁定**（被重置，累计仅 250）→ 再 `tick(250)` 累计满 500ms 锁定；无重置对照（被拒或预算耗尽）则 `tick(250)` 后即锁定。
- **AC-2（P0）被拒不重置不发声**：移动碰撞（`reason:'blocked'`）、旋转失败（`wall-kick-denied`，含踢墙关闭/全偏移失败）**不重置缓冲、不消耗预算、不发移动/旋转音效**；缓冲按既有速率继续累计。脚本断言：触底 → 被拒动作 → `tick(250)×2` 仍按无重置口径锁定；onSfx 序列无新增 move/rotate。
- **AC-3（P0）每方块上限 15 次（LOCK_MOVE_RESET_MAX）**：预算 = 15，旋转与移动计入**同一上限**；预算耗尽后，成功移动/旋转**不再重置**缓冲（计时继续累计至 500ms 锁定）。脚本断言：同一方块连续成功移动/旋转 16 次 → 前 15 次均触发重置（每次需重新计满 500ms）、第 16 次起不重置（锁定时机 = 最后一次重置后累计满 500ms）。
- **AC-4（P0）per-piece 会话内存与防钻空子**：预算随**出生（spawnFirst）、hold 交换、restart 归零**；同一方块全程共用 15 次，「悬空滑出再落地」（成功动作使方块脱离触底清零后再次触底）**不补发预算**。脚本断言：方块 A 耗尽预算 → hold 换出方块 B → B 预算恢复 15；A 滑出边缘再落地后剩余预算仍为 0。
- **AC-5（P0）软降/hardDrop 两条路径不变**：软降触底 → **立即锁定**、hardDrop → **立即锁定**，均不走缓冲、**不消耗预算**；事件与计分序列与现状逐字节一致（含 r18 清窗语义：软降触底/硬降在 `lockFlow` 前清 `tspinPending`）；软降成功下移（未触底）的既有 `lockTimer` 清零路径不变、不计入预算。

### US-2 零回归（P0）

> 新语义只作用于锁定缓冲计时，不触碰任何既有判定链。

- **AC-6（P0）r18 T-spin 窗口判据零回归**：旋转置窗（含踢墙命中）、横向移动清窗、自然重力下移清窗、软降成功/触底清窗、硬降清窗、旋转落地后经 lockTimer 锁定仍判（E11）——全部保持原语义；重置逻辑不得改动 `tspinPending` 置/清时机与快照 `tspin` 载荷。**逐一审计既有 verify-game §14 T-spin 时序用例**（`tspinSession` = 构造槽位 + 旋转 + `lockTick`）：凡因新重置语义导致锁定时机/期望改变的用例，显式登记修订理由（沿用 r28 期望改写先例）；行为不变的用例保持零改动。
- **AC-7（P0）链迁移与落定收口零回归**：`lockFlow` 单一入口语义不变（r32 `piecesPlaced` 恰 +1、combo 链递增/断链、B2B 资格迁移、onGameOver 总分、四轴叠加载荷）；触控=键盘回放器（r30/r31）**0 逻辑改动**——触屏移动/旋转经同一引擎路径自然获得新语义，无独立实现。
- **AC-8（P0）红线**：**ui.js / audio.js / persist.js / style.css 0 行 diff**；**VERSION 不动**（verify-constants 三模块一致必绿，不升级版本号）；engine 其余行为（计分/掉落/7-bag/踢墙/键位/返回值语义/`DT_CLAMP_MS` 分片）0 变化。

**范围内**：

- `LOCK_MOVE_RESET_MAX=15` 顶部常量（单一事实来源 = game.js + 本 PRD §5 + verify-game 断言）
- 预算随出生/hold/restart 归零、被拒不重置不发声、软降/硬降不变
- verify-game §r33 + qa-e2e §r33 断言追加；r18 §14 时序用例逐一审计；七套全绿

**非目标（明确不做）**：
- 改变 softDrop/hardDrop 立即锁定路径、计分四轴、等级/掉落、7-bag、踢墙行为
- 改 `tspinPending` 置/清时机、combo/B2B 迁移规则、触控回放器逻辑
- 持久化 / 会话外记忆 / 设置项 / 新 UI / 新音效
- VERSION 升级（代码头不动、verify-constants 原值一致）
- 预算数值可配置化（本期固定 15，不引入设置）

## 4. 交互流程摘要

方块下落触底 → 进入 500ms 锁定缓冲（lockTimer 累计）→ 玩家成功横向移动/旋转：缓冲重置回满额、预算 −1（≤15，含悬空清零动作）→ 被拒动作：什么都不发生 → 预算耗尽后成功动作不再重置 → lockTimer 累计满 500ms → `lockFlow` 落定（piecesPlaced +1、T-spin 窗口判据/链迁移照旧）→ 软降触底/hardDrop 不经缓冲立即锁定 → 下一方块出生预算恢复 15。全程无新增控件、无设置项、无模式切换。

## 5. 数值规格（单一事实来源 = game.js 顶部常量）

| 常量 | 值 | 语义 |
|---|---|---|
| `LOCK_DELAY_MS` | 500（既有，AC-03.5） | 触底锁定缓冲时长；措辞由「触底后 ≤500ms 固定」修订为「触底后 500ms 固定，缓冲期间每次成功移动/旋转重置至满额」 |
| `LOCK_MOVE_RESET_MAX` | 15（**新增**） | 每方块缓冲重置预算：旋转与移动计入同一上限；随出生/hold/restart 归零；被拒动作不计；预算耗尽后成功动作不再重置 |

**风险与对策**：
| 风险 | 对策 |
|---|---|
| 重置语义使 r18 §14 既有时序用例锁定时机漂移（`tspinSession` 构造旋转发生在触底缓冲期） | AC-6 逐一审计 + 显式登记修订（r28 先例）；行为不变的用例零改动 |
| 预算口径歧义（悬空清零是否计 1 次）导致防钻空子失效 | AC-4 明确「成功动作触发缓冲清零即计 1 次、脱离触底不补发、per-piece 全程共用」+ 独立对抗用例 |
| 重置逻辑误触 `tspinPending` 置/清时机 → T-spin 误判 | AC-6 置/清时机零触碰 + verify-game §14 全量复跑 |
| 软降/硬降立即锁定路径被并入缓冲 | AC-5 两条路径事件/计分逐字节比对 |
| 断言非确定性（tick 分片 250ms 与 500ms 边界） | 沿用 `lockTick=2×250` 已达上限驱动约定，判定点取「累计满 500ms」而非某次 tick 尾 |
