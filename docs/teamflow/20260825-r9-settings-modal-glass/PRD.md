- 版本：v3.0（v2.9 → v3.0 增量：**设置弹层毛玻璃风格**——将设置项从左面板移出至独立模态框，齿轮图标触发，按分组展示，保持科技玻璃设计语言）
- 状态：进行中

## 1. 背景与目标

### 1.1 背景

当前设置项（音量/静音、幽灵块开关、BGM开关、踢墙旋转开关）全部堆叠在左侧面板底部，与游戏数据（分数、等级、行数、下一个预览）混合在一起。随着设置项增多（v2.3幽灵块、v2.5 BGM、v2.9踢墙旋转），左面板变得越来越拥挤：

1. **信息层级混乱**：核心游戏数据（分数/等级/行数）与设置控件混在一起，影响快速查看。
2. **扩展性差**：后续若新增设置项（如难度选择、控制方案等），左面板空间不足。
3. **视觉一致性**：设置项与游戏数据使用相同视觉权重，但功能性质不同。
4. **科技玻璃风格**：现有 `#overlay` 已有成熟的毛玻璃模态框实现，设置弹层可复用此设计语言。

### 1.2 目标

1. **齿轮图标入口**：左面板顶部新增齿轮图标按钮（⚙），作为设置弹层的唯一触发入口。
2. **毛玻璃风格弹层**：点击齿轮图标后，弹出全屏或半屏模态框（modal/drawer），采用与现有 `#overlay` 一致的科技玻璃设计（`backdrop-filter: blur(20px) saturate(140%)` + 半透明背景）。
3. **分组展示设置项**：弹层内设置项按功能分组（音频组、辅助组等），清晰分类。
4. **保持现有功能**：所有现有设置项（音量/静音、幽灵块、BGM、踢墙旋转）保持原有功能逻辑，仅改变UI位置和展示形式。
5. **左面板精简**：左面板只保留游戏数据（分数、等级、行数、下一个预览），移除所有设置控件。
6. **设计语言一致**：弹层的视觉风格（颜色、字体、间距、动画）与现有 `#overlay` 和科技玻璃设计系统保持一致。

### 1.3 成功指标（可量化）

| 指标 | 目标值 | 测量方式 |
|---|---|---|
| 齿轮图标可见性 | 左面板顶部清晰可见，尺寸≥24px×24px | 视觉检查 |
| 弹层触发 | 点击齿轮图标后200ms内弹层完全显示 | 计时测试 |
| 弹层关闭 | 点击关闭按钮或按ESC后200ms内完全隐藏 | 计时测试 |
| 设置项完整性 | 弹层内包含所有4组设置项（音量、幽灵块、BGM、踢墙） | 功能检查 |
| 分组合理性 | 设置项按功能分组，无遗漏无冗余 | 产品验收 |
| 设计一致性 | 弹层视觉与 `#overlay` 风格一致（颜色、模糊度、圆角） | 视觉对比 |
| 左面板精简 | 左面板仅含游戏数据，无设置控件 | DOM检查 |
| 回归稳定 | 现有AC-01~19功能不变，七套验证全绿 | 自动化测试 |

## 2. 用户故事与验收标准

### 用户故事

**作为** 俄罗斯方块玩家，
**我希望** 有一个独立的设置界面，将游戏设置与游戏数据分离，
**以便** 更清晰地查看游戏状态，并方便地调整设置。

### 验收标准（AC）

#### AC-1：齿轮图标按钮
- **描述**：左面板顶部新增齿轮图标按钮（⚙），作为设置弹层的唯一触发入口。
- **验收条件**：
  1. 齿轮图标按钮位于左面板顶部（分数之上或并列）。
  2. 图标尺寸≥24px×24px，清晰可识别。
  3. 按钮有适当的hover/focus状态（科技玻璃风格）。
  4. 按钮有ARIA标签（如"设置"）。
  5. 点击后触发设置弹层显示。

#### AC-2：设置弹层显示
- **描述**：点击齿轮图标后，弹出毛玻璃风格的设置弹层（modal）。
- **验收条件**：
  1. 弹层在200ms内完全显示（动画时间≤200ms）。
  2. 弹层为全屏或半屏模态框（覆盖游戏区域或全屏）。
  3. 弹层背景采用科技玻璃设计（`backdrop-filter: blur(20px) saturate(140%)` + 半透明背景）。
  4. 弹层有关闭按钮（×或"完成"按钮）。
  5. 弹层显示时，游戏状态保持不变（不暂停、不影响游戏进行）。
  6. 弹层有适当的ARIA角色（role="dialog"）和标签。

#### AC-3：设置项分组展示
- **描述**：弹层内设置项按功能分组展示，清晰分类。
- **验收条件**：
  1. 弹层内至少有2个分组：音频组、辅助组。
  2. **音频组**包含：音量控制（静音按钮、音量+/-、音量显示）、BGM开关。
  3. **辅助组**包含：幽灵块开关、踢墙旋转开关。
  4. 每个分组有清晰的标题（如"音频设置"、"辅助设置"）。
  5. 分组间有适当的视觉分隔（间距、分隔线或背景色差异）。
  6. 所有设置项保持原有功能逻辑（开关状态、持久化等）。

#### AC-4：弹层关闭与状态保持
- **描述**：弹层可关闭，关闭后设置状态保持。
- **验收条件**：
  1. 点击关闭按钮（×）可关闭弹层。
  2. 按ESC键可关闭弹层。
  3. 点击弹层外部区域（遮罩层）可关闭弹层。
  4. 关闭弹层后，所有设置状态保持（不重置）。
  5. 关闭弹层后，游戏状态保持（不暂停、不重置）。
  6. 关闭动画时间≤200ms。

#### AC-5：左面板精简
- **描述**：左面板只保留游戏数据，移除所有设置控件。
- **验收条件**：
  1. 左面板只包含：分数、等级、行数、下一个预览。
  2. 移除原有的音量控制区（#audio-controls）。
  3. 移除原有的幽灵块开关（#ghost-control）。
  4. 移除原有的BGM开关（#bgm-control）。
  5. 移除原有的踢墙旋转开关（#wallkick-control）。
  6. 左面板布局整洁，无空白或错位。

#### AC-6：响应式与可访问性
- **描述**：弹层在不同设备和输入方式下可用。
- **验收条件**：
  1. 弹层在移动端（≤480px）可正常显示和操作。
  2. 弹层支持键盘导航（Tab焦点、Enter激活）。
  3. 弹层有适当的ARIA属性（role="dialog"、aria-modal="true"、aria-label）。
  4. 弹层内的开关控件保持原有ARIA属性（aria-pressed等）。
  5. 弹层打开时，焦点陷阱在弹层内（防止Tab跑到游戏区域）。

#### AC-7：设计语言一致性
- **描述**：弹层的视觉风格与现有科技玻璃设计系统一致。
- **验收条件**：
  1. 弹层背景颜色与 `#overlay` 一致（`--glass-bg`）。
  2. 弹层模糊度与 `#overlay` 一致（`blur(20px) saturate(140%)`）。
  3. 弹层圆角与 `#overlay-card` 一致。
  4. 弹层内的按钮、开关样式与现有科技玻璃风格一致。
  5. 弹层动画与 `#overlay` 动画一致（淡入淡出）。
  6. 弹层在不支持 `backdrop-filter` 的浏览器中有降级方案（近实底半透明）。

#### AC-8：工程约束
- **描述**：实现应遵循现有工程约定。
- **验收条件**：
  1. 代码形态保持扁平纯JS（不引入新文件或新依赖）。
  2. 设置弹层逻辑可放入现有 `ui.js` 或新增独立模块（如 `settings-modal.js`）。
  3. 若新增模块，需在 `index.html` 中按正确顺序加载。
  4. 不改变现有UMD契约（`window.TetrisUI` 等）。
  5. 不影响现有验证脚本（verify-game, verify-ui等）的运行。

## 3. 功能范围与非目标

### 3.1 功能范围（In Scope）

1. **齿轮图标按钮**：左面板顶部新增设置入口。
2. **设置弹层UI**：毛玻璃风格模态框，按分组展示设置项。
3. **设置项迁移**：将现有4个设置项从左面板移至弹层。
4. **弹层交互**：打开/关闭动画、键盘操作、焦点管理。
5. **设计一致性**：与现有科技玻璃设计系统对齐。
6. **响应式适配**：移动端基本可用。

### 3.2 非目标（Out of Scope）

1. **新增设置项**：本轮不新增任何设置项（仅迁移现有4项）。
2. **设置项功能变更**：不改变任何设置项的功能逻辑（开关行为、持久化等）。
3. **游戏逻辑变更**：不改变游戏引擎、计分、难度等。
4. **新模块引入**：不引入新的JS模块（除非必要）。
5. **复杂动画**：不实现复杂的弹出/收起动画（保持简单淡入淡出）。
6. **多级菜单**：弹层内不实现多级菜单或标签页（直接分组展示）。
7. **设置项重排**：不调整设置项的顺序或分组逻辑（保持原有顺序）。

## 4. 交互流程概述

### 4.1 主流程

```
玩家点击齿轮图标（⚙）
    ↓
弹出设置弹层（毛玻璃背景 + 设置分组）
    ↓
玩家在弹层内调整设置（音量/幽灵块/BGM/踢墙）
    ↓
设置立即生效（实时应用）
    ↓
玩家点击关闭按钮（×）或按ESC或点击遮罩层
    ↓
弹层关闭，游戏继续，设置状态保持
```

### 4.2 弹层内设置项交互

1. **音量组**：
   - 静音按钮：切换静音状态（与原有逻辑一致）
   - 音量+/-：调整音量（与原有逻辑一致）
   - 音量显示：显示当前音量百分比

2. **辅助组**：
   - 幽灵块开关：切换幽灵块显示（与原有逻辑一致）
   - BGM开关：切换背景音乐（与原有逻辑一致）
   - 踢墙旋转开关：切换踢墙旋转（与原有逻辑一致）

### 4.3 弹层打开/关闭动画

- **打开**：从透明渐变到半透明背景，弹层内容从下方轻微上移+淡入（200ms）
- **关闭**：从半透明渐变到透明，弹层内容从上方轻微下移+淡出（200ms）
- **动画函数**：使用 `ease-out` 缓动，与 `#overlay` 动画一致

### 4.4 焦点管理

- 弹层打开时，焦点移到弹层内的第一个可交互元素（关闭按钮或第一个开关）。
- 弹层内Tab键在可交互元素间循环（焦点陷阱）。
- 弹层关闭时，焦点返回触发元素（齿轮图标按钮）。

## 6. 依赖与风险

### 6.1 依赖

1. **现有设置项**：依赖v2.3/v2.5/v2.9已实现的设置项（音量、幽灵块、BGM、踢墙）。
2. **科技玻璃设计系统**：依赖现有 `style.css` 中的CSS变量和 `backdrop-filter` 实现。
3. **`#overlay` 设计**：弹层设计应复用 `#overlay` 的视觉模式和动画。
4. **`ui.js` 结构**：需要理解现有UI模块的组织方式，确保集成正确。

### 6.2 风险

1. **移动端适配**：弹层在小屏幕上可能显示不全或操作不便（风险等级：中）。
   - **缓解**：采用响应式布局，弹层宽度自适应。
2. **性能影响**：`backdrop-filter: blur()` 在低端设备上可能有性能问题（风险等级：低）。
   - **缓解**：已有降级方案（`@supports` 查询），且游戏本身已使用此效果。
3. **焦点陷阱实现**：键盘焦点管理可能引入新bug（风险等级：中）。
   - **缓解**：参考现有 `#overlay` 的焦点管理实现。
4. **兼容性**：旧版浏览器可能不支持 `backdrop-filter`（风险等级：低）。
   - **缓解**：已有降级方案，且游戏目标为现代浏览器。
