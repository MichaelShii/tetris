# r18 T-spin 检测 PRD

## 1. 背景与目标

本作现已具备完整的基础对局（7-bag、踢墙旋转、hold、预览队列、消行动画、触屏与响应式布局），但计分仍停留在"按消除行数计分"的浅层：**旋转嵌入（把 T 方块转进凹槽、靠旋转本身完成落定位）没有与普通掉落区分**。T-spin 是标准 Tetris 计分深度的核心：它奖励"旋转嵌入 + 三实角包围"的特殊消除，是高端对局的策略支点。需求原文：T-spin 检测——T 形方块旋转嵌入的特殊消除（标准 Tetris 计分深度的核心）。

目标：

- **G1 判定正确**：仅当 T 方块以"旋转"为锁定前最后动作、且其 3×3 中心邻域对角格 ≥3 格为实（Guideline 三实角规则）时，本次锁定标记为 T-spin；任何其他情形（非 T 方块、旋转后又下落、无旋转落定、实角不足）一律不判定——零误报、零漏报，用例矩阵全覆盖。
- **G2 计分对齐**：T-spin Single/Double/Triple、Mini Single/Double、No-line T-spin 六档专属加分，与现有消行基分（100/300/500/800×level）同构叠加，无重复计分、无漏分。
- **G3 零回归**：engine 锁定流程（r13 消行动画）、等级演进、事件序列（音效恰 1 次）、持久化格式、UI/音频/样式全部零回归；七套验证脚本全绿。
- **G4 最小侵入**：P0 改动面仅 `game.js` + `scripts/verify-game.cjs`；`audio.js`/`ui.js`/`style.css`/`index.html` 保持 0 行 diff（P1 徽标另行裁定）。

## 2. 用户故事与验收标准

### US-1 旋转嵌入检测（P0）

> 作为玩家，我把 T 方块旋转进凹槽完成落位时，游戏应识别这是"旋转嵌入"的 T-spin，而不是普通落位。

- **AC-1（判定成立）**：锁定前最后动作是旋转（旋转成功改变朝向，含原地旋转与踢墙 kick 位移）且为 T 方块、锁定瞬间棋盘快照下 3×3 中心邻域四角实格数 ≥3 → 标记 `tspin=true`。用例矩阵 ≥24 组（4 朝向 × {原地旋转/水平位移 kick/墙侧 kick 位移}，正负各半）全部通过（verify-game.cjs 断言）。
- **AC-2（非 T 零误报）**：I/O/S/Z/J/L 方块即使出现与 T 相同的"旋转嵌入三实角"几何，绝不标记 T-spin（每种方块 ≥1 组负例，断言 0 误报）。
- **AC-3（最后动作窗口）**：旋转之后再发生任何下落（软降 / 硬降 / 自然重力）才锁定 → 旋转窗口失效，不判 T-spin（三种下落各 ≥1 组负例）。
- **AC-4（实角不足与无旋转）**：0/1/2 实角 → 不判；T 方块无旋转直接落定（即使巧合满足三实角）→ 不判。断言计分走普通路径（见 AC-7）。
- **AC-5（Full/Mini 划分）**：按本 PRD §3 几何规则划分：四实角或三实角含对角对 → **Full**；三实角呈 L 形且均位于 T 头部反侧（T 的"脚"侧两角 + 相邻一侧角，无对角对）→ **Mini**。≥8 组权威样例逐例断言（社区标准模式：TKI 经典三实角单消=Full Single、下凹槽三实角（头朝上）单消=Mini Single、左右墙 kick 入双实角槽=按 §3 判 Full、四实角=Full），任何布局未落入两规则任一 → 按普通消行（不判 T-spin）。

### US-2 计分与等级演进（P0）

> 作为追求高分的玩家，T-spin 消除应获得专属加分，并像普通消除一样计入等级进度。

- **AC-6（六档分值精确）**：T-spin Single=800、Double=1200、Triple=1600、No-line=100、Mini Single=100、Mini Double=200，均 ×level（乘数机制与现有 `scoreForLines` 同构）；常量值进 `game.js` 顶部（单一事实来源，对应 §3 表），verify-game.cjs 逐档断言「常量 × level」的精确分值；Mini 判定下清除 3 行（不存在 Mini Triple 档）按 Full Triple=1600×level 计，防漏分。
- **AC-7（与普通计分叠加且不重复）**：T-spin 消除的总分 = 普通消行分（沿用 `LINE_SCORES[行数-1]×level`，逐分不变）+ T-spin 档位分，二者恰各计一次；负例断言非 T-spin 路径逐分与基线一致（如普通单消仍 100×level）。
- **AC-11（等级与行数）**：T-spin 清除的行数照常计入累计 lines（升级仍按每 10 行升 1 级，AC-06.2 语义不变）；T-spin 加分不额外推进等级进度；对局结束后最终分数含 T-spin 加分（onGameOver 透出正确总和）。

### US-3 事件与反馈（P0 事件 / P1 徽标）

> 作为玩家，T-spin 应有清晰（且不打扰）的反馈；作为开发者，事件序列必须向后兼容。

- **AC-8（事件序列兼容）**：T-spin 消除的音效事件仍恰好 1 次 `clear`（复用现有音效，`audio.js` 0 行 diff，r13「一次消行动作恰好 1 次」语义不破）；verify-game.cjs 对含 T-spin 场景与普通场景的事件序列均断言；T-spin 标志可通过现有回调/状态字段暴露（供 P1 徽标），缺省不改变任何既有字段语义。
- **AC-12（P1 可选徽标）**：若实现，清除发生时棋盘区显示 "T-SPIN!" / "Mini" 徽标 ≤2s，不阻塞操作、不重置对局、与 r13 闪白动画共存；未实现时本 AC 不适用，P0 出口不受影响（UI/样式仍 0 行 diff）。

### US-4 稳定性与零回归（P0）

> 作为玩家，T-spin 引入后我的对局手感、存档与本作全部既有功能不应有任何变化。

- **AC-9（既有机制零回归）**：clearing 消行动画子阶段（r13）、hold（r14）、预览队列（r15）、计分持久化格式、PAUSED/OVER 语义全部零回归；T-spin 判定基于锁定瞬间棋盘快照（含踢墙位移后的快照），不依赖对局外状态。
- **AC-10（随机对局稳定性）**：连续 50 局随机对局（含大量 T 旋转操作注入）无异常/无崩溃、总分单调不减（无负分路径）、每次 T-spin 后下一块正常 spawn。
- **AC-13（七套全绿出口·硬门槛）**：`verify-game`（含全部新增 T-spin 用例）/`verify-audio`/`verify-ui`/`verify-constants`/`assembly-check`/`qa-e2e-jsdom` 全部通过；P0 改动面仅 `game.js` + `scripts/verify-game.cjs`，其余产品文件 0 行 diff；产品版本登记 v3.5（memory.md，验收入库时执行）。

## 3. 数值规格（单一事实来源 = game.js 顶部常量 + §2 AC 断言）

**Full/Mini 几何规则**（以锁定瞬间 T 所在 3×3 邻域的四角为参考；T 头部 = 方块唯一突出方向）：

| 判定 | 规则 |
|---|---|
| 三实角 | 四角实格数 ≥3 即成立（先决：AC-1 旋转最后动作） |
| Full | 实角数 = 4；或实角数 = 3 且三实角含对角对（↖↘ 或 ↗↙） |
| Mini | 实角数 = 3 且三实角两两相邻（L 形，无对角对），且 L 位于 T 头部反侧（头朝上 → 底部两角+一侧角皆实） |
| 均不满足 | 不判 T-spin，普通消行计分 |

**计分档位**：

| 档位 | 判定 | 清除行数 | 基础分 | 乘数 |
|---|---|---|---|---|
| T-spin Single | Full | 1 | 800 | ×level |
| T-spin Double | Full | 2 | 1200 | ×level |
| T-spin Triple | Full | 3 | 1600 | ×level |
| T-spin No-line | Full | 0 | 100 | ×level |
| Mini Single | Mini | 1 | 100 | ×level |
| Mini Double | Mini | 2 | 200 | ×level |
| Mini 清除 3 行 | Mini（无此档） | 3 | 1600（按 Full Triple） | ×level |
| 普通消行（基线不变） | — | 1/2/3/4 | 100/300/500/800 | ×level |

## 4. 范围与非目标

**范围内**：T-spin 检测（几何规则 + 旋转窗口）、六档计分、事件序列兼容、用例矩阵单测、P1 可选徽标。

**非目标**：不引入 combo / back-to-back / Perfect Clear 连锁（若后续要做，另立需求）；不改动方块形状、旋转系统本体与踢墙旋转开关（v2.9 设置项语义不变）；不做 T-spin 教学或常驻提示；不改 UI 布局与触控区（r16/r17 成果不动）；不引入"旋转方向轨迹追踪"类复杂判定（按 §3 几何规则为产品级定义，实现体量与回归面最小）。

## 5. 交互流程摘要

转动 T 方块入凹槽 →（旋转使朝向改变，可含踢墙位移，之后不可再下落）→ 锁定时引擎在单一时钟原子锁流程内取棋盘快照做四角几何判定 → 标记 Full/Mini → 消行 → 计分 = 普通消行分 + 对应 T-spin 档位分（×level）→ 升级判定照常 → spawn 下一块 → 总分经 onGameOver 透出；音效仍恰 1 次 clear；P1 时叠显 "T-SPIN!" 徽标。判定插桩点位于 r13 lockFlow 的消行步骤之前，不改变该流程任何既有时序。
