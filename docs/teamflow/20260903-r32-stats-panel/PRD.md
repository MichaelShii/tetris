## 1. 背景与目标

**背景**：当前信息面板仅展示「分数 / 等级 / 行数 / 最高分」与 Next 预览（`#stat-score/#stat-level/#stat-lines/#hi-score`，`.stat-grid` DOM 顺序冻结、禁重排）。玩家无法获知对局过程性指标——已放置多少方块、当前对局进行了多久，缺少可用于回顾/分享对局的会话统计。

**目标**：新增统计面板，展示三项核心指标：**已放置方块数**（成功落定方块数）、**消行总数**（与既有「行数」同一计数源，值恒等）、**游戏时长**（有效对局时长，不含暂停）；并预留 P2 扩展位（Tetris 次数 / T-spin 次数 / 最高 combo 等）。统计为**当前会话**语义：新对局归零、OVER 定格；**不进入持久化、不参与计分、不发新音效**。

## 2. 用户故事与验收标准

### US-1 核心指标（P0）

> 对局中，玩家在信息面板区可实时看到三项统计，数值与对局事实一一对应。

- **AC-1（P0）三项可见与实时**：桌面（非 has-touch）与触控全部档位（S 竖屏行式 / 横屏双轨 / M / L）下，统计面板均可见且随对局实时更新。值规格：已放置方块数、消行总数为非负整数（0 起）；游戏时长格式 `mm:ss`（≥1 小时自动 `hh:mm:ss`）。
- **AC-2（P0）已放置方块数语义**：每次**成功落定**一个方块 +1（软降 / 硬降 / 自然下落落定均计 1 次；T-spin 落定按 1 次计；No-line T-spin 落定同样计 1 次）。Hold 交换、移动、旋转、场上悬浮**不计入**。脚本断言：混合软降/硬降落定 N 次 → 数值恰为 N。计数为**单一计数源**（与对局事件一一对应，禁止 UI 侧独立累计造成漂移）。
- **AC-3（P0）消行总数与既有行数恒等**：任何时刻 `消行总数` 与既有「行数」（`#stat-lines` 计数源）**同值**。脚本断言：10 次单消 + 2 次四消累计 = 18。
- **AC-4（P0）游戏时长语义**：新对局（New Game / 重新开始）起点归 0 并开始计时；**暂停期间不计入**（暂停存在时）；OVER 定格为最终时长；重新开始归零重计。脚本断言：对局跑 T 秒（含一次暂停 P 秒）→ 定格时长 ≈ T−P，与墙体时钟偏差 ≤1s。
- **AC-5（P0）归零与定格**：重新开始 / 新游戏三项全部归零；OVER 定格显示对局最终三项值（与结算帧一致）。

### US-2 布局与既有视觉零回归（P0）

> 统计面板融入既有 HUD 体系，不破坏任何既有元素与档位布局。

- **AC-6（P0）既有统计元素零改动**：`#stat-score/#stat-level/#stat-lines/#hi-score` 的 ID、DOM 结构、`stat__value` 命中关系与装配正例（assembly-check 正例仍全部命中）**零变化**；新增指标为**纯追加**（可追加新 stat 块或独立面板，禁止重排既有节点源序）。
- **AC-7（P0）全档位零叠压**：S 竖屏行式 / 横屏双轨 / M / L 各档下，新面板不遮档棋盘、触控垫（十字键）、左右信息面板与系统按钮；**横屏双轨下新面板布局在轨道内**（左轨 212px / 右轨 104px + safe-area 让位语义沿用 r28 规则），不超出轨道、不叠压 r28 左右侧内容。
- **AC-8（P0）r30/r31 冻结语义零触碰**：竖屏 S 行式底栏（六键一排、恒玻璃）、触控=键盘回放器（0 逻辑改动）、TOUCH_KEYS 六值契约、r31 自定义按键，本需求**不得改动三者任何逻辑**（仅允许新增面板独立于其存在）。

### US-3 红线与可测性（P0）

- **AC-9（P0）引擎行为 0 变化**：锁定 / 计分四轴（普通、T-spin、combo、B2B）/ 等级 / 掉落速度 / 7-bag / 踢墙 / 键位响应行为全部不变；game.js 允许的改动仅为**只读追加**（会话计数与暴露），不得改变既有函数返回值与状态迁移；**audio.js、persist.js 0 行 diff**。
- **AC-10（P0）onSfx 事件面不变**：既有 8 事件（move/rotate/softDrop/hardDrop/clear/levelUp/gameOver/hold）序列与次数不变；统计功能**不发任何新音效事件**。
- **AC-11（P0）VERSION 一致**：verify-constants 三模块一致必绿；若本需求决定升级版本号需三处同步修改且校验通过（是否升级由技术方案定，不升级亦合规）。
- **AC-12（P0）七套全绿零回归**：verify-game / verify-audio / verify-ui / verify-constants / assembly-check / qa-e2e-jsdom 全绿；r24~r31 既有断言**期望零改动**，本需求断言为**追加**（verify-ui §r32、qa-e2e §r32 段，含统计数值断言与源码级检查：触控下不落行式栏、新面板不触碰 TOUCH_KEYS）。
- **AC-13（P0）数值可脚本断言**：三项指标均有 Node 可断言锚点（快照/纯函数暴露）；脚本跑通「落定 N 次 → 计数 N」「消 1/2/3/4 行累计」「时长定格」断言通过。

### US-4 无障碍（P1）

- **AC-14（P1）读屏友好**：面板语义化（role/aria-label 与既有信息面板一致）；数值更新遵循既有 `aria-live=polite` 先例，但**游戏时长每秒刷新不得造成读屏刷屏**（节流 / 仅状态变化时播报等机制）；读屏人工补测纳入验收清单。

### US-5 扩展指标（P2）

- **AC-15（P2）预留扩展位**：Tetris 次数 / T-spin 次数 / 最高 combo / 最佳连消等可选指标位预留（数据面与展示位），本期可不实现；若实现须遵循同一归零语义、单一计数源与断言锚点。

## 3. 范围与非目标

**范围内**：
- 三项指标的数据面（会话计数、单一计数源、快照暴露）与展示面（桌面 + 触控全档位）
- 归零 / 暂停不计 / OVER 定格语义
- verify-ui §r32 + qa-e2e §r32 断言追加，七套全绿

**非目标（明确不做）**：
- 跨对局统计 / 历史记录 / 排行榜持久化（统计为会话内存，不入 persist）
- 最高分机制变更、计分规则变化、新音效
- 触控键位、回放器、自定义按键逻辑任何改动
- 统计结果参与计分 / 升级
- 网络 / 遥测 / 导出

## 4. 交互流程摘要

新对局（New Game / 重新开始）→ 三项归 0，时长开始累计（暂停期间停表）→ 对局中数值实时更新（落定 / 消行 / 每秒时长）→ OVER → 定格显示最终三项 → 重新开始 → 归 0 重计。全程纯展示，无新增可交互控件、无新设置项、无模式切换。

## 5. 优先级

- **P0**：AC-1 ~ AC-13（三项指标、归零/定格语义、布局零回归、红线、七套断言）
- **P1**：AC-14（读屏友好与时长播报防刷屏）
- **P2**：AC-15（扩展指标位）

## 6. 依赖与风险

**依赖**：r31 验收基线（含 r28 横屏双轨、r30 触控回放/竖屏行式冻结语义承继）；既有 `.stat-grid` 结构与装配正例；七套验证脚本与 onSfx 事件面。

**风险与对策**：
| 风险 | 对策 |
|---|---|
| 计数双源漂移（UI 独立累计与引擎事实不一致） | AC-2/AC-3 单一计数源 + 断言锚点 |
| 时长计时漂移（暂停 / 切后台 visibilitychange / rAF 节流） | AC-4 语义定义 + ≤1s 容差断言 + 人工补测 |
| 布局回归（stat-grid 源序 / 横屏双轨 / 竖屏行式被破坏） | AC-6~AC-8 零改动 + qa-e2e §r32 源码级检查 |
| 读屏刷屏（时长每秒播报） | AC-14 节流机制 + 人工补测 |
| 既有断言被误改（旧期望漂移） | AC-12 旧期望零改动、新断言纯追加 |
| 引擎行为被顺带改动 | AC-9 红线 + 红线复核环节（game/audio/persist diff 复检） |
