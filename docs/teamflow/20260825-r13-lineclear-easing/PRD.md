## 1. 背景与目标

### 1.1 背景

1. 自 v1.0 起，消行为**即时消除**：锁定满行后在同一个时钟原子步内完成「塌缩 → 计分 → 升级 → spawn 下一块」（E3：一次最多 4 行一次性消除，AC-03）。玩家对消行没有任何视觉反馈。
2. 「消行动画 / 动画缓动」自 v2.0 起多次列入 P2 可选清单并明确「不做」，是长期悬置的体验打磨项（v2.0/2.1/2.2/2.3/2.4/2.5/2.7/2.8 历史 PRD 均有记录）；本需求将其落地。
3. 既有动效资产可复用：DESIGN P4 动效规范（时长 ≤ 800ms、缓动用 ease-out 指数曲线、`prefers-reduced-motion` 全降级为瞬时/淡化）、LEVEL UP toast 的 ease-out-quart 先例（DOM 层）、性能红线（游戏板为唯一逐帧重绘层 Canvas、不动画 `box-shadow`/`backdrop-filter`/`filter`、FPS ≥ 55，AC-09.8）。
4. 消行动画是**引擎驱动的板内动效**（Canvas 内），不是 DOM 层动画，须遵守「单 Canvas 逐帧层」性能契约，不能引入逐帧 DOM 更新。

### 1.2 目标

1. **消行反馈动画**：锁定检测到满行（1~4 行）时，被消除行不立即消失，先播放 1 次「渐亮 → 渐暗」亮度脉冲，再塌缩消失。**显式取代「消行即时消除」时序**（AC-03/E3 的行为变化点）。
2. **缓动曲线**：动画亮度/进度采用 ease-out-quart 指数曲线（对齐 DESIGN P4 与 LEVEL UP 先例）。
3. **零副作用**：动画只是把既有「消行 → 计分 → 升级 → spawn → 出生碰撞判定」原子步**整体后移 T 毫秒**——计分公式、行数、等级、`clear` 音效恰 1 次、7-bag、对外状态机枚举全部不变（§3「不改」清单）。
4. **可访问降级**：`prefers-reduced-motion: reduce` 或动画时长配置为 0 时，行为与现状完全等价（即时消除）。
5. **可测**：动画进度由显式 `tick(dtMs)`/差值时钟驱动 + 时长可配置（0ms 钩子），verify-game 可同步步进断言，qa-e2e 可绕过 jsdom 时序坑（r9 人工热修先例）。

## 2. 用户故事与验收标准

**用户故事**

- US-1 作为玩家，消行时我希望看到清晰的消行动画反馈，而不是瞬间消失（→ AC-1/AC-2）。
- US-2 作为玩家，我希望动画不改变计分/等级/下落节奏，不影响游戏公平（→ AC-3/AC-5/AC-10）。
- US-3 作为动效敏感或系统降级用户（`prefers-reduced-motion`），我不希望看到任何动画（→ AC-7）。
- US-4 作为工程师，我希望动画可配置、可步进、不依赖真实计时器，测试稳定（→ AC-9）。

**验收标准（AC 编号仅限本任务夹）**

### AC-1（P0）动画触发与视觉规格
- 触发：一次锁定消除 1~4 行（E3 上限不变）；`cleared = 0` 时零动画、走既有原子步（零变化）。
- 动画：被消除的整行（同行全部 10 格）同步播放 1 个「渐亮 → 渐暗」亮度脉冲：亮度 1.0 → 峰值 ≥ 1.2（默认 1.25）→ 0；进度曲线 ease-out-quart（相邻两帧亮度增量单调递减，可数值断言）。
- 时长：T = 240ms，容差 160~320ms（满足 DESIGN P4「动效时长 ≤ 800ms」）；1~4 行共用同一时长、同行同步。
- 动画期间棋盘其余格静止（未消除行的渲染逐像素不变）。

### AC-2（P0）塌缩与棋盘等价性
- 动画结束后执行既有 `clearLines` 塌缩：被消除行移除、上方行整体下移、顶部补空行；随后 spawn 下一块。
- 等价性：同一输入序列下，动画结束时刻的棋盘与「无动画路径」逐格一致；消除行集合与塌缩结果与无动画路径完全一致。**动画只平移时序，不改变几何结果。**

### AC-3（P0）计分/行数/等级/音效/随机零副作用
- `scoreForLines(cleared, level)`、行数累计、升级判断（每满 10 行 1 级）在动画结束后的值，与「即时消除路径」完全一致（AC-14 公式、AC-03/E3 不变）。
- `sfx('clear')` 每次消行动作恰 1 次（1/2/3/4 行均 1 次，回归 AC-09.2），在动画开始帧播放。
- 7-bag 序列不受影响；下一块预览在 spawn（动画结束）时更新恰 1 次。
- 升级时 LEVEL UP toast（800ms±200，AC-06.4）在动画结束后触发，时长/样式不变。

### AC-4（P0）动画期间输入与暂停（含 r12 协同）
- 动画期间：左/右移动、软降、硬降、旋转输入**全部忽略**（不排队、不缓冲、不产生动作事件），动画结束后首个可用输入才生效。
- P 键/空格暂停在动画期间有效：暂停 → 画面冻结于当前动画帧（进度冻结）；恢复 → 从冻结帧续播（进度不重置、不跳帧、剩余时长有效）。
- 设置弹层打开自动暂停（r12/req-12）在动画期间同样生效：动画冻结；关闭弹层保持暂停；按 P/空格继续后动画从冻结帧续播。**r12 全行为回归**（弹层内 ESC 仅关弹层、不误触暂停）。

### AC-5（P0）下落时钟冻结
- 动画期间自动下落时钟冻结：dt 不累计、不触发下落 tick（E7/E8 dt clamp ≤ 250 语义不变），spawn 新块后按当前等级间隔重新计时。
- 不得出现：动画结束瞬间新块立即下落、动画期间悄悄积压下落步数、新块首帧连降。

### AC-6（P1）GAME_OVER 顺序
- 若消行后 spawn（动画结束）发生出生碰撞 → OVER：动画仍完整播放（≤ 320ms），OVER 在动画结束后呈现；OVER 后动画状态清空（无残留亮度帧）。
- 顺序与既有「消行 → spawn → 碰撞 → OVER」一致，仅整体后移 T。

### AC-7（P0）reduced-motion 降级等价
- `prefers-reduced-motion: reduce` 或动画时长配置为 0 时：动画完全跳过（T=0）。同一输入序列下，棋盘/计分/行数/等级/音效次数/状态序列与「即时消除基线」逐点等价（无残留状态、无额外帧）。

### AC-8（P1）渲染与性能红线
- 动画仅对 ≤ 4 行被消除单元格做亮度/alpha 逐帧重绘（Canvas 内纯 fillRect/透明度变化，合成器友好）；不逐帧动画 `box-shadow`/`backdrop-filter`/`filter`；不引入 DOM 逐帧更新（面板仍按数值变化更新）。
- 动画期间无活动块/幽灵块绘制（锁定后、spawn 前无当前块，属既有语义）。
- 含动画的整帧渲染 FPS ≥ 55（回归 AC-09.8 量级）；动画帧的 layout/paint 开销不高于无动画帧量级。

### AC-9（P0）测试钩子与验证
- 引擎提供动画时长构造参数（默认 240ms；0 = 立即完成）；动画进度由显式 `tick(dtMs)`/差值时钟驱动（复用既有 autoLoop/tick 机制，可同步步进）。0ms 为正规配置项，非测试后门。
- `scripts/verify-game.cjs` 新增消行动画用例组：① 动画期棋盘 = 「锁定后含满行棋盘」且未消除行静止；② 动画期输入被忽略；③ 动画结束塌缩 + 计分 + 行数 + 升级 + `sfx('clear')` 恰 1 次 + spawn；④ 0ms 模式与基线逐点等价；⑤ 动画期多步 tick 不触发下落（时钟冻结）。
- 回归：E3、AC-14、AC-09.2、AC-09.8/E7/E8 等既有用例全绿，AC-01~19 集零回归。
- `scripts/qa-e2e-jsdom.cjs` 新增消行动画端到端段（rAF 步进或 0ms 配置绕过 jsdom 时序，沿用 r9 人工热修约定）：消行 → 动画进度可见 → 塌缩 → 新块生成；既有 237 断言（v3.0/v3.0.1 弹层段）零回归。
- 出口：七套验证全绿（verify-game / verify-audio / verify-ui / verify-persist / verify-constants / assembly-check / qa-e2e-jsdom）。

### AC-10（P1）状态机契约与快照
- 新增引擎内部「clearing 子阶段」，**不改变对外 phase 枚举**（READY/RUNNING/PAUSED/OVER 语义与消费方兼容）：动画期间 `getPhase()` 仍为 RUNNING。
- 动画进度通过快照附加字段播报（如 `clearedIndices` + `animProgress ∈ [0,1]`），既有消费方（ui.js 渲染、qa-e2e 既有断言）无需感知即兼容；**无新增 UMD 接口重签名**。
- 暂停快照在动画中途拍下：恢复后从同一进度帧续播（AC-4 细化）。

## 3. 范围与非目标

**做**
- 引擎：lockFlow 中新增「动画延时子阶段」（锁定 → 检测满行 → clearing 动画 → 塌缩 → 计分 → 升级 → spawn → 碰撞判定），时长配置与 0ms 降级。
- 渲染：ui.js Canvas 对被消除行做 ease-out-quart 亮度脉冲动画；`prefers-reduced-motion` 检测。
- 测试：verify-game 新增动画/降级/时钟用例；qa-e2e 新增消行动画段。

**不改**
- 计分公式 / 等级曲线 / 下落间隔 / 7-bag / 幽灵块 / 音效引擎 / BGM / 踢墙开关 / 设置弹层架构（r9/r10/r12 产物原样）。
- UMD 契约签名（`window.TetrisGame` / `window.TetrisUI`）、对外 phase 枚举、模块头部 VERSION（发布版本仅对外发版统一升位，见 memory 约定）。

**不做（明确排除）**
- 逐行错峰塌缩动画、方块粉碎/粒子特效、掉落轨迹、消行动画开关设置项（不新增设置键）、触屏/手势、DOM 层动画复刻。

## 4. 交互流程概要

1. 玩家操作导致方块锁定（自然下落 / 软降 / 硬降落地）。
2. 锁定合并后检测满行：`cleared = 0` → 立即走既有原子步（零变化）；`cleared ≥ 1` → 进入 clearing：
   - 棋盘保持「锁定后含满行」静止画面；被消除行播放 ease-out-quart 亮度脉冲（1.0 → 1.25 → 0，T = 240ms）。
   - 时钟冻结：下落 tick 暂停累计；输入全部忽略；P / 空格 / 设置弹层自动暂停可冻结动画（恢复续播）。
3. 动画结束：塌缩（移除 + 下移）→ 计分 / 行数 / 升级（数值与即时路径一致）→ `sfx('clear')`（恰 1 次）→ LEVEL UP toast（如升级）→ spawn 下一块 → 出生碰撞判定 → RUNNING 或 OVER。
4. `prefers-reduced-motion` / `animMs = 0`：跳过动画，完全等价现状即时消除。

## 6. 依赖与风险

**依赖**
- DESIGN P4 动效规范（ease-out 指数曲线、时长 ≤ 800ms、`prefers-reduced-motion` 降级）与 LEVEL UP ease-out-quart 先例。
- 性能红线（单 Canvas 逐帧层、不动画 `box-shadow`/`backdrop-filter`/`filter`、FPS ≥ 55）。
- r12 暂停机制（P / 空格 / 设置弹层自动暂停）与动画冻结的协同（AC-4）。

**风险与对策**
| 风险 | 对策 |
|---|---|
| jsdom 动画时序断言不可靠（r9 先例 8 失败项） | AC-9 强制 0ms 钩子 + rAF 步进；动画类断言等待 rAF |
| 动画期新块 spawn 延迟影响节奏感 | T 上限 320ms + 时钟冻结保证公平（AC-5） |
| 逐帧行重绘性能劣化 | 仅 ≤ 4 行 alpha/亮度、Canvas 内，AC-8 红线条目 |
| 既有 237 条 E2E 受新时序干扰 | 既有用例适配（消行段等待动画完成或动画 0ms 下跑既有段），回归不降级（AC-9） |
