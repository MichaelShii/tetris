# r19 移动端棋盘优先一屏适配 PRD

## 1. 背景与目标

r17 交付后真机反馈（用户截图 + 复述）：手机「能玩但体验太差」——S 竖屏把桌面左面板线性化成卡片流（标题→统计→设置→预览→**棋盘**→Hold→按钮），棋盘排第 4 位在首屏之外，玩耍时必须滚动，滚动后统计/预览又出视野；设置按钮独占整行、统计 2×2 大卡与两行 dock 预留（16.5vh 中心带）浪费大量纵向空间。

用户已确认方向：**不另起一套移动端样式，仍是响应式，但 S 竖屏按「棋盘优先、一屏适配」重写**（方案 A）。细化设计已确认两处修订：Next 队列保持竖排画布放棋盘侧栏（不做顶部横排，避免 ui.js 双模式渲染 + L 档重基线）；设置齿轮与统计同行右端（纯 CSS 无法跨容器搬入 header）。

目标：

- **G1 一屏适配**：S 竖屏整页零滚动，棋盘、统计、Hold、Next、控制钮、触控区全部首屏可见。
- **G2 棋盘为王**：棋盘（1:2）吃满扣除顶部信息条与底部触控区后的全部剩余高度，无拉伸变形。
- **G3 零 JS 重排**：断点仍纯 CSS 媒体查询；`index.html` / `ui.js` / `game.js` / `audio.js` / `persist.js` 0 行 diff。
- **G4 其余档零回归**：S 横屏变体、M、L 三档规则不动，桌面视觉零漂移（承继 r17 AC-7 红线）。

## 2. 用户故事（含验收标准）

  验收：AC-1、AC-2、AC-4。

  验收：AC-3。

  验收：AC-5。

## 3. S 竖屏布局规格（数值单一事实来源）

| 区块 | 位置 | 规格 |
|---|---|---|
| 页头 | 顶部 | 标题 + 状态灯压缩为一行（字号降档、间距收窄） |
| 统计行 | 页头下 | 分数/最高分/等级/行数单行横排（label + value 同组），右端设置齿轮按钮 |
| 控制行 | 统计行下 | 开始/暂停/重开三钮单行横排 |
| 对局区 | 剩余全部高度 | Hold（48×24 竖排画布）与 Next（48×80 竖排画布）细侧栏贴棋盘左右；棋盘 1:2 等比缩放吃满剩余高度 |
| 触控区 | 底部（文档流内） | 单行 6 键（375px 下 48px 键恰可容纳；≤379px 44px 兜底延续 r16），safe-area-inset-bottom 避让延续 |

实现形态：S 竖屏内 body 改纵向 flex（`100dvh` 渐进增强），`#main` 网格化（统计行/控制行/对局区三行），棋盘列 `flex:1` + `#board` 以 `width/height auto !important + max-width/max-height` 等比缩放（先例：r17 §7.2 横屏档）。取消 r17 的 `--dock-h` 滚动预留、两行 dock、16.5vh 中心带、`display:contents` 列序（整档重写）。

断点实现：纯 CSS 媒体查询，禁止由断点切换触达引擎状态（承继 r17 AC-8 前提）。

## 4. 验收标准（AC 清单，本任务夹内编号）

- **AC-1 [P0] 一屏零滚动**：S 竖屏（代表 320×568 / 375×667 / 390×844）下 `documentElement.scrollHeight ≤ clientHeight`（垂直 0 滚动）且 `scrollWidth ≤ clientWidth`（横向 0 溢出）；统计、设置、控制钮、棋盘、Hold、Next、触控区包围盒全部落入首屏。验证：QA DevTools 视口截图对拍 + verify-ui 静态锚点。
- **AC-2 [P0] 棋盘等比吃满**：S 竖屏 `#board` 显示尺寸保持 280:560 比例（width/height 换算偏差 ≤1px），显示高度 = min(可用高, 可用宽×2)（即无留白浪费、无拉伸）；棋盘为页面最大视觉主体（包围盒面积 > 其余任一区块）。验证：QA 截图量测。
- **AC-3 [P0] 触控区单行随流**：S 竖屏 dock 六键单行、位于文档流末尾（position 非 fixed），与对局区包围盒交集 = 0；键 48px（≤379px 44px）、间距 ≥8px、`env(safe-area-inset-bottom)` 避让保留。验证：verify-ui 静态断言（改写后）+ QA 截图。
- **AC-4 [P0] 信息与控制首屏可达**：统计四项单行同屏、数值字号 ≥16px、正文 ≥12px；设置按钮与开始/暂停/重开三钮单行可见可点；READY/PAUSED/OVER 遮罩按钮覆盖在棋盘上天然可见。验证：QA 截图 + verify-ui computed-style 断言沿用。
- **AC-5 [P0] 侧栏预览零渲染改动**：Hold/Next 竖排画布贴棋盘左右（Next 队列画布内联尺寸仍 48×80、槽位竖排），ui.js 渲染器 0 diff；预览队列/Hold 开关关闭时对应侧栏隐藏、棋盘加宽（auto 轨道收窄）。验证：verify-ui 48×80 断言沿用 + QA 截图。
- **AC-6 [P0] 其余档零回归**：`@media (max-width:599px) and (orientation:landscape)`、M 两档、L 基线规则 0 行 diff；≥1024px 桌面视觉与 r17 交付一致。验证：git diff 审查 + assembly-check 选择器正例沿用。
- **AC-7 [P0] 跨档切换不丢状态（承继 r17 AC-8）**：对局中 resize 跨任意断点不重载无重置，引擎快照逐字段一致，连续 5 轮无漂移。验证：qa-e2e-jsdom 断点切换用例沿用。
- **AC-8 [P1] 键位图例 S 竖屏隐藏**：`.key-hints` 在 S 竖屏不渲染显示（触屏隐藏承继 r16；非触屏窄窗口同步隐藏，登记为已确认行为变更——细化设计已获用户确认）。验证：verify-ui 静态断言。

## 6. 交互流程摘要

打开页面 → <600px 竖屏命中新 S 档：页头压缩行 → 统计+设置行 → 控制钮行 → Hold｜棋盘｜Next 对局区（吃满剩余高度）→ 单行触控 dock，整页零滚动；旋转横屏切 r17 §7.2 横屏变体，≥600px 切 M/L 档，行为均与 r17 一致。对局中跨档切换只换布局、不触达引擎状态。

## 7. 依赖与风险

**依赖**：r17 断点框架（S 横屏变体/M/L 承继）；r16 触控语义与 `html.has-touch` 显隐；`100dvh` 渐进增强（不支持时 `100vh` 兜底，移动现代内核均支持）；verify-ui / qa-e2e-jsdom 断点断言同步改写。

**风险**：
- R1（中）`100vh` 与移动端动态工具栏 → 对策：`min-height:100vh` 兜底行 + `100dvh` 增强行（仓库既有渐进增强惯例）；真机补测登记。
- R2（低）极矮视口（如 320×350 竖屏）内容挤压 → 对策：棋盘 `max-*` 等比收缩自适应；不设 overflow 裁剪，极端情况自然滚动兜底。
- R3（低）jsdom 无真实视口 → 对策：verify-ui 以静态锚点（calc 形状/选择器存在性）表达，真实几何入 QA 人工/DevTools 对拍。
- R4（低）设置按钮不在 header 与已确认预览图有出入 → 细化设计已确认（纯 CSS 不可跨容器，视觉位置等效）。
