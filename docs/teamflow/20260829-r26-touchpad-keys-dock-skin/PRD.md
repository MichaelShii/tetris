## 1. 背景与目标

**痛点**：r24 交付后用户反馈三处不达标——(1) 横屏侧轨质感与设计稿不符（Hold 键为圆角方形而非设计稿正圆、轨道用 ::before/::after 伪元素全边描边而非设计稿独立 .rail 元素单边描边、M/L 横屏走轨或底栏未裁定）；(2) S 竖屏/横屏作用域下 Hold 键漏设 `border-radius:50%` 继承 `--radius-md` 成圆角方形、旋转键微底 `color-mix(primary 16%, surface-2)` 在深底上偏素、紫色突出感弱于设计稿；(3) 设置弹层「外观 · 操作区背景」四档横排文字 radio 文字长、一行挤出/堆叠。

**参考设计稿**（用户已评审通过，实施唯一视觉依据）：`docs/teamflow/drafts/20260829-touchpad-cross-design-draft.html`（标准档、横屏、四套背景均已确认）。

**目标**：
1. 横屏侧轨校正至与设计稿一致：Hold 键为正圆（`border-radius:50%`）；轨道用独立 `.rail` 元素 + 单边描边质感（非伪元素全边描边）；按设计稿仅画手机横屏的事实，裁定 **M/L（≥600px）横屏维持行式底栏恒玻璃、不引入侧轨**，侧轨仅作用于手机横屏（<600px）。
2. 键帽质感统一：S 竖屏 dock 与横屏侧轨作用域内所有触控键帽（十字/旋转/Hold）统一正圆，补上 Hold 的 `border-radius:50%`；旋转主键紫色突出感对标设计稿增强（微底/常亮环），仅复用既有玻璃/霓虹 token、零新增色板。
3. 设置弹层「外观 · 操作区背景」改 2×2 网格：每行 2 个选项、每个选项带真实皮肤缩略预览、缩略图下方另起一行显示名称（如「A 玻璃 dock」）；选中态清晰；仍为 radio 语义。
4. 零回归红线：引擎 game.js / 音效 audio.js 0 diff、VERSION 不动、触控=键盘回放器路径零逻辑改动；四套皮肤作用域仅 S 竖屏 dock 与横屏侧轨、M/L 行式底栏（含 M/L 横屏）恒玻璃零回归；按压态 / r16 三态 / safe-area / 多指守卫全部承继；七套验证脚本全绿出口。

**性质说明**：本需求为 r24 交付后的**实现校正 + 设置 UI 改版**，不是布局/契约重设计——TOUCH_KEYS 契约、六键功能、四皮肤语义与持久化通道均保持 r24 既有 AC 不变。

## 2. 用户故事与验收标准

### US-1 横屏侧轨符合设计稿
*作为横屏玩家，我希望侧轨细节与设计稿完全一致：正圆 Hold、独立的轨道质感，且 M/L 大屏不被强行换成侧轨。*

- **AC-1 [P0] Hold 键正圆（横屏侧轨）**：横屏侧轨作用域 `.tpad-main .tkey--hold` 设 `border-radius:50%`，computed 圆角 = 键径（48px）一半 ±1px；左右轨 Hold 均可点、正圆几何与设计稿一致。验证：verify-ui computed 断言 + QA 截图对拍。
- **AC-2 [P0] 独立 .rail 轨道元素**：横屏侧轨轨道以独立 `.rail` 元素承载（含设计稿的单边描边/毛玻璃细节），不再依赖 ::before/::after 全边描边模拟；DOM 结构存在 `.rail` 且其样式与设计稿一致。验证：verify-ui DOM/样式断言 + 截图对拍。
- **AC-3 [P0] M/L 横屏裁定**：设计稿仅画手机横屏 → 裁定 **M/L（≥600px）横屏维持行式底栏恒玻璃、不渲染侧轨**；侧轨仅作用于手机横屏（触屏且视口 <600px 横屏）。裁定结论写入 TECHNICAL.md；verify-ui 断点断言覆盖全部尺寸档与当前实现一致。验证：verify-ui 断点断言 + git diff 审查。
- **AC-4 [P0] 横屏几何零回归（承继 r24 AC-10）**：手机横屏侧轨键径 左十字 56 / 右 Hold 48+旋转 80、底部贴 safe-area（`env(safe-area-inset-bottom)`）、侧轨包围盒与棋盘中列零遮挡、z-index 不遮键——r24 AC-10 全部断言保持（零改动或纯追加）。验证：qa-e2e 既有用例 + git diff 审查。

### US-2 键帽质感统一（竖屏 + 横屏）
*作为移动端玩家，我希望六颗键全是干净的正圆，旋转主键的紫色像设计稿那样醒目但依旧玻璃质感。*

- **AC-5 [P0] 全触控键帽正圆**：S 竖屏 dock 与横屏侧轨作用域内 `.tpad-cross .tkey`、`.tpad-main .tkey--rotate`、`.tpad-main .tkey--hold` 全部 `border-radius:50%`（Hold 补漏，十字/旋转保持）；不新增 radius token，沿用既有 token 体系。验证：verify-ui 样式断言覆盖三键类。
- **AC-6 [P0] 旋转键主色增强**：旋转主键微底/常亮环的紫色突出感对标设计稿（不改变按键功能与尺寸）；仅复用既有玻璃/霓虹 token、零新增色板，且不降低棋盘辨识度（C 默认态下棋盘清晰可辨）。验证：设计稿截图对拍 + verify-ui 断言 token 归零新增 + QA 截图。

### US-3 设置弹层「操作区背景」2×2 缩略选择器
*作为玩家，我希望背景四个选项看得见样子再选：两行排开、每个带小示意图和名字，选中的一眼能认出。*

- **AC-7 [P0] 2×2 网格布局**：四档选项每行 2 个、共 2 行（2×2 网格）；任意档位值下选项不横向挤出/堆叠（320px 视口下每选项不换行、无横向溢出）。验证：verify-ui 断点断言 + QA 截图。
- **AC-8 [P0] 缩略图 + 名称**：每个选项包含真实呈现该皮肤的小尺寸缩略预览（复用皮肤 CSS 变量的 mini-dock 示意，非静态图标占位），缩略图下方**另起一行**显示名称（如「A 玻璃 dock」）。验证：verify-ui DOM/样式断言 + QA 截图对拍。
- **AC-9 [P0] 选中态与 radio 语义**：选中项视觉清晰可辨（高亮/勾选/描边任一种，四档互斥）；仍为 radio 语义（互斥单选、键盘可达、聚焦态清晰——承继 r24 AC-14/r16 可访问性）。验证：qa-e2e 单选交互用例 + 键盘操作用例。
- **AC-10 [P0] 行为零变化**：切换仍即时生效（不重载、不重置对局、引擎快照零漂移）；持久化 `tetris.dockSkin` 通道与非法回退 fade 全部不变；非触屏桌面（has-touch=false）整组不显示不变。验证：qa-e2e 四皮肤循环切换 + persist 单测（沿用 r24 对抗用例，零改动）。

### US-4 零回归出口
*作为产品，我要求这三处视觉校正不碰引擎、不碰桌面、不碰验证基线。*

- **AC-11 [P0] 引擎/音效 0 diff**：game.js / audio.js 0 行 diff；代码头 VERSION 三模块一致（verify-constants 绿）。验证：git diff 审查 + verify-constants.cjs。
- **AC-12 [P0] 皮肤与键帽作用域**：四套皮肤与正圆/主色修正仅作用于 S 竖屏 dock 与手机横屏侧轨；M/L 行式底栏（竖屏与横屏，含 AC-3 裁定）恒玻璃零回归；桌面视觉零变化。验证：verify-ui 断言 + git diff 审查 style.css 作用域。
- **AC-13 [P0] 触控行为零回归**：触控=键盘回放器路径零逻辑改动；按压态 / r16 三态 / safe-area / 多指守卫与 r16/r24 断言一致。验证：qa-e2e 既有触屏仿真用例沿用 + git diff 审查。
- **AC-14 [P0] 七套全绿**：verify-game / verify-ui / verify-audio / verify-constants / verify-persist / assembly-check / qa-e2e-jsdom 七套全绿；既有断言零改动或纯追加（verify-persist 登记改写仅限 r24 已登记的 dockSkin 往返 1 处，禁止新增改写）；r24/r21/r19/r16 既有用例零回归。验证：七套脚本执行 + git diff 审查。
- **AC-15 [P1] 辨识度与可访问性**：C 默认态与全部四皮肤下棋盘辨识度不降低（正常亮度清晰可辨）；radio 组键盘可达、聚焦态清晰；触屏键位图例与十字/旋转含义一致（承继 r24 AC-14/r16 AC-13）。

## 3. 范围与非目标（Non-goals）

- **不改**：桌面布局与键鼠操作、游戏引擎计分/锁定/音效逻辑、TOUCH_KEYS 契约字面量与六键功能、has-touch 判定（r21）、r19 一屏零滚动机制、四皮肤语义与命名（A/B/C/D 不变）。
- **不做**：新增皮肤或吸顶新增色板/阴影/半径 token（AC-6 收紧为零新增调色）、皮肤参数化（透明度/动画时长）、M/L 横屏侧轨（已裁定恒行式底栏）、真机自动截图回归（沿用 r24 人工补测清单机制）。

## 4. 交互流程摘要

1. **横屏**（手机 <600px）：左轨十字 56 + 右轨独立 `.rail`（Hold 48 正圆 + 旋转 80），贴 safe-area、零挡中列；M/L 横屏不渲染侧轨、维持行式底栏恒玻璃。
2. **竖屏（S）**：dock 六键全正圆（Hold 补 `border-radius:50%`），旋转主键微底/常亮环紫色增强；皮肤按 `tetris.dockSkin`（默认 C 渐隐）渲染于 dock/侧轨。
3. **设置**：设置弹层 → 「外观」分组 → 「操作区背景」2×2 网格（每选项缩略图 + 下方另起一行名称）→ 选中即高亮 → 即时应用皮肤（不重载、引擎无感）→ 写入 persist；重开/刷新恢复，非法值回退 fade；非触屏桌面整组隐藏。
4. **零回归**：触控=键盘回放器路径、按压态/三态/safe-area/多指守卫维持；桌面与 M/L 恒玻璃零变化；game/audio 0 diff。

**风险**：
- **R1 M/L 横屏裁定歧义**：设计稿仅画手机横屏，M/L 走轨还是底栏存在二义。缓解：PRD 已裁定 M/L 恒行式底栏（AC-3），UI/UX 复核设计稿后把结论写入 TECH，verify-ui 断点断言锁档。

- **R4 回归红线**：game.js/audio.js 必须 0 diff、回放器零逻辑改动。缓解：改动面限 index.html/style.css/ui.js/persist.js + 验证脚本（断言纯追加或沿用既有登记），AC-11/AC-14 出口审查。
- **R5 2×2 布局宽度预算**：缩略图+名称双行选项在 320px 视口可能宽度紧张。缓解：纯 CSS 收口网格列宽、断点断言（AC-7）锁零溢出。
