## 0. 现状与约束（先读）

1. **工作区场景**：项目已有完整前端代码（`index.html` / `game.js` / `audio.js` / `ui.js` / `style.css`）与既有设计规范（本文档 v1.0~v2.8 累积）。**本次设计不推翻既有规范**，在既有 token / 布局 / 组件体系上做**最小 UI 增量**，新增/修订部分一律以「**【v2.9】**」标注。
2. **PRD 硬约束（不可协商）**：
   - 视觉风格为「科技玻璃」：深色背景（背景主色亮度 ≤ 15%）、毛玻璃 `backdrop-filter: blur()` 生效、霓虹光效 ≥ 1 种、信息面板（AC-07）。
   - 零外部依赖：禁止 CDN 库/字体/图片，字体用系统字体栈（§5.1）。
   - 单文件内联：不使用 ES Module、不发起任何网络请求（AC-08）。
   - 仅键盘操作、桌面优先；兼容 Chrome/Edge ≥ 90、Firefox ≥ 95、Safari ≥ 15。
   - 运行帧率 ≥ 55 FPS、操作响应 ≤ 100ms、数值刷新 ≤ 200ms（AC-02/AC-06）。
3. **设计定位**：玻璃与霓虹是 PRD 强制项，但按「product register」克制使用——毛玻璃仅用于静态面板与遮罩，霓虹光效用于「状态与反馈」，不用于装饰堆砌。开关控件遵循既有「科技玻璃紧凑按钮」体系（`.btn--audio`），不另造新组件形态。
4. **【v2.9】本次变更边界（AC-19）**：踢墙为**纯控制开关**，UI 侧只新增一个信息面板开关行：
   - 不改变既有**布局结构**（仍为 §2.1 三列 grid：`240px | 340px | 240px`），踢墙开关加入**左信息面板**中部「设置区」，与幽灵块/BGM 开关同区同宽（100%），不新增独立面板/DOM 层；
   - 不改变既有**视觉 token**（§5.1 全部颜色/字号/间距/圆角/辉光原样保留），踢墙开关**复用** `#btn-bgm`/`#btn-ghost` 同款「开启态描边微金、关闭态中性」规则组（§5.3）；
   - 不改变既有**动效清单**（§4.3 原样保留）——踢墙开关本身无动画（只读 `.btn--audio` 切换态），旋转成功/失败反馈沿用既有旋转音效与方块位置渲染（引擎驱动，UI 不新增反馈层）；
   - 不改变**幽灵块渲染**（§3.6/§5.6 保持）——踢墙命中后方块落点变化，幽灵块沿用既有「每次 `renderAll` 按当前快照 `ghostY` 重算」机制自动同步（AC-12 实时刷新已覆盖，无需新规则）；
   - 只读开关：UI 仅置初值（默认开）+ 镜像 + 写回持久化，**不驱动引擎**（开关判定在 `game.js rotate` 内自读状态），符合既有「设置旁观看写」模式（§8）。

## 1. 设计定位与原则

### 1.1 氛围一句话（调色板锚点）

> 「深夜霓虹街机厅：近乎纯黑的空间里，玻璃面板折射靛紫与琥珀金双色辉光，方块如霓虹灯管逐格点亮。」

### 1.2 设计原则（5 条）

| # | 原则 | 落地 |
|---|---|---|
| P1 | **界面让位于方块** | 板面是唯一焦点；面板/按钮只承担信息与操作，亮度与饱和度均低于方块。**【v2.9】踢墙开关为低调设置行，不抢占注意力** |
| P2 | **状态即光效** | 霓虹只表达状态与反馈；开关「开」态用微金描边/高亮表达，与实体块霓虹辉光区分 |
| P3 | **毫秒级响应** | 所有操作反馈 ≤ 100ms 内完成（帧内处理），数值变化 ≤ 200ms 可见。【v2.9】切换踢墙开关后下一次旋转即按新状态执行（≤100ms，AC-19.5） |
| P4 | **动效服务于节奏** | 动效时长 ≤ 800ms，缓动用 ease-out 指数曲线；`prefers-reduced-motion` 时全部降级为瞬时/淡化 |
| P5 | **自包含即优雅** | 系统字体栈 + 内联资源 + 逐项降级（backdrop-filter、OKLCH、网格），老浏览器核心玩法不失效 |

## 4. 交互与动效说明

### 4.1 输入映射（v2.9 无新增按键）

踢墙开关为**鼠标/触摸点击的 UI 设置**，不映射到游戏操作键。旋转键位 `↑ / X`（顺时针 90°）行为随开关态变化（§4.2），键位图例不变。其余输入映射与既有 v2.8 完全一致。

### 4.2 旋转行为随开关态（AC-19，UI 只读开关、引擎判定）

| 开关态 | `↑ / X` 旋转行为（AC-19.2/19.4） | UI 层 |
|---|---|---|
| **开**（默认） | 旋转后形状直接合法 → 原地旋转成功；碰撞 → 按踢墙偏移表逐格尝试（右移→左移→上移…，每方向 1~2 格），命中（偏移后不碰撞且在板内）→ x/y 更新、rot 生效、播放旋转音效；全部失败 → 保持原位（x/y/rot 不变） | 无新增视觉效果；方块位置/姿态由引擎驱动渲染，幽灵块沿用实时刷新自动同步（§0.4） |
| **关** | 旋转碰撞 → x/y/rot 均不变、不尝试任何偏移、返回 `{ ok:false, reason:'wall-kick-denied' }`（v2.8 AC-18 语义） | 同上 |

- **切生效时点**：游戏中点开关后，**下一次旋转操作**即按新状态执行（≤100ms，AC-19.5），无需暂停/重开。
- **UI 只读原则**：`ui.js` 开关仅 → 置初值（默认开）+ 切换本地闭包态 + 镜像按钮（aria/文案）+ 旁观写回持久化；**不调用引擎 setter**（引擎 `rotate` 内自读开关状态），避免「第三变更入口」破坏既有持久化旁观架构（§8）。
- **幽灵块联动**：踢墙命中改变方块落点，幽灵块沿用既有「每次 `renderAll(s)` 按 `s.piece` 调 `ghostY` 重算」机制，**旋转成功同帧刷新落点**（AC-12.3 已覆盖，无新增规则，§0.4 风险已闭合）。

### 4.3 动效清单

与既有 v2.8 §4.3 **完全一致，零新增**。踢墙开关本身无动画（仅 `.btn--audio` 开/关态描边/文字色切换，随点击即时生效，120ms 级），旋转成功/失败的反馈为**引擎驱动的位置/姿态变化 + 既有旋转音效**，UI 不新增独立反馈动效（AC-19.8 零副作用）。

### 4.4 【v2.2】幽灵块交互与刷新时机（保持，v2.9 无关）

同既有 §4.4，本文不重复展开——踢墙命中改变落点时，幽灵块仍按既有「随旋转成功同帧重算」规则自动同步（历史正文见 `docs/teamflow/history/v2.8/DESIGN.md` §4.4）。

## 5. 视觉规范

## 7. 性能注意（支撑 ≥ 55 FPS / 响应 ≤ 100ms）

与既有 v2.8 §7 **完全一致**；踢墙开关为**纯 DOM 设置行**，不参与逐帧渲染（旋转渲染仍走单一 Canvas、跳帧代价 ≤ 200 格），开关切换仅一次 DOM 类切换 + 持久化写回，对帧率/响应零影响。踢墙判定在 `game.js rotate` 内（纯函数，偏移表 ≤ 4 格逐格 `collides` 判定，O(1) 常数级），满足 ≤100ms 操作响应（AC-19.5）。
