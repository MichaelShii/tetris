# r17 全面响应式重排 PRD

## 1. 背景与目标

移动端已通过 r16 触屏控制可玩，但界面仍是桌面版原样缩小：面板横向铺满、触控按键散落、视口利用率低，不符合移动端操作习惯。用户已确认范围：**全面响应式重排——竖屏单列重排 + 底部触控操作区 + 平板/桌面多档断点**。

目标：

- **G1 竖屏单列重排**：手机竖屏下全部面板按移动端习惯的单一纵向列排布（信息流自上而下），无横向滚动。
- **G2 底部触控操作区**：触控按键固定视口底部（拇指自然区），避让安全区（刘海/底部手势条），不遮挡棋盘与信息面板。
- **G3 平板/桌面多档断点**：平板多列布局、桌面保持 r16 基线布局零视觉回归。
- **G4 行为零回归**：r16 触屏控制语义（六键等效/显隐/多指/防误触）完整保留；引擎/音效/持久化零改动；七套验证脚本全绿。

## 2. 用户故事（含验收标准）

- **US-1 竖屏手机玩家**：手机竖屏打开即得单列布局，标题→HUD 统计→预览→棋盘→Hold 自上而下，拇指区域干净。
  验收：AC-1、AC-2、AC-10。
- **US-2 触控操作玩家**：六键在底部固定区，大拇指轻松够到；带刘海/底部条的设备不遮挡按键；按键不小不挤。
  验收：AC-3、AC-4、AC-11。
- **US-3 平板/横屏玩家**：平板不再是一整条竖列，棋盘居中、信息分列；小屏横屏（568×320）紧凑可玩。
  验收：AC-6、AC-9。
- **US-4 桌面玩家**：≥1024px 桌面布局与 r16 交付基线完全一致，无任何视觉/交互回归。
  验收：AC-7。
- **US-5 转动设备的玩家**：对局中旋转屏幕或拖动窗口跨越断点，布局平滑切换，对局状态分毫不丢。
  验收：AC-8。
- **US-6 全体玩家回归保障**：非触屏设备不出现触控区；所有既有按钮各档位可达；七套脚本全绿出口。
  验收：AC-5、AC-12、AC-13。

## 3. 断点与布局规格（数值单一事实来源，技术方案直接引用）

| 档位 | 视口宽度 | 布局模式 | 触控区 |
|---|---|---|---|
| S 竖屏单列 | <600px | 单列：标题→HUD 统计→预览→棋盘→Hold→触控区 | 固定视口底部 |
| S 横屏变体 | <600px 且 height<width（如 568×320） | 棋盘与信息面板紧凑并排，全部可见 | 保留，可达 |
| M 平板 | 600–1023px | 棋盘为主区居中，HUD/预览/Hold ≥2 列分布 | 触屏设备保留，与棋盘 0 重叠 |
| L 桌面 | ≥1024px | 保持 r16 基线布局（几何快照比对一致） | 仅 has-touch 设备显示（r16 延续） |

触控操作区规格：底部固定（不随滚动离开视口）；上边缘 ≥ 视口高度 50%；总高 ≤ 视口高度 45%；与游戏面板包围盒交集面积 = 0；底内边距 ≥ max(8px, env(safe-area-inset-bottom))。
可读性规格：统计数值字号 ≥ 16px，其余正文 ≥ 12px，禁止截断省略。
断点实现：纯 CSS 媒体查询，禁止由断点切换触达引擎状态。

## 4. 验收标准（AC 清单，本任务夹内编号）

- **AC-1 [P0] 竖屏单列重排**：S 档（代表性 320×568 / 375×667 / 390×844 / 430×932）下 `document.documentElement.scrollWidth ≤ clientWidth`（横向溢出 0px）；主面板（标题、HUD、预览、棋盘、Hold、触控区）沿单一纵向列序排布，任意两面板包围盒无重叠。验证：verify-ui 断点断言 + QA 截图抽查。
- **AC-2 [P0] 固定底部触控操作区**：S 档触控区固定视口底部，页面滚动前后位置不变；触控区上边缘 ≥ 视口高度 50%、总高 ≤ 视口高度 45%；触控区与棋盘/预览/Hold 包围盒交集面积 = 0（375×667 与 390×844 实测）。验证：verify-ui 几何断言 + qa-e2e 滚动前后位移断言。
- **AC-3 [P0] 安全区避让**：触控区底内边距 ≥ max(8px, env(safe-area-inset-bottom))；模拟 inset=34px（iOS 底部条）与 inset=0 两取值下按键内容完整可见。验证：verify-ui 计算样式断言；真机补测入 QA 人工清单。
- **AC-4 [P0] 触控规格保底（r16 AC-12 延续）**：各档触控按键与全部可点元素命中区域 ≥ 44×44px；触控区六键（左/右、软降↓、硬降、旋转、Hold）齐全、相对语义不变。验证：verify-ui 尺寸断言。
- **AC-5 [P0] 仅触屏渲染回归（r16 AC-1 延续）**：触控区显隐仍由 `html.has-touch` 纯 CSS 控制；非触屏设备任意档位不渲染触控区；显隐切换不重置对局。验证：verify-ui has-touch 断言沿用。
- **AC-6 [P0] 平板档多列**：600–1023px（抽样 768×1024 / 834×1112）下棋盘为主区居中，HUD/预览/Hold ≥2 列分布；触屏设备触控区保留且与棋盘 0 重叠；无横向滚动。验证：verify-ui M 档断言 + QA 截图抽查。
- **AC-7 [P0] 桌面档零回归**：≥1024px 下布局与 r16 基线几何一致（面板相对位置/间距/居中与基线快照比对一致），桌面视觉无变化；has-touch 触屏桌面（如 Surface）触控区仍可用（r16 AC-10 延续）。验证：verify-ui L 档断言 + QA 与 r16 基线截图比对。
- **AC-8 [P0] 跨档切换不丢状态**：对局中 resize 或旋转跨越任意断点（390→1024→390；320×568↔568×320）不重载、无引擎重置——得分/棋盘/预览/Hold/难度与切换前逐项一致，仅布局层变化；连续跨档 5 次无累积漂移。验证：qa-e2e-jsdom 断点切换用例。
- **AC-9 [P1] 小屏横屏变体**：width<600px 且 height<width（如 568×320）下棋盘与信息面板紧凑排列全部可见，触控区可达可点，无元素溢出/裁剪视口。验证：QA 截图 + verify-ui 几何断言。
- **AC-10 [P1] 可读性**：S 档统计数值字号 ≥ 16px、其余正文 ≥ 12px；所有文本完整可见，无 ellipsis、无 overflow hidden 裁剪内容。验证：verify-ui computed-style 断言。
- **AC-11 [P1] 触控习惯区与误触防控**：S 档触控区几何中心位于视口高度 55%–92%；按键间距 ≥ 8px；多指同时按压互不串扰（r16 AC-9 延续，跨通道语义不变）。验证：verify-ui 几何断言 + QA 真机多指补测。
- **AC-12 [P0] 全流程可达（r16 AC-11/AC-2 延续）**：现有 HTML 按钮（新建/暂停/设置/Hold 等）在 S/M/L 各档、触屏与非触屏下全部可达可点；触控区按键全流程可用，PAUSED/OVER 下按钮无副作用。验证：qa-e2e 全流程用例 + QA 各档点击抽查。
- **AC-13 [P0] 零回归出口**：七套脚本全绿（verify-game / verify-audio / verify-ui / verify-persist / verify-constants / assembly-check / qa-e2e-jsdom）；verify-ui 新增断点断言规模 ≤ 原有+3（r16 17→20 同量级）；game.js / audio.js / persist.js 0 行 diff；VERSION 三模块一致。验证：七条命令逐一执行全绿。

## 6. 交互流程摘要

打开页面 → 依视口宽度命中 S/M/L 断点档：S 档面板单列（标题→HUD→预览→棋盘→Hold→底部固定触控区），横屏小屏自动切 S 横屏变体；M 档棋盘主区 + 侧栏多列；L 档保持桌面基线。触控区仅 `has-touch` 设备显示，按键行为与 r16 完全一致（键盘事件回放器）。对局中跨档切换只换布局、不触达引擎状态。

## 7. 依赖与风险

**依赖**：r16 触屏控制（基线）；`html.has-touch` 显隐机制；目标浏览器支持 `env(safe-area-inset-*)` 与 CSS 媒体查询（现代移动 WebView/Safari/Chrome 均满足）；verify-ui / qa-e2e-jsdom 脚本扩展。

**风险**：
- R1（中）iOS 安全区/安卓手势条差异 → 对策：`env()` 统一避让 + 真机补测入 QA 人工清单；真机不可达时以模拟 inset 值断言兜底。
- R2（低）断点切换抖动/误触状态 → 对策：纯 CSS 媒体查询优先、禁 JS 触达状态；AC-8 e2e 断言。
- R3（低）桌面档回归 → 对策：AC-7 与 r16 基线几何快照比对。
- R4（中）jsdom 无法验证真实视口几何/媒体查询 → 对策：断点断言以 computed style / class 层表达，真实视口几何入 QA 人工补测清单。
- R5（低）触控区遮挡/误触 → 对策：AC-2 零重叠 + AC-11 习惯区约束。
