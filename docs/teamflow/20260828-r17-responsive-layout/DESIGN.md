# r17 全面响应式重排 — UI/UX 设计文档（DESIGN）

> meta 摘要：Tetris v3.4 响应式布局设计——S 竖屏单列（卡片流）+ 两行底部触控 dock + S 横屏变体 + M 平板多列 + L 桌面零回归；纯 CSS 实现，零新增视觉 token，DOM 不重排序。
> 基线依赖：docs/teamflow/20260827-r16-mobile-touch-controls（dock 显隐/六键语义/多指/防误触全部沿用）；取代：无（本设计只重排布局，不改任何既有已验证行为）。

---

## 0. 现状与约束（先读）

1. **既有规范不推翻**：视觉 token（§5）、组件体系（玻璃面板/按钮/开关/kbd/遮罩/toast）、动效清单（§4.3）、可访问性原则全部沿用，本设计只做**布局层的增量**，新增/修订一律以 **【r17】** 标注。
2. **PRD 硬约束（不可协商）**：三档断点（S<600 / M 600-1023 / L≥1024）+ S 横屏变体；dock 固定底部、上缘≥50% vh、总高≤45% vh、与面板 0 重叠、底内边距≥max(8px, env(safe-area-inset-bottom))；数值字号≥16px、正文≥12px；断点切换纯 CSS、禁止触达引擎状态；七套脚本全绿。
3. **DOM 不可重排序（关键约束）**：桌面基线是 `#main` 三列 CSS Grid 的自动放置（左=panel-left / 中=board-col / 右=panel-right）。若改动 DOM 节点顺序，L 档三列会错位 → **所有 S/M 档视觉重排必须走 CSS（媒体查询 + `display:contents` + `order`），DOM 顺序恒为 标题→左面板→棋盘→右面板→触控区**。
4. **L 档 = 现 style.css 原样**：≥1024px 不新增任何规则，r16 桌面基线（三列 `240|340|240`，1024–1100 维持既有 ≤1100 单列堆叠降级）天然保留 → AC-7 几何快照比对零风险。既有 ≤1100 堆叠、480/379 窄屏兜底、横屏侧轨、reduced-motion 规则全部保持原位。
5. **改动面**：仅 `index.html`（一处 stat 包裹归一，可选）/ `style.css`（断点框架）/ `verify-ui.cjs` + `qa-e2e-jsdom.cjs`（断点断言 ≤+3）；`ui.js` 预期零改动（如 verify 需暴露档位，用只读 CSS/class 表达，不写 JS 状态）。

## 1. 设计原则（【r17】移动端增量，桌面 P1~P5 原则不变）

| # | 原则 | 落地 |
|---|---|---|
| M1 | **拇指区可达优先** | 高频操作（六键）固定视口底部拇指自然弧区；dock 几何以「中心带 55%–92% vh」为硬约束反推高度 |
| M2 | **单列动线 = 阅读动线** | S 竖屏列序照 PRD：标题→HUD→预览→棋盘→Hold→按钮，自上而下信息密度递减，棋盘居中主宰 |

| M4 | **桌面零回归优先** | 一切新规则只写在媒体查询内；L 档不出现任何新选择器 |

## 3. 关键布局线框与规格

### 3.1 S 竖屏单列（<600px，portrait）【r17 核心】

```
┌────────────────────────┐     元素           order   卡化说明
│   TETRIS  ◉PLAYING      │ ①  #header           0   （不摊平，置顶）
├────────────────────────┤
│ ┌● 分数    最高分 ┐┐   │ ②  .stat-grid        10   HUD 卡（2×2 网格）
│ │ 012340   0      ││   │
│ │ 等级 1   行数 0 ││   │
│ └──────────────────┘│   │
│ [⚙ 设置]             │ ③  #btn-settings      20   紧凑按钮行（玻璃卡）
│ ┌───────────────┐    │ ④  .next-well         30   预览卡（canvas 48×80）
│ │ 下一个  ◣     │    │
├───────────────────────┤ ⑤  #board-col        40   棋盘卡（280×560 不变）
│ ┌───────────────┐    │
│ │   游 戏 板    │    │
│ └───────────────┘    │
│ ┌───────────────┐    │ ⑥  .hold-well         50   Hold 卡（canvas 48×24）
│ │ Hold  ◣       │    │
│ ├───────────────┤    │ ⑦  .key-hints         60   （has-touch 下已有规则隐藏）
│ │ [开始][暂停][重开] │ ⑧  #controls           70   按钮卡
└────────────────────────┘
  固定底部：触控区两行 dock（§3.5，不参与文档流列序）
```

实现要点（纯 CSS）：

- S 媒体查询内：`#main { display:flex; flex-direction:column; }`；`#panel-left,#panel-right { display:contents }`（摊平为 main 的直接子项，使其子块可跨面板参与 order；L 档不受影响）。
- 各摊平块卡片化：HUD/预览/Hold/按钮/设置各自成卡，复用既有 token（`--glass-bg` + `backdrop-filter` + 1px `--line` 描边 + `--radius-md` + 内边距 `--sp-3` + 外间距 `--sp-4`）——与原两面板同一视觉语言，仅粒度变细。
- `.stat-grid`：`display:grid; grid-template-columns:1fr 1fr;` 分数/最高分一行、等级/行数一行；分数值用 `--fs-xl`，其余统计值 ≥16px（AC-10）。
- 独占列序：`order` 值如右列；**触控区为 `position:fixed`，不参与文档流列序断言**（AC-1 的包围盒断言只测流内面板）。
- 底部预留（AC-2 零重叠）：`#main { padding-bottom: var(--dock-h) }`，`--dock-h` 与两行 dock 净高用同一 calc 表达式维护单一事实来源 → 滚底时最后一块按钮卡完整停在 dock 之上，dock 永不压住棋盘/预览/Hold。
- 横向溢出 0：`body{overflow-x:hidden}` 既有；单列块宽 100%，棋盘卡 280+32 内边距 ≤ 320 视口。

### 3.2 S 横屏变体（<600px 且 h<w，如 568×320）【r17】

```
┌ 标题(紧凑) ──◉PLAYING ┐
├ 分数 0123 │ 等级 2 │ 行数 4 │ ⚙ │        ← HUD 横带（一行四格）
├────────────┬──────────────┬─────────┤
│ ⟳ 旋转     │   游 戏 板     │ ▼ 软降   │    ← r16 侧轨（左 ◀▶⟳ / 右 ▼⤓Hold）不变
│ ◀ ▶ 移动   │ (CSS 等比缩放) │ ⤓ 硬降   │
│            │              │ 📦 Hold  │
│ [开始][暂停][重开]（顶栏横排）          │
└────────────┴──────────────┴─────────┘
```

- 左侧轨/右侧轨**完全复用 r16 横屏侧轨规则**（72px 轨、safe-area 贴边、玻璃轨 `::before/::after`），零改动。
- 主区横排：`#main { flex-direction:row }` 覆盖 ≤1100 堆叠；信息压缩为 HUD 横带（4 格一行、含 ⚙）+ 棋盘居中 + 按钮横排。
- **棋盘缩放**：280×560 canvas 在 320 高视口必须 CSS 等比缩放（`#board { width:auto; height:min(100%, 可用高); }` 或等宽 `scale` 包裹，保持 1:2 比例与画布渲染不变，仅显示缩放）→ 全部可见可玩（AC-9）。缩放只出现在本档媒体查询内。
- 标题压缩字号至 `--fs-xl`（24px）可省空间；无元素裁剪/溢出（AC-9）。

### 3.3 M 平板档（600–1023px）【r17】

```
≥768px（768×1024 / 834×1112 抽样）：
┌───────────────────────────────────────────┐
│      TETRIS  ◉ PLAYING                    │
├───────────┬─────────────────┬─────────────┤
│ 左面板     │   游 戏 板       │ 右面板      │   grid: 200px 340px 200px
│ （200px）  │   （340px）      │（200px）    │   gap 24 → 总宽 688 ≤ 768 ✓
│ 分数/等级  │                │ 键位图例    │
│ 预览/Hold │                │ 按钮组      │
│ 设置…     │                │             │
├───────────┴─────────────────┴─────────────┤
│  (触屏设备) r16 单行底栏，固定底部          │   底部预留 = dock 净高
└───────────────────────────────────────────┘

600–767px：两列 [棋盘主区 | 信息列(左面板→右面板纵向堆叠)]，grid: minmax(0,1fr) 340px
```

- 棋盘居中、双侧等宽 200px；信息/操作分居两侧即「HUD/预览/Hold ≥2 列分布」（AC-6）。
- 触屏设备保留 dock：沿用 r16 单行底栏（AC-11 中心带仅约束 S 竖屏，见 §5.3 取舍）；`#main` 底部预留同 §3.1 公式 → 与棋盘 0 重叠。
- 无横向滚动（AC-6）：`minmax(0,1fr)` 吸收余量。

### 3.4 L 桌面档（≥1024px）

零改动 = r16 基线：三列 `240px 340px 240px`、`gap --sp-6`、居中；1024–1100 沿用既有 `@media (max-width:1100px)` 单列堆叠（r16 行为本就如此，AC-7 快照不变）。触屏桌面（Surface 等）dock 沿用 r16 形态与显隐。

### 3.5 触控区两行 dock（S 竖屏）【r17 新形态】

**动机（几何推导）**：底部固定 dock 的几何中心纵坐标 = `vh − h/2`，AC-11 要求中心位于 55%–92% vh ⇔ **h ≥ 16% vh**。r16 单行底栏（净高约 64px）中心落在 94%–95% vh，无法满足 → S 竖屏必须抬高 dock 重心。

```
┌──────────────────────────────┐
│  ◀ 左    ▶ 右    ⟳ 旋转       │  上排：移动 + 旋转（主操作）
├──────────────────────────────┤
│  ▼ 软降   ⤓ 硬降  📦 Hold     │  下排：下落 + Hold（第二操作）
└──────────────────────────────┘
  高 h = 2×--tpad-key + 行距 --sp-4 + 上下内边距 2×--sp-3 + env(safe-area-inset-bottom)
  （48px 键 → 净高 ≈136px、≤379px 44px 键 → 净高 ≈128px；加 iOS inset 34 ≈170px）
```

| 视口 | h+vh 占比 | 中心位置 | AC-11 达标 |
|---|---|---|---|
| 320×568（44px 键, inset 0） | 128/568=22.5% | 88.7% vh | ✓ |
| 375×667（48px 键, inset 0） | 136/667=20.4% | 89.8% vh | ✓ |
| 390×844（inset 0） | 136/844=16.1% | 91.9% vh | ✓ |
| 430×932（inset 0） | 152*/932=16.3% | 91.8% vh | ✓（*宽屏档 padding 用 --sp-4） |
| 390×844（inset 34） | 170/844=20.1% | 89.9% vh | ✓ |

同时满足 AC-2：上缘 = vh−h ≥ 50% vh（实测 77%–81%）✓；总高 ≤ 45% vh ✓；AC-3 底内边距 ≥ max(8px, inset)（公式已含）✓；AC-4 键 ≥44×44 ✓；键距 `--sp-2` ≥8px ✓（AC-11）。

- 结构：同一 `.touchpad > .tkey` 六键，仅容器改为 `flex-wrap:wrap` 两行 + `align-content:center`；键组件样式零改动 → TOUCH_KEYS/事件绑定/ui.js 零改动。
- 材质：整条 dock 保持 r16 竖屏底栏玻璃（`--glass-bg` + blur + 顶部 1px `--line` + 上投影），仍是弹层之下（`--z-touchpad:5`，设置弹层 10/11 必盖其上）。
- 双拇指分区：上排左半 ◀▶ 左拇指、上排右半 ⟳ 与下排 ▼⤓📦 右拇指，减少跨拇指长按。

## 4. 交互与动效说明

- **行为零新增**：六键行为/防滚动缩放选中（`touch-action:none`、防选中、容器级 preventDefault）与 r16 完全一致；`html.has-touch` 纯 CSS 显隐不改（AC-5）；PAUSED/OVER 下按钮语义不变（AC-12）。
- **跨档切换（AC-8）**：断点切换 = 媒体查询命中 → 一次样式重算，瞬时重排；**不断点过渡动画**（避免重排中间态被几何断言误判）；不写 JS、不改 history/hash、不触达引擎状态。resize/旋转（390→1024→390、320×568↔568×320）天然无重载。
- **动效清单**：沿用 r16 §4.3——dock 键按下 `:active` 描边 primary + 标签 accent-hi + `scale(0.96)`（60ms ease-out）、辉光走 `::before` opacity；`prefers-reduced-motion` 由既有 §6 全局裁剪。无新增动效。
- **滚动关系**：S 档内容列比视口高（棋盘卡 592px 起），允许纵向滚动；dock 固定不随滚动（AC-2「滚动前后位置不变」），内容底部预留保证滚底时最后一卡悬于 dock 之上。

## 5. 视觉规范

### 5.1 设计 Token【r17 零新增、零覆盖】

全部沿用既有 token（色彩体系/字体栈/字号阶梯/间距/圆角/辉光/z-index，清单见 docs/teamflow/design/DESIGN.md §5.1）。本设计只**组合使用**：

| 用途 | 复用 token |
|---|---|
| S 卡片玻璃底/描边/圆角 | `--glass-bg` / `--line` / `--radius-md`，blur 20px saturate(140%)（与面板同源） |
| 卡片间距/内边距 | `--sp-4`（卡间）/ `--sp-3`（卡内）|
| dock 键 | `--tpad-key`（48px；≤379px 2.75rem=44px 既有规则保持）、`--surface-2`、`--line`、`--radius-md`、`--glow-primary` |
| dock 背景 | `--glass-bg` + blur + `--line` 顶描边 + 上投影（r16 底栏不变式）|
| 阴影 | 既有玻璃浮起 shadow |
| 层级 | `--z-board:1`/`--z-panel:2`/`--z-touchpad:5`/弹层 10/11/`--z-toast:20` 不变 |
| S 档底部预留高度 | 新 `--dock-h`（= 两行 dock 净高 calc，唯一事实来源，DOCK 与 main padding 共用） |

### 5.2 S 档文字（AC-10）

- 统计数值：分数 `--fs-xl`(24px)、最高分/等级/行数 ≥ `--fs-lg`(18px)（>16px 底线）；正文/标签 ≥ `--fs-xs`(12px)。
- 全面禁止 `ellipsis`/`overflow:hidden` 截断正文（S 档新出现的卡片/键标签检查一遍）；设置按钮等既有 `nowrap` 文案在 S 档宽度下放行换行或缩短内边距，不回退省略。

### 5.3 已知取舍（设计边界声明）

- **AC-11 中心带**按 S 竖屏样本（375×667/390×844/430×932）断言；S 横屏变体与 M/L 档沿用 r16 侧轨/单行底栏几何（其包围盒中心不适用该带，AC-9/AC-6 只要求可达与 0 重叠）——verify-ui 的中心带断言须按 portrait+<600 媒体过滤。
- **S 档视觉列序 vs DOM/Tab 顺序**：CSS `order`/`display:contents` 只改视觉，读屏与 Tab 焦点顺序仍为 DOM 序（HUD→预览→Hold→棋盘→按钮）——视觉 Hold 在棋盘后、焦点序 Hold 在棋盘前，为保 L 基线不重排 DOM 的必然取舍；AC-12 只要求可达可点，不要求焦点序与视觉序一致。
- 横屏棋盘缩放仅 CSS 显示缩放（不改画布分辨率与渲染逻辑），是「小屏横屏全部可见」的最小代价。

## 6. 可访问性要点

| 类别 | 要求 | 落地【r17】 |
|---|---|---|
| 触控目标 | ≥44×44 各档 | 键 48px 常态、≤379px 44px 兜底（既有规则保持）；S 卡内按钮（⚙/开始/暂停/重开）沿用既有 .btn 高度 → 复查命中区 |
| 焦点可见 | :focus-visible | 既有 2px `--accent` 外环保持不变，卡片化不破坏 |
| Tabbing | 全功能键盘可达 | 原生 `<button>` 全部沿用；S 档焦点序 = DOM 序（§5.3 取舍透明） |
| 读屏 | 语义不变 | `.touchpad` aria-label「触屏操控区」、六键 aria-label、状态灯 `aria-live` 全部沿用 r16 |
| 防误触 | 滚动/缩放/选中 | dock `touch-action:none` 等 r16 AC-8 规则原样保留；新两行布局不新增手势 |
| 对比度/动画 | WCAG AA / reduced-motion | token 未动，既有 §6 断言继续成立 |

## 7. 性能注意

- 布局重排为一次性样式计算，不进逐帧路径；断点切换零 JS、零布局抖动。
- `display:contents` 不产生新合成层；S 档卡片数（5 张玻璃卡）略多于原 2 面板 → 每卡一个 backdrop-filter 实例，移动端静态小卡成本可控，不随帧变化（无逐帧模糊）。不引入新滤镜/动画/大图。
- 既有 `background-attachment:fixed` 在移动端的已知渲染开销：**不在本需求范围**，不处理（记入 memory 待办备查）。

## 8. 交付清单（给前端实现者，【r17】专项）
