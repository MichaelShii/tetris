# PRD — 多格预览队列与设置开关（r15）

## 1. 背景与目标

### 1.1 背景

现行版本（r14）Next 预览区仅展示单个"下一方块"（基线 AC-06.1；v2.7 曾明确"不做前瞻窗口扩展"）。玩家无法预判后续多个方块，在 7-bag 随机（v2.7）、踢墙旋转（v2.9）、Hold（r14）组合玩法下规划空间受限。现代 Tetris 普遍提供 2~5 格预览队列。

### 1.2 目标

1. **多格预览队列**：Next 预览区从单格升级为 3 格队列，展示接下来 3 个方块，顺序与实际出块严格一致（7-bag 派生，不改随机语义）。
2. **设置开关**：设置弹层新增"预览队列"开关（默认开、持久化），关闭时整体隐藏 Next 预览区，重新开启立即恢复。
3. **零回归**：r14 Hold 全量行为、7-bag 随机、设置持久化、既有 AC-01~AC-19 语义不回归；七套验证全绿。

### 1.3 成功指标（可量化）

| 指标 | 量化标准 |
|---|---|
| 队列长度 | 任意检查点（lockFlow 后）`state.queue.length` 恒为 3 |
| 顺序一致性 | 固定序列打桩下连续 20 次出生，出块顺序与队列展示顺序 100% 一致 |
| 开关即时性 | 切换后 Next 区显示/隐藏 DOM 状态变化 ≤ 200ms，游戏状态（棋盘/分/级/行）不变、不重置 |
| 持久化 | 刷新页面后开关保持上次选择（首次默认开） |
| 回归底线 | 七套验证脚本全绿；r14 AC-1~17 专项 35 项无回归 |

## 2. 用户故事与验收标准

### US-1：多格预览队列显示

**作为**玩家，**我希望**提前看到接下来多个方块，以便规划摆放。

**验收标准**：

- **AC-1**：游戏就绪/进行中，Next 预览区纵向展示接下来 3 个方块（含即将出生的下一块），队列顺序与该局 7-bag 出块序列一致。
- **AC-2**：使用固定序列打桩 7-bag 随机源时，队列展示顺序与随后依次出块顺序严格一致——QA 断言连续 20 次出生无错位、无缺漏。
- **AC-3**：当前方块锁定后队列前移：队首方块成为当前方块，队列尾部由随机源补充 1 个新方块，队列长度恒为 3。
- **AC-4**：每格渲染与既有 next-well 一致（rot=0、方块色、48×24 迷你渲染，复用现有渲染器扩展），队列区无方块时空格留白、不报错。
- **AC-5**：PAUSED 态队列冻结不变化；GAME_OVER / restart 后队列重置为初始 3 个方块，与新的随机序列一致。

### US-2：设置开关控制

**作为**玩家，**我希望**在设置中开关预览队列，以适配不同难度偏好。

**验收标准**：

- **AC-6**：设置弹层新增"预览队列"开关控件，默认开启；交互复用既有设置开关模式（点击切换、Tab 聚焦、`aria-checked`/`aria-pressed` 状态不只靠颜色、即时生效）。
- **AC-7**：关闭开关后 Next 预览区整体隐藏（含多格队列与单格展示——队列已取代单格 next），游戏（棋盘/下落/消行/计分）不受影响、不重置；重新开启立即恢复 3 格队列显示。
- **AC-8**：开关状态经既有设置持久化通道（localStorage）存取，刷新后保持上次选择；首次使用默认为开。
- **AC-9**：开关关闭期间不影响出块序列；重新开启后队列内容与实际序列一致（无错位、无凭空生成）。

### US-3：引擎一致性

**作为**玩家，**我希望**队列只是"看得更远"，绝不改变游戏本身随机、玩法与计分。

**验收标准**：

- **AC-10**：引擎新增队列状态与读取接口（如 `state.queue` + 后续 n 块 peek），snapshot 覆盖队列字段、restart 重置；verify-game 新增队列用例（长度/顺序/前移/重置/开关联动）。
- **AC-11**：Hold（r14）与队列共存——暂存/交换取出的是"下一个出生方块"即队首，hold 操作不影响队列内容与顺序；r14 AC-1~17 全量回归（Hold 专项 35 项保持绿）。
- **AC-12**：七套验证脚本全绿（verify-game / verify-audio / verify-ui / verify-constants / verify-persist / assembly-check / qa-e2e-jsdom），无回归；新开关与既有设置（音量/静音/幽灵/BGM/踢墙/Hold）互不干扰。

## 3. 功能范围与非目标

### 3.1 功能范围

| 模块 | 内容 |
|---|---|
| **多格预览队列（本次）** | Next 预览区升级为 3 格队列（取代单格 next 展示）；数据由 7-bag 派生、与出块顺序严格一致；队列长度常量 `NEXT_QUEUE_SIZE=3` 置于 game.js 顶部常量区 |
| **设置开关（本次）** | 设置弹层新增"预览队列"开关：默认开、即时隐藏/恢复、经 persist 通道持久化 |
| **Hold / 持久化 / 7-bag** | 保持基线行为；hold 语义与队列队首绑定（AC-11）；队列数据源复用 7-bag（不改随机算法） |

### 3.2 非目标（本期明确不做）

- **不做**队列格数可配置（设置中不提供格数选项，格数固定为 3）。
- **不做**队列内的点击/拖拽/直接操作。
- **不做**7-bag 随机算法改动（仅扩展"后续 n 块可读"能力）。
- **不做**"隐藏队列"的难度模式（仅开关控制的显示/隐藏，不改难度数值）。

## 4. 交互流程概述

1. **启动/重开**：引擎按 7-bag 生成初始 3 格队列，Next 区显示 3 个方块。
2. **游戏中**：当前方块锁定 → 队首成为当前方块、队列尾部补 1、队列滚动刷新（≤ 200ms）。
3. **设置**：齿轮 → 设置弹层 → 切换"预览队列"开关 → 关闭：Next 区立即隐藏；开启：立即恢复 3 格队列（游戏不暂停、不重置）。
4. **刷新页面**：开关按上次选择恢复（默认开）。

## 5. 数值与设计决策（实现基准）

| 项 | 值 | 说明 |
|---|---|---|
| `NEXT_QUEUE_SIZE` | 3 | 队列格数常量，game.js 顶部常量区（数值单一事实来源，与 verify-* 脚本同步校验） |
| 队列数据源 | 7-bag 派生 | 基于 v2.7 随机器，仅扩展"后续 n 块"读取接口，不改随机语义 |
| 开关默认值 | 开 | 与 r14 Hold 开关默认开一致 |
| 开关持久化键 | `previewQueueEnabled` | persist.js 布尔字段（sanitize/encode/readState 同步） |
| 格渲染 | 48×24 迷你渲染 | 复用 next-well/hold-well 渲染模式（rot=0、方块色） |
| 关闭态 | 整区隐藏 | Next 区显示/隐藏由开关控制（取代单格 next 展示） |

## 7. 依赖与风险

### 7.1 依赖

- **r14 Hold**：hold 取块语义（r14 AC-1）绑定"下一个出生方块"即队首；hold-well 渲染模式复用。
- **v2.7 7-bag**：队列数据源；必须保持袋内 Fisher-Yates 契约（既有 7-bag 契约组扩展）。
- **v2.6 持久化 + r9 设置弹层**：开关存取通道与展示位置。

### 7.2 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 随机源现仅暴露"下一块" | 接口不足以支撑队列 | 技术方案定义"后续 n 块"peek 纯函数 + 单测扩展 7-bag 契约组；不改随机语义 |
| 队列与锁定流程时序错位 | 出生顺序与展示不一致 | lockFlow 统一"先耗队首、再补尾"；E2E 固定序列连续 20 次出生断言 |
| Hold 交互耦合 | r14 回归 | hold 只消费队首（等价"下一个出生方块"）；QA 保留 Hold 专项 35 项复跑 |
| verify-constants 存量漂移（memory 待办） | 版本断言红 | 版本号处理遵循技术方案裁定；队列不新增 VERSION 字段，不放大漂移 |
| 开关关闭后信息缺失 | 玩家误以为功能丢失 | 开关默认开；关闭态为显式用户选择；README 与键位/设置图例说明 |
