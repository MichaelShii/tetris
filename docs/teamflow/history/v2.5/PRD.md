## 1. 背景与目标

### 1.1 背景
v2.0 起已交付七类合成音效（SFX，AC-09）与音量/静音控制（AC-10），全部采用 Web Audio API 实时合成、零外部音频文件、保持 file:// 双击即玩/零网络/离线约束。**背景音乐（BGM）**自 v2.0 起列为 P2 可选增强（README「已知取舍」：背景音乐（BGM）与循环配乐 P2 可选；PRD §3.2 非目标明示「不做 BGM 等既有 P2 清单项」）。

本迭代将其转为**正式功能**：BGM 以与 SFX 完全同源同哲学的方式实现——Web Audio 实时合成循环旋律，零外部音频文件，不引入任何 `http(s)` 或本地音频资源引用，从而不破坏 AC-08 自包含、AC-09.5 零音频文件。交付后关闭 README「已知取舍」P2 BGM 项。

### 1.2 目标
1. **BGM 播放/停止**：信息面板新增 BGM 开关，控制实时合成循环旋律的播放与停止（默认关闭）。
2. **音量/静音联动语义**：BGM 与既有音量/静音控制（AC-10）联动——音量跟随主音量 0–100%、静音即静 BGM、取消静音即恢复；共享音效引擎的 AudioContext 与主增益，避免重复上下文、无需重复 unlock。
3. **自包含/离线零破坏**：零外部音频文件、零网络请求；AC-08 自包含、AC-09.5 音频文件审计、AC-01~14 回归底线全绿。
4. **自动播放合规**：首次用户交互前 BGM 不发声、Console 0 报错；降低级（Web Audio 不可用）时玩法 100% 正常、仅无声。
5. **关闭 P2 项**：README「已知取舍」中「背景音乐（BGM）与循环配乐（P2 可选）」项关闭，不再列为非目标。

## 2. 用户故事与验收标准

> 验收标准均为可执行测试项；测试在 Chrome/Edge 最新稳定版、`file://` 直接打开 `index.html` 场景下执行。
> **（v2.5）** 既有 AC-01 ~ AC-14 保留且语义不变（表述压缩），为回归底线；本次新增 **US-15 / AC-15（背景音乐 BGM）**。

### US-01 开始游戏
作为玩家，我打开页面后可以立即开始游戏，无需任何配置。
**验收标准（AC-01）**
1. 双击 `index.html` 后 ≤ 2s 渲染完整游戏界面，无白屏。
2. 初始展示「开始」按钮与完整游戏板（10 列 × 20 行）。
3. 点击「开始」后 ≤ 300ms 进入进行态，首个方块出现并可操作。
4. 初始分数 0、等级 1、消除行数 0。

### US-02 移动与旋转方块
作为玩家，我可以用键盘控制当前方块。
**验收标准（AC-02）**
1. `←`/`→` 左右移动 1 格，按住不放以 ≥ 8 次/秒连续移动。
2. `↓` 软降 1 格，按住持续软降。
3. `↑`（或 `X`）顺时针旋转 90°。
4. 移动/旋转受边界与障碍阻挡：被拒时方块位置不变、游戏不报错。
5. 所有操作响应 ≤ 100ms（帧内即时响应）。

### US-03 自动下落与消行
作为玩家，方块自动下落，整行填满后消除并得分。
**验收标准（AC-03）**
1. 方块按等级间隔自动下落（§5 速度表，实测误差 ≤ 50ms）。
2. 一行 10 格全满时该行立即消失，上方行整体下移 1 行。
3. 一次填满多行按实际行数一次消除（2/3/4 行均可）。
4. 消除后按 §5 计分公式加分，消除行数同步增加。
5. 方块触底（障碍/地板）后 ≤ 500ms 固定，下一方块出现。

### US-04 暂停与恢复
作为玩家，我可以在游戏进行中暂停，之后恢复。
**验收标准（AC-04）**
1. PLAYING 态按 `P`（或 `Esc`）≤ 300ms 进入暂停态，显示「已暂停」遮罩。
2. 暂停期间方块不自动下落，除恢复键外所有按键不改变游戏状态。
3. PAUSED 态按 `P`（或 `Esc`）恢复，方块位置、分数、等级与暂停前完全一致。
4. 页面失去焦点时自动暂停；恢复焦点不自动恢复（需手动恢复或明确提示）。

### US-05 游戏结束与重新开始
作为玩家，方块堆到顶部时游戏结束，我可以重新开始。
**验收标准（AC-05）**
1. 新方块无法完整放入顶部出生区 → 结束态，显示「游戏结束」遮罩与最终分数。
2. 结束态方块停止运动，方向键不再产生效果。
3. 点击「重新开始」/按 `R` ≤ 300ms 重置：分数 0、等级 1、消除行数 0、棋盘清空、可立即游玩。
4. 连续 5 次「结束 → 重新开始」循环无报错、无状态残留。

### US-06 计分与升级
作为玩家，我能实时看到分数、等级、消除行数，且难度随等级提升。
**验收标准（AC-06）**
1. 信息面板实时显示分数、等级、消除行数、下一方块预览，刷新 ≤ 200ms。
2. 累计消除 10 行升 1 级（第 10 行 → L2；第 20 行 → L3）。
3. 升级瞬间下落间隔按 §5 速度表缩短（新旧间隔差值 ≤ 10ms）。
4. 升级时有可见反馈（LEVEL UP 提示，显示 800ms ± 200ms）。
5. 计分公式（§5）用自动化脚本对 1/2/3/4 行消除分别验证，与公式 100% 一致（AC-14 起仅消行计分）。

### US-07 视觉风格
作为玩家，我感受到统一的科技玻璃风格。
**验收标准（AC-07）**
1. 页面背景深色（背景主色亮度 ≤ 15%）。
2. 游戏板与信息面板毛玻璃：`backdrop-filter: blur()` 生效。
3. 当前/已固定方块、边框/按钮呈现 ≥ 1 种霓虹光效（`box-shadow`/`text-shadow`）。
4. 信息面板与游戏板在 1920×1080、1366×768 无错位、无遮挡。
5. 网格线可见，7 种方块色相可区分。

### US-08 自包含与离线
作为玩家，我在无网络环境下双击文件即可游玩。
**验收标准（AC-08）**
1. 仅由 `index.html`（内联）或 `index.html + 本地 css/js` 组成，无任何 `http(s)://` 外部引用。
2. DevTools Network 面板显示 0 个请求。
3. 断网（Offline）状态完整游玩一轮，功能与联网一致。
4. Chrome/Edge/Firefox 最新版双击均可正常游玩。

### US-09 游戏音效（v2.0）
作为玩家，我在操作与关键事件发生时听到即时、可区分的合成音效，且不依赖任何外部音频文件。
**验收标准（AC-09）**
1. 七类事件各有独立音效（移动/旋转/软降/硬降/消行/升级/结束），任意两类可区分。
2. 每个事件触发且仅触发一次对应音效；单次消行（含 2/3/4 行）= 1 次，不叠加；进入 GAME_OVER = 1 次。
3. 音效仅在操作成功时触发：被边界/障碍拒绝的移动/旋转不触发。
4. 触发时机与事件同步（消行同刻、升级同 `LEVEL UP`、结束同遮罩、硬降落底固定时）。
5. Web Audio API 实时合成：无任何音频文件，Network 0 个音频请求，零外部音频依赖。
6. 自动播放：首次用户交互前不发声且 Console 0 报错；首次交互后 AudioContext 激活。
7. 降级：浏览器不支持/未激活 Web Audio 时，玩法、计分、键盘 100% 正常、Console 0 报错，仅无声。
8. 性能：操作仍 ≤ 100ms；60s 高频操作后无报错、无音频节点泄漏、FPS ≥ 55。

### US-10 音量控制与静音（v2.0）
作为玩家，我可以随时调整音量或静音，控制方式与界面遵循既有风格。
**验收标准（AC-10）**
1. 信息面板音量控件复用既有 token；1920×1080 / 1366×768 无错位、无遮挡。
2. `M` 键任意游戏态切换静音；图标/文案与 `aria-pressed` ≤ 200ms 同步。
3. 静音后所有事件无可闻输出；关闭立即恢复。
4. 音量 0–100%、默认 80%、步进 ≤ 10%，即时生效；任意音量无爆音/削波。
5. 设置跨「结束 → 重新开始」保持；刷新恢复默认（80%、静音关）。
6. 可访问性：可 Tab 聚焦、`:focus-visible`、读屏可读状态、不只靠颜色。

### US-11 暂停/继续快捷键（v2.1）
作为玩家，我希望暂停与继续都能通过快捷键完成（`P` 双向切换、`空格` 从暂停恢复），且界面视觉与 v2.0 完全一致。
**验收标准（AC-11）**
1. PLAYING 态按 `P` ≤ 300ms 进入 PAUSED；PAUSED 态按 `P` 恢复，状态与暂停前完全一致。
2. PAUSED 态按 `空格` ≤ 300ms 恢复；PLAYING 态按 `空格` 仍执行硬降（立即落底固定 + 硬降音效），**v2.3 起不加分**（仅消行计分）。
3. `空格` 仅在 PAUSED 态承担「继续」：恢复瞬间不触发硬降、不改变状态；连续按 ≥ 3 次不报错。
4. 恢复后首个自动下落间隔与等级表一致（偏差 ≤ 50ms）。
5. 快捷键不依赖焦点位置（window 级 keydown）。
6. READY/GAME_OVER 态按 `P` 无副作用；GAME_OVER 态按 `空格` 保持「重新开始」语义。
7. 零视觉改动（v2.1 基线，幽灵块属 v2.2 变更，见 AC-12）。

### US-12 幽灵块（落点预览）（v2.2 新增）
作为玩家，我希望在当前下落方块正下方看到其垂直落点预览（半透明轮廓），并随移动/旋转/软降实时刷新。
**验收标准（AC-12）**
1. **落点位置正确**（幽灵块开关开启时）：幽灵块落点 = 当前方块沿 y 轴纯垂直下落、首次与已固定方块/地板碰撞前一刻的最大深度，与硬降实际固定位置偏差 0 格；开关关闭时不显示、无需计算。
2. **随左右移动实时刷新**：移动成功后同帧重算重绘（≤ 100ms），垂直投影随列正确（含侧边界限制）。
3. **随旋转实时刷新**：旋转成功后按新 `rot` 轮廓重算（≤ 100ms）。
4. **随软降/自动下落实时刷新**：软降/重力步后同步上移（≤ 100ms）。
5. **遮挡/边界语义一致**：复用于 `collides`/硬降一致，落在掩体上一格、不穿越、贴边不越界；**无踢墙**。
6. **不参与逻辑**：纯显示，不参与碰撞/消行/计分/固定，对玩法逻辑零影响。
7. **不改变既有接口行为**：不改数值/状态机/`keyAction`/音效；变更面 = 新增 `ghostY` 纯函数 + 渲染层（`collides` 实现不改）。
8. **渲染可辨识**：半透明轮廓（同色系、暗色玻璃基调可辨识，透明度/线宽可编程测量）；不响应输入、不遮挡关键信息，双分辨率无错位。
9. **状态覆盖**：PLAYING 实时可见；PAUSED 冻结；READY/GAME_OVER 不显示。
10. **性能**：移动/旋转/软降后刷新 ≤ 100ms、含幽灵渲染 FPS ≥ 55。
11. **人工补测（v2.2 新增，环境限制非缺陷）**：真机可辨识度、旋转后复杂形状（I/S/Z）落点、双分辨率目测、相邻块体边界等归人工补测清单。
12. **（v2.4 追加·引擎健壮性，AC-12.12）** `ghostY(board, piece)` 对非法/越界入参防御、**不抛错**且返回类型安全值：`rot` 用 `%4` 归一并负数归一到 0–3（等价 `((v%4)+4)%4`）；未知 `type` 回退原样（不抛错）；`piece === null` 防御返回安全默认（类型安全 `number`）。已知用例：`rot = -1 / 4 / 5 / 100`、未知 `type`、`piece === null`。**合法性路径零行为变化**：唯一调用方 ui.js 守卫合法 piece，防御分支不改合法落点（回归 AC-12.1~12.11）。

### US-13 幽灵块辅助开关（v2.3 新增）
作为玩家，我可以通过开关控制幽灵块显示/隐藏，以便根据个人喜好调整界面复杂度。
**验收标准（AC-13）**
1. **开关位置与样式**：左侧信息面板新增科技玻璃风开关控件，位于合适位置，不遮挡现有信息。
2. **开关状态与渲染联动**：开启（默认）时幽灵块正常显示；关闭时不再渲染（任一状态），棋盘/记分/硬度/音效不受影响。
3. **回合中切换即时生效**：PLAYING 态切换后幽灵块下一帧（≤100ms）显示/隐藏，不影响逻辑。
4. **状态保持**：「结束 → 重新开始」间保持；刷新恢复默认（开启）。可选 P2 持久化。
5. **可访问性**：可 Tab 聚焦、`:focus-visible`、读屏可读状态（`aria-label` + `aria-pressed`）、不只靠颜色。

### US-14 修正计分规则（v2.3 新增）
作为玩家，我希望硬降（空格）不额外加分，仅消行时获得分数。
**验收标准（AC-14）**
1. **硬降不加分**：PLAYING 态按 `空格` 硬降（立即落底 + 硬降音效），不增加分数；硬降前后分数差 = 0（自动化断言）。
2. **消行计分不变**：计分公式保持 §5（1/2/3/4 行 = 100/300/500/800 × 等级）；软降不加分。
3. **回归底线**：AC-01 ~ AC-12 全绿（除 AC-14 明确改变的硬降加分断言外）；状态机/快捷键/音效零改动。

### US-15 背景音乐（BGM）（v2.5 新增）
作为玩家，我可以在信息面板通过开关开启/关闭一段实时合成的循环背景音乐，营造更有氛围的游戏体验，而不依赖任何外部音频文件。
**验收标准（AC-15）**
1. **开关位置与样式**：左侧信息面板新增科技玻璃风 **BGM 开关**控件（复用既有 token，同 AC-13 幽灵块开关样式族），位于不遮挡现有信息的位置；1920×1080 / 1366×768 无错位、无遮挡。
2. **默认关闭**：页面加载后 BGM 关闭、不发声，不触发自动播放违规（首次用户交互前 AudioContext 不硬启，Console 0 报错）。
3. **开启播放**：首次用户交互后切换 BGM 开关为 ON，≤ 500ms 开始可闻的循环旋律；旋律为 Web Audio 实时合成（振荡器 + 包络），**零外部音频文件**。
4. **关闭停止**：切换 BGM 开关为 OFF，≤ 300ms 停止，无残留长音/拖尾（已调度节点释放干净）。
5. **循环连续**：BGM 开启后连续播放 ≥ 60s 无卡顿、无无声空窗（lookahead 调度器保证连续非空调度窗口）。
6. **零音频文件**：不经由任何外部或本地音频资源文件——Network 面板 0 个音频请求；源码无 `.mp3/.wav/.ogg/.m4a` 引用（assembly-check AC-09.5 审计全绿）。
7. **自包含**：不新增任何 `http(s)://` 外部引用；AC-08 自包含审计全绿。
8. **音量联动**：BGM 音量跟随主音量设置（0–100%）；主音量调至 0% → BGM 无声；调回 → 恢复（无需重新 unlock）。
9. **静音联动**：`M` 键或面板静音按钮切换后，BGM 随所有声音立即静音（≤ 200ms 同步）；取消静音立即恢复，无需重新用户交互。
10. **自动播放合规**：首次用户交互前无论开关状态 BGM 均不发声；AudioContext 未激活时开启操作不抛错（等待/降级处理），Console 0 报错。
11. **降级**：浏览器不支持/未激活 Web Audio 时，BGM 开关为禁用态或保持无声，玩法、计分、键盘 100% 正常、Console 0 报错。
12. **性能**：BGM 开启 + 高频操作 60s 后 FPS ≥ 55、振荡器/增益节点计数有界（无泄漏）、Console 0 报错。
13. **状态保持**：BGM 开关跨「结束 → 重新开始」保持；刷新恢复默认（关闭）。可选 P2 本地持久化。
14. **可访问性**：可 Tab 聚焦、`:focus-visible`、读屏可读状态（`aria-label` + `aria-pressed`）、不只靠颜色。

> 注：AC-15 与既有 AC-09/AC-10 的关系——SFX 七类事件音效（AC-09）与音量/静音（AC-10）语义全部保留不变；BGM 是**叠加的独立播放层**，与音效引擎共享 AudioContext 与主增益，但**不改变**任何 SFX 触发/并发/声像语义。

## 4. 交互流程概述

```
[待开始 READY] --点击"开始"/回车--> [进行中 PLAYING]
[进行中] --按 P/Esc/失焦--> [暂停 PAUSED]
[暂停] --按 P/Esc/空格--> [进行中]
[进行中] --方块堆顶--> [结束 GAME_OVER] --点击"重新开始"/按 R/空格--> [待开始或直接进行中]
```

- **READY**：展示游戏板、开始按钮、空面板；方块不活动；不显示幽灵块；BGM 开关可见但默认关闭。
- **PLAYING**：自动下落循环，键盘操作生效；当前方块正下方实时显示幽灵块（开关开启时）；`空格` = 硬降（v2.3 起不加分）；BGM 按开关 ON 时循环播放、OFF 时停止。
- **PAUSED**：下落定时器停止；显示遮罩；幽灵块原地冻结；恢复键（`P`/`Esc`/`空格`）生效；**BGM 状态独立于游戏态**——开关 ON 时 BGM 暂停态继续播放（氛围层与玩法态解耦，不随 PAUSED 冻结）。
- **GAME_OVER**：所有方块停止；显示最终分数；不显示幽灵块；BGM 按开关状态保持（ON 继续/ OFF 停止），跨「结束→重新开始」保持。

**v2.5 变更（交互层面）**：
1. 信息面板新增 **BGM 开关**（默认关闭、可访问），用户可随时开启/关闭背景音乐。
2. BGM 为**独立氛围层**：开关 ON 后跨 READY/PLAYING/PAUSED/GAME_OVER 全态持续循环，仅在用户关闭开关或静音时静默；开关与音量/静音（AC-10）联动。
3. 首次用户交互前 BGM 不发声；开启操作在 AudioContext 未激活时等待/降级，不报错。
4. 除上述外，玩法、计分、布局、SFX、幽灵块交互与 v2.4 完全一致。

页面布局（自上而下/自左而右）：顶部标题 → 中部（左：信息面板：分数/等级/行数/下一个方块/音量控件/幽灵块开关/**BGM 开关**）→ 中：游戏板（叠加半透明幽灵块，开关控制显隐）→ 右/下：操作说明与控制按钮。所有面板毛玻璃卡片、霓虹描边。

## 7. 依赖与风险

### 7.1 依赖
- **运行时**：现代浏览器（Chrome/Edge ≥ 90、Firefox ≥ 95、Safari ≥ 15），依赖 `backdrop-filter`、`requestAnimationFrame`、ES6、Web Audio API（`AudioContext`、`OscillatorNode`、`GainNode`）。
- **音效引擎 `audio.js`**：BGM 复用其 `AudioContext`/`unlock`/主增益/`dispose` 基础设施（AC-10/AC-09）；二次开发须保持 `window.TetrisAudio` 既有方法语义不变（AC-09/AC-10 兼容）。
- **零外部依赖**：不引入任何 CDN/字体/图片/音频文件；BGM 纯实时合成。

### 7.2 风险与缓解
| 风险 | 影响 | 缓解 |
|---|---|---|
| 老浏览器不支持 `backdrop-filter` | 毛玻璃失效 | 半透明背景色兜底，核心玩法不受影响 |
| `file://` 下模块加载受限 | 游戏无法运行 | 代码内联于单个 `index.html`，禁用模块加载 |
| 页面失焦导致定时器漂移/堆叠 | 下落节奏错乱 | `performance.now()` 差值计时 + 失焦自动暂停（**不影响 BGM lookahead 调度，其独立于游戏定时器**） |
| 键盘焦点丢失 | 操作失灵 | 全局 `keydown` 监听于 `window` 或回焦游戏容器 |
| 帧率不足 | 体验卡顿 | 逻辑与渲染分离，目标 ≥ 55 FPS；BGM 由音频线程/独立定时器调度，不占主线程渲染帧 |
| 自动播放策略阻止 AudioContext | 无声/报错 | 首次用户交互创建并 resume（与 SFX 同一 unlock）；BGM 默认关闭、开关 ON 也仅在激活后才发声；失败无声降级 0 报错 |
| BGM 调度器与 SFX 并发/泄漏 | 爆音/卡顿/内存增 | lookahead 前瞻窗口有限（≤ 数百 ms）、节点用后释放、`dispose()` 统一清理；并发/节点计数有界（AC-15.12） |
| BGM 破坏 AC-08 自包含 / AC-09.5 零音频文件 | 验收失败 | 全程零外部引用、零音频资源文件；assembly-check 双审计全绿（AC-15.6/15.7） |
| BGM 静音/音量联动失效 | 静音后仍有 BGM 声 | BGM 走同一主增益且 `muted` 短路/置 0（同 AC-10.3 双保险）；联动断言（AC-15.8/15.9） |
| 回归破坏既有 SFX/状态机 | AC-09/AC-10/AC-01~14 红 | 变更面收敛于 `audio.js` 新增 BGM 播放层 + `window.TetrisAudio` 导出面扩展；SFX 触发/并发/声像语义零改动；回归底线全绿 |
