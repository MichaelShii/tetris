# PRD — r28 横屏双轨十字布局（landscape-dual-track）

## 1. 背景与目标

**背景**：用户反馈 + 自查定位——横屏在宽屏（≥600px）下显示为底部一排行式底栏（硬降 左 右 软降 Hold 旋转），而非预期的左右双轨布局（左轨=十字方向键 上=软降/左/右/下=硬降/中心✛ + 右轨=Hold/旋转，且硬降应放下面）。自查根因：

- (a) `style.css` 横屏侧轨门控 `@media (orientation: landscape) and (max-width: 599px)`（r26 裁定 AC-3「M/L 横屏恒行式底栏」/R-D1）把 ≥600px 宽横屏挡在侧轨之外，落入 M/L 行式底栏；
- (b) r27 行式栏 order 规则把键序冻结为「硬降在上」，与竖屏 r27 互换后（硬降在下）不一致。

**目标**：横屏触控布局回归双轨十字预期——横屏（has-touch、任意宽度）恒走左右双轨：左轨十字（上=软降/左/右/下=硬降/中心✛）、右轨 Hold+旋转；横屏双轨十字键位与竖屏一致（硬降在下、软降在上）。竖屏 M/L 行式底栏保持现状，桌面零变化，红线零 diff。

## 2. 用户故事与验收标准

**US-1（触屏横屏用户）**：横屏游玩时（无论宽窄屏），底部显示左右双轨——左轨十字方向键（上=软降、下=硬降、左/右=横移、中心✛装饰）、右轨 Hold+旋转；硬降在下、软降在上，与竖屏键位语义一致，不再出现一排行式底栏。

- **AC-1（P0）横屏恒双轨、取代行式**：has-touch 设备横屏（orientation: landscape，任意宽度，含 ≥600px 宽屏）恒走左右双轨十字布局；移除或放宽 `style.css` 横屏侧轨 `@media (orientation: landscape) and (max-width: 599px)` 宽度门控（r26 AC-3/R-D1 裁定），≥600px 横屏不再落入基座行式底栏；横屏双轨十字键位与竖屏 r27 互换后一致（硬降在下、软降在上）。取代 r26#AC-3。
- **AC-2（P0）契约与回放器零逻辑改动**：横屏双轨复用既有侧轨结构（左轨十字簇 + 右轨 Hold/旋转），`.tkey[data-action] ↔ TOUCH_KEYS` 六值映射契约零变化；ui.js TOUCH_KEYS 表与触控=键盘回放器路径 0 逻辑改动（含 r27 互换语义：上=softDrop、下=hardDrop）。
- **AC-3（P0）竖屏 M/L 行式底栏保持现状**：portrait ≥600px 竖屏仍为底部一行六键底栏（硬降 左 右 软降 Hold 旋转，一排、恒玻璃），键序沿用 r27 冻结语义（硬降在下），不随本需求变化；竖屏 S dock（<600px）亦零变化。
- **AC-4（P0）桌面/键鼠视觉零变化**：非 has-touch（键鼠/桌面）设备视觉/键位/布局 0 变化（触控操作区不显示，同 r16/r21 既有行为）；键盘操作路径零变化。
- **AC-5（P0）红线 0 diff**：game.js/audio.js 0 diff；VERSION 三模块一致且不动；persist.js 0 diff；交互/按压态（:active 三态）/safe-area 避让/多指守卫全部承继。
- **AC-6（P0）七套脚本全绿出口**：verify-ui 中 r26/r27 登记的横屏侧轨门控与行式底栏判定断言改写（横屏分支改为恒双轨判定，取代 r26#AC-3 相关断言）+ 新增 §r28 段；qa-e2e 追加 §r28 横屏双轨布局断言（双轨存在、键位映射、≥600px 横屏不落行式栏）；verify-game/verify-audio/verify-ui/verify-constants/persist/assembly/qa-e2e 七套全绿，r24/r26/r27 既有断言零回归。
- **AC-7（P1）人工补测清单更新**：新增真机横屏双轨手感（含 ≥600px 宽屏横屏实机）、横竖屏切换态、竖屏 M/L 行式栏回归、读屏语义、safe-area/多指/FPS，留产品验收。

**优先级**：P0×6（AC-1~AC-6）、P1×1（AC-7）。

## 3. 范围与非目标

**范围**：
- `style.css`：横屏侧轨宽度门控移除/放宽（侧轨规则作用于全部横屏宽度）。
- `verify-ui.cjs` / `qa-e2e-jsdom.cjs`：横屏布局相关断言改写与 §r28 段登记。
- 交付物：PRD/TECHNICAL/QA-REPORT/ACCEPTANCE 入本任务夹；main 工作区仅任务夹一并提交。

**非目标**：
- 不改 TOUCH_KEYS 六值映射、不改触控=键盘回放器逻辑、不改 `ui.js` 触控绑定逻辑（布局仅 CSS 层）。
- 不改竖屏布局：S dock 键序/尺寸、M/L 行式底栏、恒玻璃视觉。
- 不改桌面非触控 UI 与键盘操作。
- 不改 game.js/audio.js 数值与 VERSION。
- 不新增构建/依赖；不调整 S/M/L 断点三档划分本身。
- 不处理 r17/r19 遗留 D 项（M 档溢出、S 横屏溢出等，本需求范围外）。

## 4. 交互流程摘要

- **横屏（has-touch，任意宽度）**：棋盘居中，底部左右双轨——左轨十字（上=软降/左=左移/右=右移/下=硬降/中心✛装饰）、右轨 Hold+旋转；键位语义与竖屏 r27 互换后一致（硬降在下、软降在上）。
- **竖屏 S（<600px）**：单行 dock 双簇，现状不动。
- **竖屏 M/L（≥600px）**：底部一行六键行式底栏（恒玻璃、键序 r27 冻结语义），现状不动。
- **桌面（非 has-touch）**：无触控操作区，键盘操作，视觉零变化。

## 5. 依赖与风险

- **依赖**：r27 交付的互换语义与行式栏 order 冻结规则；r26 的侧轨结构、dock/skin 规则（恒玻璃、z-index 遮键修复）；r16/r21 的 has-touch 门控。
- **风险 1（横屏折叠点）**：移除 599px 门控后横屏恒侧轨——窄横屏（如 568×320）沿用既有侧轨规则（r26 即 <600px 横屏在用），冲突风险低；verify-ui 门控断言需同步替换，防止旧断言误判。
- **风险 2（视觉序与 DOM 源序分叉）**：横屏双轨不再受行式栏 order 影响，行式 order 仅服务竖屏 M/L；DOM 源序与双轨视觉序分叉（r27 D-5 同族）为接受项而非缺陷，QA 阶段注明。
- **风险 3（E2E 断点模拟）**：qa-e2e 新增横屏双轨用例受 jsdom 视口模拟限制，以 computed/style 断言与真实断点注册为准。
