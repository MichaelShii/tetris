# PRD — r29 横屏双轨与三列内容共存（landscape-dual-track-no-overlap）

## 1. 背景与目标

**背景**：r28 让横屏（has-touch、任意宽度）恒走左右双轨十字，但仅把 `style.css` 横屏侧轨门控从 `@media (orientation: landscape) and (max-width: 599px)` 放宽为 `@media (orientation: landscape)`。侧轨 `.touchpad` 是 `position:fixed` 悬浮层（style.css:1028）：宽屏 M/L 横屏下 `#main` 为「左面板|棋盘|右面板」三列布局（600–767px `minmax(0,1fr) 340px`、768–1023px `minmax(180px,1fr) 340px minmax(180px,1fr)`），fixed 双轨（左轨 ≈212px / 右轨 ≈104px）左右两端贴边、内容未让位，于是直接叠压在三列两侧的信息面板与系统按钮之上（用户实机截图：左轨十字叠压左侧分数/最高分/等级/消除行数面板、右轨 Hold/旋转叠压右侧「开始游戏/暂停/重新开始」按钮）。QA 此前仅在无浏览器沙箱下跑脚本断言，判定「双轨存在、不落行式栏」即通过，未捕获此叠压（r28 接受项 E1 已把同类板底预留差列为真机观测项，但未阻断）。

**目标**：横屏（has-touch、任意宽度）保持左右双轨十字布局，但与三列内容共存——横屏触控下 `#main` 内容左右各让出双轨宽度（左轨 ≈212px、右轨 ≈104px + safe-area-inset），使双轨贴靠屏幕左右边缘、内容（左右信息面板与棋盘）居中不被遮挡；或采用等价方案使双轨不悬浮、不叠压内容。竖屏、窄屏 S 横屏、桌面零回归；契约/回放器/红线零变化；若环境允许新增真实浏览器视觉/布局检查以捕获此类叠压。

## 2. 用户故事与验收标准

**US-1（宽屏横屏触屏用户）**：M/L（≥600px）横屏游玩时，左右双轨十字布局保持，且左轨不再叠压左侧信息面板、右轨不再叠压右侧系统按钮——内容（信息面板与棋盘）居中可见，双轨贴靠屏幕左右边缘。

- **AC-1（P0）横屏恒双轨且内容让位不叠压**：has-touch 设备横屏（orientation: landscape、任意宽度，含 ≥600px 宽屏）恒走左右双轨十字布局（左轨=上软降/左/右/下硬降/中心✛、右轨=Hold+旋转，硬降在下，键位与竖屏 r27 互换后一致），基线 r28#AC-1 不得回归；同时 M/L（≥600px）横屏下 `#main` 内容左右各让出双轨宽度（左轨 ≈212px、右轨 ≈104px，各加 safe-area-inset），使双轨贴靠屏幕左右边缘、内容居中——左轨不叠压左侧信息面板（分数/最高分/等级/消除行数）、右轨不叠压右侧「开始游戏/暂停/重新开始」按钮。取代 r28#AC-1 中「纯门控放宽、内容不让位」导致的叠压行为。
- **AC-2（P0）真实浏览器视觉/布局检查补测叠压**：若环境允许，新增真实浏览器视觉/布局检查（截屏/几何探测）以捕获此类叠压（此前 QA 仅在无浏览器沙箱下跑脚本断言导致叠压漏检）；验收判据 = 在 M/L（≥600px，如 768×400/1024×600 横屏视口）真实浏览器下渲染，双轨与信息面板/按钮无盒体重叠（几何不相交或 overlap 面积为 0），内容居中可见；若环境不允许真实浏览器，则以「等价的布局几何断言 + 与实机截图人工比对」替代，并留人工补测。此为 r28 漏检的针对性补强（见 §5 依赖与风险）。
- **AC-3（P0）窄屏手机横屏（S <600px）视觉保持**：横屏 <600px（如 568×320）沿用既有横屏变体（单列卡片流/面板 flex 复位），双轨与内容布局视觉与 r26/r28 一致、零变化——窄屏无左右面板冲突，不引入内容让位。
- **AC-4（P0）竖屏零回归**：S（<600px）竖屏 dock（r24 双簇）与 M/L（≥600px）竖屏行式底栏（六键一排、恒玻璃、键序沿用 r27 冻结语义：硬降在下）零变化；不随本需求改竖屏布局。
- **AC-5（P0）桌面/键鼠（非 has-touch）视觉零变化**：非 has-touch（键鼠/桌面）设备视觉/键位/布局 0 变化（触控操作区不显示，同 r16/r21 既有行为）；键盘操作路径零变化。
- **AC-6（P0）契约与回放器零逻辑改动**：`.tkey[data-action]` ↔ `TOUCH_KEYS` 六值映射契约零变化（软降/横移/硬降/Hold/旋转）；ui.js `TOUCH_KEYS` 表与触控=键盘回放器路径 0 逻辑改动（r27 互换语义：上=softDrop、下=hardDrop）；横屏双轨键位映射不变（上软降/下硬降、左右横移、中心✛装饰、右轨 Hold/旋转）。
- **AC-7（P0）红线 0 diff + VERSION 不动**：game.js/audio.js 0 diff；persist.js 0 diff；VERSION 三模块一致且不动；交互/按压态（:active 三态）/safe-area 避让/多指守卫全部承继。
- **AC-8（P0）七套脚本全绿零回归**：verify-ui/qa-e2e 同步更新（横屏 M/L 内容让位断言 + 与 r28 双轨断言衔接，r28 §r28 段断言承接；「双轨存在/不落行式栏」既有断言保留）；r24/r26/r27/r28 既有断言零回归；verify-game/audio/ui/constants/persist/assembly/qa-e2e 七套全绿。
- **AC-9（P1）人工补测清单更新**：新增 M/L 宽屏横屏实机（叠压消失/内容居中/信息面板与按钮不被遮挡）、横竖屏切换态、窄屏 S 横屏回归、竖屏行式栏回归、读屏语义、safe-area/多指/FPS、横屏双轨手感，留产品验收。

**优先级**：P0×8（AC-1~AC-8）、P1×1（AC-9）。

## 3. 范围与非目标

**范围**：
- `style.css`：横屏（§5.5 门控块）双轨「不悬浮叠压」处理——等价为①横屏触控下 `#main` 内容左右各让出双轨宽度（左 ≈212px、右 ≈104px + safe-area-inset），或②使双轨与内容布局不叠压的等价方案；门控仍为裸 `@media (orientation: landscape)`（r28 定稿不倒退）。
- `verify-ui.cjs` / `qa-e2e-jsdom.cjs`：横屏 M/L 内容让位/不叠压断言改写与 §r29 段登记；承接 r28 §r28 段断言。
- 交付物：PRD/TECHNICAL/QA-REPORT/ACCEPTANCE 入本任务夹 `docs/teamflow/20260830-r29/`；main 工作区仅任务夹一并提交。

**非目标**：
- 不改 `.tkey[data-action]` ↔ `TOUCH_KEYS` 六值映射、不改触控=键盘回放器逻辑、不改 `ui.js` 触控绑定逻辑（布局仅 CSS/验证脚本层）。
- 不改竖屏布局：S dock 键序/尺寸、M/L 行式底栏、恒玻璃视觉。
- 不改桌面非触控 UI 与键盘操作。
- 不改 game.js/audio.js 数值与 VERSION。
- 不新增构建/依赖/运行时；不调整 S/M/L 断点三档划分本身。
- 不处理 r17/r19 既有遗留 D 项（M 档溢出、S 横屏溢出等，本需求范围外）；本需求仅修 r28 引入的横屏双轨叠压，不扩散。

## 4. 交互流程摘要

- **横屏（has-touch，任意宽度）**：棋盘/内容居中，底部左右双轨——左轨十字（上=软降/左=左移/右=右移/下=硬降/中心✛装饰）、右轨 Hold+旋转；键位语义与竖屏 r27 互换后一致（硬降在下、软降在上）。M/L（≥600px）下内容左右各让出双轨宽度，双轨贴边、内容不被遮挡；窄屏 S 横屏沿用既有变体（无面板冲突，不叠加让位）。
- **竖屏 S（<600px）**：单行 dock 双簇，现状不动。
- **竖屏 M/L（≥600px）**：底部一行六键行式底栏（恒玻璃、键序 r27 冻结语义），现状不动。
- **桌面（非 has-touch）**：无触控操作区，键盘操作，视觉零变化。

## 5. 依赖与风险

- **依赖**：r28 交付的横屏恒双轨门控（裸 `@media (orientation: landscape)`）、双轨结构/皮肤/键位、`#main` 三列 M/L 栅格、r27 互换语义与行式栏 order 冻结、r26 侧轨结构/dock/skin（恒玻璃、z-index 遮键修复）、r16/r21 has-touch 门控。
- **风险 1（方案耦合三列几何）**：内容让位方案与 M/L `#main` 三列栅格、`--dock-h` 板底预留强耦合。600–767px（两列 `minmax(0,1fr) 340px`）与 768–1023px（三列）让位需各自核算，避免让位后内容窄于可用区或引入横向滚动；必须同时在真实/近似真实浏览器几何探测 + 真机人工比对兜底。
- **风险 2（与 r28 门控/断点断言互扰）**：r28 §r28 段与 r26/r27 既有断言对「横屏双轨存在、不落行式栏」的判定不得因内容让位改动误报；verify-ui 门控断言需保持裸 landscape（不倒退 `max-width`）。
- **风险 3（环境无真实浏览器）**：若环境仍无浏览器，AC-2 的视觉/几何探测退化为「布局几何断言 + 实机截图人工比对」；需在 §r29 段明示「几何不相交」断言与人工补测交接，防止叠压再次漏检。
- **风险 4（非目标边界）**：内容让位若波及竖屏或窄屏 S 横屏，须立即收口——仅横屏 ≥600px 分支产生让位，其余分支零变化（verify-ui 源码断言 + 竖屏/S 快照对照兜底）。
