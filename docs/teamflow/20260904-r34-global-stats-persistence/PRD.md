# PRD r34 — 全局统计持久化（统计面板升级为「本局 + 全局」）

> **基线依赖**：docs/teamflow/20260903-r32-stats-panel（统计面板基线：已放置方块数 / 消行总数 / 游戏时长三项会话指标的归零、定格、暂停不计、单计数源语义与全档位布局，均不得回归）；即时前序 docs/teamflow/20260904-r33-lock-move-reset（锁定移动保护）亦不得回归。

> 本需求为**增量扩展**，不取代任何既有 AC（无「取代」条目）；唯一的语义调整是**有意的、已与用户确认的变更**：突破 r32 非目标「跨对局统计/历史记录不入持久化」——本次为累计统计引入持久化，而 r32 定义的局内会话语义（归零/定格/暂停不计/单计数源）保持逐字不变。

## 1. 背景与目标

**背景**：r32 统计面板已提供三项**当前会话**指标（已放置方块数 / 消行总数 / 游戏时长），语义为：新局归零、OVER 定格、暂停不计、不入持久化。玩家只能看到单局数据，无法回看长期战绩（累计放了多少方块、累计消了多少行、累计玩了多久、共完成多少局）。

**目标**：把统计面板升级为「本局 + 全局」双组——新增四项**全局累计统计**（累计已放置方块数、累计消行总数、累计游戏时长、对局次数），与最高分同级持久化到 localStorage（persist.js 单键存储），中途刷新/切后台/关页不丢时长；局内状态（得分/等级/消行/本局方块数/本局时长）保持会话内存语义不变。

**已与用户确认的数据分界**：
| 层 | 字段 | 生命周期 | 持久化 |
|---|---|---|---|
| ① 局内状态（会话内存） | 本局得分、本局等级、本局消行、本局已放置方块数、本局时长 | restart / OVER 归零 | 不入持久化 |
| ② 全局持久化状态（四项 + 既有） | 累计已放置方块数、累计消行总数、累计游戏时长（毫秒整型）、对局次数；与 highScore（既有）同级 | 只增不减，随入账递增 | persist.js 单键存储，新增 saveStats 出口 |
| ③ 展示 | 统计面板分「本局 + 全局」两组 | 本局组实时更新；全局组随入账时点刷新 | — |

**时长入账口径（核心）**：OVER 定格入账 + 页面隐藏（visibilitychange→hidden）/ 卸载（pagehide/beforeunload）时补记当前局时长；暂停不计时长；中途刷新不丢（刷新前局内时长经补记通道入账全局）。

## 2. 用户故事与验收标准

- US-1 作为玩家，我希望关闭/刷新页面后再打开，累计方块数、消行数、时长、对局次数仍保留，能回看长期战绩 → AC-2、AC-6
- US-2 作为玩家，我希望面板同屏看到「本局」与「全局」两组数据，方便对比当前局与历史积累 → AC-8
- US-3 作为玩家，我希望暂停时不计时长，挂机/暂停不会虚增战绩 → AC-7
- US-4 作为玩家，我中途切走（切后台/关页）再回来，已玩过的时间不能丢 → AC-5、AC-6
- US-5 作为老玩家，升级后最高分与设置不受影响，新统计从 0 起步而非报错 → AC-3

## 3. 范围与非目标

**范围**：
- 数据面：四项全局累计字段的记数、入账、补记、持久化读写（saveStats）；局内五项字段保持既有语义（本局方块数/本局时长沿用 r32 单一计数源与计时器）。
- 展示面：统计面板分为「本局」+「全局」两组（组内字段见 AC-8），全部档位（桌面、触控竖屏行式、横屏双轨、M/L）可见。
- 断言面：verify-persist 新增 saveStats 用例；verify-game / verify-ui / qa-e2e 各追加 §r34 段（纯追加，旧期望零改动）。

**非目标**：
- 不改玩法、数值规格、计分四轴与掉落速度；不改触控=键盘回放器与 TOUCH_KEYS 契约。
- 不做跨设备/服务端同步；不做逐局历史明细（只累计不分局）；不做统计清零/导出/排行榜重排（如需另立需求）。
- 不发起任何新音效事件（onSfx 事件面 0 变化）。

## 4. 交互流程

新对局/重新开始 → 本局组五项归 0，时长开始计时（暂停停表）→ 对局中本局组实时更新（落定 +1 方块 / 消行同步 / 每秒时长，均沿 r32 既有计数源）→ **OVER 定格**：本局五项定格显示，同时一次性入账全局（对局次数 +1、累计方块/消行/时长按定格值累加），全局组刷新并持久化 → 本局未结束即隐藏/卸载：补记当前局时长入全局并持久化（幂等，只记一次）→ 重开页面：读取单键载荷，全局组恢复显示。

全程无新增可交互控件、无新设置项、无模式切换；暂停语义与既有完全一致。

## 5. 验收标准（AC）

- **AC-1（P0）局内五项会话内存边界**：本局得分、本局等级、本局消行、本局已放置方块数、本局时长为会话内存；restart（新局/重新开始）与 OVER（本局结束）均归零；五项均不写入持久化。脚本断言：既有 verify-game 快照键集与快照断言**保持不变**（不追加快照字段），r32 归零/定格用例逐字沿用全绿。

- **AC-2（P0）全局四项持久化 + saveStats 出口**：累计已放置方块数、累计消行总数、累计游戏时长（毫秒整型）、对局次数与 highScore 同存于 persist.js **单键**载荷（同一 localStorage 键、PAYLOAD_VERSION 保持 1，纯增量向后兼容扩展）；新增 `saveStats` 读写出口，与 saveHighScore/saveSettings 同级（业务侧仅经 load/save* 消费，禁止直接 setItem/getItem）。脚本断言：verify-persist 新增用例（写入→读出 roundtrip、清洗、只增不减、降级），既有 highScore/settings 用例零改动全绿。

- **AC-3（P0）旧数据兼容与降级**：升级前已存在的载荷（无 stats 字段）读取时四项按 **0** 初始化，highScore/settings 原值保留；坏 JSON/结构不符仍按既有「清键回默认」处理；localStorage 能力探测失败（降级内存 Map）时 saveStats 静默降级、绝不 throw、游戏不中断。脚本断言：模拟旧结构载荷 → 四项为 0 且 highScore 原值不变；模拟不可用存储 → saveStats 返回既定降级结果。

- **AC-4（P0）OVER 定格入账（幂等、单计数源）**：本局结束（OVER 定格帧）一次性入账——对局次数 +1、累计方块 += 本局已放置数、累计消行 += 本局消行、累计时长 += 本局时长定格值；累计方块/消行只从本局定格值累加（沿用 r32 单一计数源，禁止 UI 侧独立累计）。入账后局内五项清零并置「已入账」标记，后续重复触发（再次隐藏/卸载/OVER 帧重入）**不再叠加**。脚本断言：完成 2 局（各落子 N1/N2）→ 累计方块 = N1+N2、对局次数 = 2、时长 ≈ 两局定格之和（与墙体时钟偏差 ≤1s，沿 r32 AC-4 容差）；局内进行中刷新 1 次不增加对局次数。

- **AC-5（P0）隐藏/卸载补记（幂等）**：本局进行中（未 OVER、未暂停）发生 visibilitychange→hidden 或 pagehide/beforeunload 时，将当前局内时长并入全局累计时长并持久化；已 OVER（已入账）或暂停中的局不产生补记；同一局多次触发只补记一次（幂等标记）。脚本断言：jsdom 模拟「进行中隐藏 → 可见 → 再隐藏」→ 全局时长仅 + 一次当前局内时长。

- **AC-6（P0）中途刷新不丢**：本局未结束即刷新/关页，局内五项随会话丢失（预期行为），但刷新前已进行的局内时长必须经补记通道入账全局；重开后全局四项完整无丢失。QA 场景断言：「进行中 N 秒 → 刷新/重载」→ 全局累计时长 ≥ N（≤1s 容差）。

- **AC-7（P0）暂停不计时长**：暂停期间经过时间不计入本局时长，因此也不入账全局（入账值与补记值均不含暂停段）。脚本断言：对局跑 T 秒含一次暂停 P 秒后定格 → 本局时长与全局增量 ≈ T−P（≤1s 容差）；暂停中触发隐藏 → 补记值不含暂停段。

- **AC-8（P0）面板两组展示**：统计面板分「本局」与「全局」两组；**本局组** = 得分 / 等级 / 消行 / 已放置方块数 / 本局时长（实时，时长格式沿 r32：`mm:ss`，≥1 小时 `hh:mm:ss`）；**全局组** = 最高分（与既有 #hi-score 同源）+ 累计方块 / 累计消行 / 累计时长 / 对局次数（随入账时点刷新）。布局遵循既有横屏恒双轨（r28 轨道宽度与让位语义）/ 竖屏 S 行式底栏冻结语义，既有布局断言零回归，新字段不叠压棋盘/触控垫/系统按钮；读屏沿 r32 AC-14 机制（面板语义化 + 时长播报节流，防刷屏）。

- **AC-9（P0）引擎行为 0 变化红线**：规则引擎（tick / lockFlow / softDrop / hardDrop / T-spin 窗口 / combo / B2B 链 / 7-bag / 踢墙 / 键位响应 / 触控回放器）行为与数值规格 0 变化；onSfx 事件面（事件序列与次数）不变；audio.js 0 行；persist.js 仅**增量新增**（stats 字段 + saveStats 出口，存量结构与方法逐字不动）；VERSION 三模块（game/ui/audio=2.3.0）与 persist 模块版本、PAYLOAD_VERSION 均不动（若技术方案决定升级版本号，须三处同步修改且 verify-constants 必绿——默认不升级）。

- **AC-10（P0）七套全绿零回归**：verify-game / verify-audio / verify-ui / verify-persist / verify-constants / assembly-check / qa-e2e-jsdom 全绿；r32/r33 及更早既有断言**期望零改动**，本需求断言为**纯追加**（verify-persist §r34、verify-game §r34、verify-ui §r34、qa-e2e §r34 段）；soak（长跑）无漂移：全局时长累计误差不随风化累积（建议时间戳差值累计而非 tick 计数）。

- **AC-11（P1）人工补测清单（留产品验收）**：真机多标签/切后台补记时序（visibilitychange 双触发幂等）；移动端清后台（页面被回收）卸载补记；进行中刷新不丢；暂停不计时抽查；仅含旧 highScore 的存档升级迁移；长时间挂机时长精度；读屏朗读新增面板文本不刷屏；横屏双轨与竖屏行式两组展示不叠压。

## 7. 依赖与风险

| 风险 | 对策 |
|---|---|
| 补记双触发（visibilitychange 与 pagehide 同帧先后触发）导致重复入账 | AC-4/AC-5 幂等标记（入账后置脏/清零），jsdom 双触发用例 |

| 计时漂移（setInterval tick 计数误差累积） | 时间戳差值（Date.now）累计入账值；soak 断言（AC-10） |
| 旧存档载荷结构兼容 | PAYLOAD_VERSION 保持 1、缺省 0、saveStats 清洗；AC-3 迁移用例 |
| 面板字段增多导致布局回归（横屏 212/104px 双轨） | 先登记 r28 轨道与 r26 双轨断言，AC-8 逐组核对 |
