## 1. 背景与目标

### 1.1 背景
俄罗斯方块的旋转系统有两种常见实现：

1. **简单旋转（Simple Rotation System）**：方块绕中心旋转 90°，如果旋转后与墙壁或已固定方块碰撞，则旋转失败，方块保持原位。
2. **踢墙旋转（Wall Kick / SRS）**：方块绕中心旋转 90°，如果旋转后碰撞，则尝试将方块向左/右/上偏移 1~2 格（"踢墙偏移表"），如果偏移后不碰撞则旋转成功。

当前游戏（v2.7）的 `rotate` 函数已实现"旋转碰撞时保持原位"的行为（`game.js` 第 605 行注释："E1 无踢墙，保持原位"），但存在以下待完善项：

1. **语义不明确**：代码注释表明"无踢墙"，但 PRD 未显式声明此设计决策，后续迭代可能误引入踢墙逻辑。
2. **返回值区分不足**：旋转失败返回 `{ ok: false, reason: 'blocked' }`，与移动碰撞共用同一 reason，不利于测试断言和日志区分。
3. **边界测试缺失**：现有 `verify-game.cjs` 未专门验证"旋转碰撞时不尝试踢墙偏移"这一行为契约。

### 1.2 目标
1. **显式声明无踢墙设计**：在 PRD 和代码中明确声明"单点旋转，无踢墙"作为设计决策，防止后续迭代误引入踢墙逻辑。
2. **优化返回值语义**：旋转碰撞时返回 `{ ok: false, reason: 'wall-kick-denied' }`，与移动碰撞的 `'blocked'` 区分。
3. **补充边界测试**：在 `verify-game.cjs` 中补充旋转边界用例，验证旋转碰撞时方块位置（x/y/rot）完全不变、不尝试任何踢墙偏移。
4. **保持接口兼容**：`rotate()` 函数签名不变，`{ ok, reason }` 返回结构不变，调用方无需改动。
5. **零副作用**：不改状态机/计分/数值/音效/UI 渲染/幽灵块/BGM/7-bag 随机算法。

### 1.3 成功指标（可量化）
| 指标 | 目标值 | 测量方式 |
|---|---|---|
| 旋转碰撞保持原位 | 旋转碰撞时 x/y/rot 三项均不变 | verify-game 旋转边界用例 |
| 不尝试踢墙偏移 | 旋转碰撞时不向左/右/上偏移（x/y 不变） | verify-game 旋转边界用例 |
| 返回值区分 | 旋转碰撞返回 `reason: 'wall-kick-denied'`（非 `'blocked'`） | verify-game 旋转边界用例 |
| 回归底线 | AC-01 ~ AC-17 可自动化项 100% 全绿 | 独立复跑七套验证 |

### US-18 无踢墙旋转系统（v2.8 新增）
作为玩家，我希望旋转系统明确为"单点旋转，无踢墙"——旋转碰撞时方块保持原位，不尝试任何踢墙偏移，确保旋转行为简单可预测。

**验收标准（AC-18）**
1. **旋转碰撞保持原位**：旋转时如果碰撞（与墙壁或已固定方块），方块的 x、y、rot 三项均不变——不尝试左移、右移、上移等任何踢墙偏移。
2. **返回值语义区分**：旋转碰撞返回 `{ ok: false, reason: 'wall-kick-denied' }`（区别于移动碰撞的 `'blocked'`）。
3. **左墙旋转碰撞**：方块紧贴左墙（x 最小值）旋转时碰撞，x 不变（不右移让位）。
4. **右墙旋转碰撞**：方块紧贴右墙（x 最大值）旋转时碰撞，x 不变（不左移让位）。
5. **已固定方块旋转碰撞**：方块下方/侧方有已固定方块，旋转后与之碰撞，x/y 均不变（不尝试任何偏移）。
6. **零副作用**：不改状态机/计分/数值/音效/UI 渲染/幽灵块/BGM/7-bag 随机算法；变更面仅 `game.js` rotate 函数 reason 优化 + `verify-game.cjs` 旋转边界用例。
7. **回归底线**：AC-01 ~ AC-17 可自动化项 100% 全绿；七套验证全绿（verify-game / verify-audio / verify-ui / verify-constants / assembly-check / verify-persist / qa-e2e-jsdom）。

> 注：AC-18 与既有 AC-02（移动与旋转）的关系——AC-02 验证旋转操作可响应，AC-18 进一步验证旋转碰撞时的精确行为（不踢墙）。

## 4. 交互流程概述

```
[待开始 READY] --点击"开始"/回车--> [进行中 PLAYING]
[进行中] --按 P/Esc/失焦--> [暂停 PAUSED]
[暂停] --按 P/Esc/空格--> [进行中]
[进行中] --方块堆顶--> [结束 GAME_OVER] --点击"重新开始"/按 R/空格--> [待开始或直接进行中]
```

- **PLAYING** 旋转行为（v2.8 明确）：按 ↑/X 键旋转，如果旋转后碰撞则方块**保持原位**（x/y/rot 均不变），不尝试任何踢墙偏移。
- 除旋转碰撞行为外，玩法、计分、布局、音效、幽灵块、BGM、7-bag 随机算法与 v2.7 完全一致。

## 5. 游戏规则与数值规格（实现基准）

### 5.1 既有规格（v1.0 ~ v2.7，**v2.8 全部保持，零改动**）

| 项目 | 规格 |
|---|---|
| 游戏板 | 10 列 × 20 行 |
| 方块种类 | 7 种标准 Tetromino（I/O/T/S/Z/J/L），每方块 4 格 |
| 出生位置 | 顶部中间（列 4-5 区域），方块完全可见 |
| **旋转** | **顺时针 90°，单点旋转，无踢墙（AC-18）**：旋转碰撞时 x/y/rot 均不变，不尝试任何偏移 |
| 硬降（空格） | PLAYING 态：方块立即落底固定（**不加分**，v2.3 修正）；PAUSED 态：空格 = 继续（v2.1） |
| 计分公式 | 单次消行：1 行=100、2 行=300、3 行=500、4 行=800；乘以当前等级倍率（L 倍率 = L） |
| 升级阈值 | 累计每满 10 行升 1 级 |
| 下落速度 | 等级 L 间隔 = `max(100, 1000 × 0.85^(L-1))` ms（下限 100ms） |
| 游戏结束 | 新方块出生即与已固定方块碰撞 |
| 输入映射 | ←/→ 移动，↑/X 旋转，↓ 软降，空格 硬降（PLAYING）/ 继续（PAUSED），P 暂停/继续，Esc 暂停/继续，R 重新开始 |

### 5.2 无踢墙旋转系统规格（v2.8 本次新增）

| 项目 | 规格 |
|---|---|
| 旋转系统名称 | Simple Rotation - No Wall Kick |
| 旋转方向 | 顺时针 90°（↑/X 键）；逆时针仅用于 API（`rotated(piece, -1)`），UI 无逆时针绑定 |
| 旋转中心 | 方块自身的参考点（`piece.x`, `piece.y` 不变，仅 `rot` 变化） |
| 旋转成功 | `collides(board, next)` 为 false → `piece.rot = (rot + 1) % 4`，播放旋转音效 |
| **旋转碰撞** | `collides(board, next)` 为 true → **x/y/rot 均不变**，不尝试左/右/上偏移，返回 `{ ok: false, reason: 'wall-kick-denied' }` |
| 踢墙偏移表 | **不存在**——不维护任何偏移表，不做任何偏移尝试 |
| 确定性 | 相同 board + piece 状态下旋转结果完全确定（无随机偏移） |

### 5.3 音效/幽灵块/BGM/持久化/7-bag 规格（v2.0 ~ v2.7，**本次不改**）
