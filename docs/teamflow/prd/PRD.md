## 1. 背景与目标

### 1.1 背景
v2.3 已交付幽灵块辅助开关（AC-13）+ 修正硬降计分（AC-14）（产品验收 ⚠️ 有条件通过：可自动化项 100% 全绿、无 P0/P1/P2 缺陷）。

v2.2 幽灵块落地时，TECHNICAL §6.2 E-12-08 即描述了 `ghostY(board, piece)` 应对非法入参做防御（`rot` 用 `%4` 归一、未知 `type` 回退不抛错、`piece === null` 防御），但**当前 `game.js` 的 `ghostY` 复用 `collides`/`shapeOf`**，对 `rot > 3`、非法负 `rot` 或未知 `type` 会抛错。此为**文档-实现对齐缺口**，登记为 **OBS-12-1（P3，不阻断，非功能缺陷）**：唯一调用方 ui.js 已守卫合法 piece，不构成 P0/P1/P2 缺陷，属健壮性补齐。

### 1.2 目标
1. **`ghostY` 入参防御**：对 `rot % 4` 归一（含负数归一到 0–3）、未知 `type` 回退原样（不抛错）、`piece === null` 返回类型安全值，**均不抛错**。
2. **文档-实现对齐**：TECHNICAL §6.2 E-12-08 由「描述」校准为「已实现」，OBS-12-1 关闭。
3. **零回归**：AC-01 ~ AC-14 全部保持绿色；防御分支**不改合法路径**——唯一调用方 ui.js 传入的合法 piece 下，`ghostY` 落点结果与 v2.3 完全一致（偏差 0）。
4. **测试可追溯**：verify-game 补 E-12-08 用例（断言项数 51 → 52）。

### 1.3 成功指标（可量化）
| 指标 | 目标值 | 测量方式 |
|---|---|---|
| `ghostY` 非法入参不抛错 | `rot = -1/4/5/100/其他越界`、未知 `type`、`piece === null` 均返回类型安全值（`number`），**0 抛错** | verify-game E-12-08 用例自动化断言 |
| `ghostY` 防御后落点正确 | 非法入参防御不影响合法路径落点：合法 piece 下 `ghostY` 结果 = 硬降固定位置，偏差 0 格 | verify-game 既有 ghostY 用例回归全绿 |
| E-12-08 用例覆盖 | `rot` 负数/超界归一（含 -1/4/5/100）、未知 `type`、`piece === null` 至少各 1 例 | verify-game 断言项数 **51 → 52** |
| 回归底线 | AC-01 ~ AC-14 可自动化项 100% 全绿；verify-game/verify-audio/verify-ui/verify-constants/assembly-check/qa-e2e-jsdom 六套全绿 | 独立复跑五套 + E2E |
| 控制台报错 | 0 条（防御分支不引入新报错） | DevTools Console |

## 2. 用户故事与验收标准

> 验收标准均为可执行测试项；测试在 Chrome/Edge 最新稳定版、`file://` 直接打开 `index.html` 场景下执行。
> **（v2.4）** 既有 AC-01 ~ AC-14 保留且语义不变（表述已压缩），为本版回归底线；本次为引擎健壮性补齐（OBS-12-1 关闭），无新增玩家可见 US/AC，仅追加 AC-12.12（引擎 `ghostY` 入参防御，供 E-12-08 可测试化）并同步文档口径。

### US-01 开始游戏
作为玩家，我打开页面后可以立即开始游戏，无需任何配置。
**验收标准（AC-01）**
1. 双击 `index.html` 后 ≤ 2s 渲染完整游戏界面，无白屏。
2. 初始展示「开始」按钮与完整游戏板（10 列 × 20 行）。
3. 点击「开始」后 ≤ 300ms 进入进行态，首个方块出现并可操作。
4. 初始分数 0、等级 1、消除行数 0。

### US-02 移动与旋转方块
作为玩家，我可以用键盘控制当前方块。
**验收标准（AC-02）**
1. `←`/`→` 左右移动 1 格，按住不放以 ≥ 8 次/秒连续移动。
2. `↓` 软降 1 格，按住持续软降。
3. `↑`（或 `X`）顺时针旋转 90°。
4. 移动/旋转受边界与障碍阻挡：被拒时方块位置不变、游戏不报错。
5. 所有操作响应 ≤ 100ms（帧内即时响应）。

### US-03 自动下落与消行
作为玩家，方块自动下落，整行填满后消除并得分。
**验收标准（AC-03）**
1. 方块按等级间隔自动下落（§5 速度表，实测误差 ≤ 50ms）。
2. 一行 10 格全满时该行立即消失，上方行整体下移 1 行。
3. 一次填满多行按实际行数一次消除（2/3/4 行均可）。
4. 消除后按 §5 计分公式加分，消除行数同步增加。
5. 方块触底（障碍/地板）后 ≤ 500ms 固定，下一方块出现。

### US-04 暂停与恢复
作为玩家，我可以在游戏进行中暂停，之后恢复。
**验收标准（AC-04）**
1. PLAYING 态按 `P`（或 `Esc`）≤ 300ms 进入暂停态，显示「已暂停」遮罩。
2. 暂停期间方块不自动下落，除恢复键外所有按键不改变游戏状态。
3. PAUSED 态按 `P`（或 `Esc`）恢复，方块位置、分数、等级与暂停前完全一致。
4. 页面失去焦点时自动暂停；恢复焦点不自动恢复（需手动恢复或明确提示）。

### US-05 游戏结束与重新开始
作为玩家，方块堆到顶部时游戏结束，我可以重新开始。
**验收标准（AC-05）**
1. 新方块无法完整放入顶部出生区 → 结束态，显示「游戏结束」遮罩与最终分数。
2. 结束态方块停止运动，方向键不再产生效果。
3. 点击「重新开始」/按 `R` ≤ 300ms 重置：分数 0、等级 1、消除行数 0、棋盘清空、可立即游玩。
4. 连续 5 次「结束 → 重新开始」循环无报错、无状态残留。

### US-06 计分与升级
作为玩家，我能实时看到分数、等级、消除行数，且难度随等级提升。
**验收标准（AC-06）**
1. 信息面板实时显示分数、等级、消除行数、下一方块预览，刷新 ≤ 200ms。
2. 累计消除 10 行升 1 级（第 10 行 → L2；第 20 行 → L3）。
3. 升级瞬间下落间隔按 §5 速度表缩短（新旧间隔差值 ≤ 10ms）。
4. 升级时有可见反馈（LEVEL UP 提示，显示 800ms ± 200ms）。
5. 计分公式（§5）用自动化脚本对 1/2/3/4 行消除分别验证，与公式 100% 一致（AC-14 起仅消行计分）。

### US-07 视觉风格
作为玩家，我感受到统一的科技玻璃风格。
**验收标准（AC-07）**
1. 页面背景深色（背景主色亮度 ≤ 15%）。
2. 游戏板与信息面板毛玻璃：`backdrop-filter: blur()` 生效。
3. 当前/已固定方块、边框/按钮呈现 ≥ 1 种霓虹光效（`box-shadow`/`text-shadow`）。
4. 信息面板与游戏板在 1920×1080、1366×768 无错位、无遮挡。
5. 网格线可见，7 种方块色相可区分。

### US-08 自包含与离线
作为玩家，我在无网络环境下双击文件即可游玩。
**验收标准（AC-08）**
1. 仅由 `index.html`（内联）或 `index.html + 本地 css/js` 组成，无任何 `http(s)://` 外部引用。
2. DevTools Network 面板显示 0 个请求。
3. 断网（Offline）状态完整游玩一轮，功能与联网一致。
4. Chrome/Edge/Firefox 最新版双击均可正常游玩。

### US-09 游戏音效（v2.0）
作为玩家，我在操作与关键事件发生时听到即时、可区分的合成音效，且不依赖任何外部音频文件。
**验收标准（AC-09）**
1. 七类事件各有独立音效（移动/旋转/软降/硬降/消行/升级/结束），任意两类可区分。
2. 每个事件触发且仅触发一次对应音效；单次消行（含 2/3/4 行）= 1 次，不叠加；进入 GAME_OVER = 1 次。
3. 音效仅在操作成功时触发：被边界/障碍拒绝的移动/旋转不触发。
4. 触发时机与事件同步（消行同刻、升级同 `LEVEL UP`、结束同遮罩、硬降落底固定时）。
5. Web Audio API 实时合成：无任何音频文件，Network 0 个音频请求，零外部音频依赖。
6. 自动播放：首次用户交互前不发声且 Console 0 报错；首次交互后 AudioContext 激活。
7. 降级：浏览器不支持/未激活 Web Audio 时，玩法、计分、键盘 100% 正常、Console 0 报错，仅无声。
8. 性能：操作仍 ≤ 100ms；60s 高频操作后无报错、无音频节点泄漏、FPS ≥ 55。

### US-10 音量控制与静音（v2.0）
作为玩家，我可以随时调整音量或静音，控制方式与界面遵循既有风格。
**验收标准（AC-10）**
1. 信息面板音量控件复用既有 token；1920×1080 / 1366×768 无错位、无遮挡。
2. `M` 键任意游戏态切换静音；图标/文案与 `aria-pressed` ≤ 200ms 同步。
3. 静音后所有事件无可闻输出；关闭立即恢复。
4. 音量 0–100%、默认 80%、步进 ≤ 10%，即时生效；任意音量无爆音/削波。
5. 设置跨「结束 → 重新开始」保持；刷新恢复默认（80%、静音关）。
6. 可访问性：可 Tab 聚焦、`:focus-visible`、读屏可读状态、不只靠颜色。

### US-11 暂停/继续快捷键（v2.1）
作为玩家，我希望暂停与继续都能通过快捷键完成（`P` 双向切换、`空格` 从暂停恢复），且界面视觉与 v2.0 完全一致。
**验收标准（AC-11）**
1. PLAYING 态按 `P` ≤ 300ms 进入 PAUSED；PAUSED 态按 `P` 恢复，状态与暂停前完全一致。
2. PAUSED 态按 `空格` ≤ 300ms 恢复；PLAYING 态按 `空格` 仍执行硬降（立即落底固定 + 硬降音效），**v2.3 起不加分**（仅消行计分）。
3. `空格` 仅在 PAUSED 态承担「继续」：恢复瞬间不触发硬降、不改变状态；连续按 ≥ 3 次不报错。
4. 恢复后首个自动下落间隔与等级表一致（偏差 ≤ 50ms）。
5. 快捷键不依赖焦点位置（window 级 keydown）。
6. READY/GAME_OVER 态按 `P` 无副作用；GAME_OVER 态按 `空格` 保持「重新开始」语义。
7. 零视觉改动（v2.1 基线，幽灵块属 v2.2 变更，见 AC-12）。

### US-12 幽灵块（落点预览）（v2.2 新增）
作为玩家，我希望在当前下落方块正下方看到其垂直落点预览（半透明轮廓），并随移动/旋转/软降实时刷新。
**验收标准（AC-12）**
1. **落点位置正确**（幽灵块开关开启时）：幽灵块落点 = 当前方块沿 y 轴纯垂直下落、首次与已固定方块/地板碰撞前一刻的最大深度，与硬降实际固定位置偏差 0 格；开关关闭时不显示、无需计算。
2. **随左右移动实时刷新**：移动成功后同帧重算重绘（≤ 100ms），垂直投影随列正确（含侧边界限制）。
3. **随旋转实时刷新**：旋转成功后按新 `rot` 轮廓重算（≤ 100ms）。
4. **随软降/自动下落实时刷新**：软降/重力步后同步上移（≤ 100ms）。
5. **遮挡/边界语义一致**：复用于 `collides`/硬降一致，落在掩体上一格、不穿越、贴边不越界；**无踢墙**。
6. **不参与逻辑**：纯显示，不参与碰撞/消行/计分/固定，对玩法逻辑零影响。
7. **不改变既有接口行为**：不改数值/状态机/`keyAction`/音效；变更面 = 新增 `ghostY` 纯函数 + 渲染层（`collides` 实现不改）。
8. **渲染可辨识**：半透明轮廓（同色系、暗色玻璃基调可辨识，透明度/线宽可编程测量）；不响应输入、不遮挡关键信息，双分辨率无错位。
9. **状态覆盖**：PLAYING 实时可见；PAUSED 冻结；READY/GAME_OVER 不显示。
10. **性能**：移动/旋转/软降后刷新 ≤ 100ms、含幽灵渲染 FPS ≥ 55。
11. **人工补测（v2.2 新增，环境限制非缺陷）**：真机可辨识度、旋转后复杂形状（I/S/Z）落点、双分辨率目测、相邻块体边界等归人工补测清单。
12. **（v2.4 追加·引擎健壮性，AC-12.12）** `ghostY(board, piece)` 对非法/越界入参防御、**不抛错**且返回类型安全值：`rot` 用 `%4` 归一并负数归一到 0–3（等价 `((v%4)+4)%4`）；未知 `type` 回退原样（不抛错）；`piece === null` 防御返回安全默认（类型安全 `number`）。已知用例：`rot = -1 / 4 / 5 / 100`、未知 `type`、`piece === null`。**合法性路径零行为变化**：唯一调用方 ui.js 守卫合法 piece，防御分支不改合法落点（回归 AC-12.1~12.11）。

### US-13 幽灵块辅助开关（v2.3 新增）
作为玩家，我可以通过开关控制幽灵块显示/隐藏，以便根据个人喜好调整界面复杂度。
**验收标准（AC-13）**

2. **开关状态与渲染联动**：开启（默认）时幽灵块正常显示；关闭时不再渲染（任一状态），棋盘/记分/硬度/音效不受影响。
3. **回合中切换即时生效**：PLAYING 态切换后幽灵块下一帧（≤100ms）显示/隐藏，不影响逻辑。
4. **状态保持**：「结束 → 重新开始」间保持；刷新恢复默认（开启）。可选 P2 持久化。
5. **可访问性**：可 Tab 聚焦、`:focus-visible`、读屏可读状态（`aria-label` + `aria-pressed`）、不只靠颜色。

### US-14 修正计分规则（v2.3 新增）
作为玩家，我希望硬降（空格）不额外加分，仅消行时获得分数。
**验收标准（AC-14）**

2. **消行计分不变**：计分公式保持 §5（1/2/3/4 行 = 100/300/500/800 × 等级）；软降不加分。
3. **回归底线**：AC-01 ~ AC-12 全绿（除 AC-14 明确改变的硬降加分断言外）；状态机/快捷键/音效零改动。

## 4. 交互流程概述

```
[待开始 READY] --点击"开始"/回车--> [进行中 PLAYING]
[进行中] --按 P/Esc/失焦--> [暂停 PAUSED]
[暂停] --按 P/Esc/空格--> [进行中]
[进行中] --方块堆顶--> [结束 GAME_OVER] --点击"重新开始"/按 R/空格--> [待开始或直接进行中]
```

- **READY**：展示游戏板、开始按钮、空面板；方块不活动；不显示幽灵块。
- **PLAYING**：自动下落循环，键盘操作生效；当前方块正下方实时显示幽灵块（开关开启时）；`空格` = 硬降（v2.3 起不加分）。
- **PAUSED**：下落定时器停止；显示遮罩；幽灵块原地冻结；恢复键（`P`/`Esc`/`空格`）生效。
- **GAME_OVER**：所有方块停止；显示最终分数；不显示幽灵块。

**v2.4 变更（交互层面）**：本迭代**无玩家可见交互变化**。`ghostY` 入参防御为纯引擎内部健壮性补齐，正常游戏流程（ui.js 守卫合法 piece）输入始终合法，防御分支不可达，幽灵块渲染/位置/刷新行为与 v2.3 完全一致。

页面布局（自上而下/自左而右）：顶部标题 → 中部（左：信息面板：分数/等级/行数/下一个方块/音量控件/幽灵块开关）→ 中：游戏板（叠加半透明幽灵块，开关控制显隐）→ 右/下：操作说明与控制按钮。所有面板毛玻璃卡片、霓虹描边。

|---|---|

## 7. 依赖与风险

### 7.1 依赖
- **运行时**：现代浏览器（Chrome/Edge ≥ 90、Firefox ≥ 95、Safari ≥ 15），依赖 `backdrop-filter`、`requestAnimationFrame`、ES6。
- **引擎既有 `collides`**：`ghostY` 复用 `collides` 语义（v2.2 不改其实现）；防御仅作用于 `ghostY` 自身入参，不改变对 `collides` 的合法调用。
- **零外部依赖**：不引入任何 CDN/字体/图片/音频文件。

### 7.2 风险与缓解
| 风险 | 影响 | 缓解 |
|---|---|---|
| 老浏览器不支持 `backdrop-filter` | 毛玻璃失效 | 半透明背景色兜底，核心玩法不受影响 |
| `file://` 下模块加载受限 | 游戏无法运行 | 代码内联于单个 `index.html`，禁用模块加载 |
| 页面失焦导致定时器漂移/堆叠 | 下落节奏错乱 | `performance.now()` 差值计时 + 失焦自动暂停 |
| 键盘焦点丢失 | 操作失灵 | 全局 `keydown` 监听于 `window` 或回焦游戏容器 |
| 帧率不足 | 体验卡顿 | 逻辑与渲染分离，目标 ≥ 55 FPS |
| 自动播放策略阻止 AudioContext | 无声/报错 | 首次用户交互创建并 resume；失败无声降级 0 报错 |
| 高频操作音效堆叠/泄漏 | 爆音/卡顿/内存增 | 并发上限 ≤ 4、节点用后释放、`dispose()` 清理 |
| **`ghostY` 归一化影响合法落点（v2.4 新增）** | 幽灵块位置错误 | 归一化仅作用于非法越界的 `rot`（`%4`、负数归 0–3）；合法 `rot∈{0..3}` 下 `%4` 恒等、行为零变化；回归 AC-12.1 偏差 0 断言 + AC-01~14 全绿 |
| **未知 `type`/`null` 防御引入新异常（v2.4 新增）** | 防御分支报错 | 防御分支只返回类型安全值、不调用会抛错的路径（`type` 回退原样用于 `shapeOf` 回退、`null` 返回安全默认）；E-12-08 用例断言不抛错 |
| **文档-实现再次脱节（v2.4 新增）** | OBS 复发 | 本次以 E-12-08 为验收锚点，verify-game 补用例后 TECHNICAL §6.2 标注已实现、memory 标记关闭；后续 ghostY 改动须同步 E-12-08 |
