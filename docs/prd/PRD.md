## 1. 背景与目标

### 1.1 背景
v2.1 已交付暂停/继续快捷键（产品验收 ⚠️ 有条件通过：可自动化项 100% 全绿、无 P0/P1/P2 缺陷，人工补测清单待完成）。
本次为 **P2 增强「幽灵块（落点预览）」**迭代：在**当前下落方块正下方**，以半透明轮廓实时显示其**垂直落点预览**（跟随左右移动/旋转/软降实时刷新），帮助玩家预判落点、提升可玩性。
实现须严格保持既有行为**零回归**：不得改动既有数值（计分/等级/速度/音效参数）、状态机（READY/PLAYING/PAUSED/GAME_OVER）、快捷键映射（`keyAction`）与音效触发逻辑——幽灵块为**纯显示增强**，不参与碰撞/消行/计分。

### 1.2 目标
1. **落点可读**：玩家在任何时刻可见当前方块的垂直落点轮廓，预判固定位置。
2. **实时刷新**：幽灵块跟随左右移动、旋转、软降**同帧**刷新，位置始终与「当前方块垂直下落到底」一致。
3. **引擎纯函数**：落点计算为纯函数，复用既有 `collides` 碰撞语义（无踢墙、垂直直线下落），可 Node 单测。
4. **视觉可辨识**：半透明轮廓在深色玻璃基调下清晰可辨，同色系不破坏科技玻璃风格。
5. **零回归底线**：AC-01 ~ AC-11 全部保持绿色；数值/状态机/快捷键/音效零改动。

### 1.3 成功指标（可量化）
| 指标 | 目标值 | 测量方式 |
|---|---|---|
| 首屏可玩时间 | ≤ 500ms（本地加载） | DevTools Performance 面板 |
| 游戏运行帧率 | ≥ 55 FPS（普通 PC，Chrome/Edge） | DevTools FPS 计数 |
| 控制台报错 | 0 条（完整游玩 5 分钟，含高频操作） | DevTools Console |
| 外部网络请求 | 0 个（含 0 个音频请求） | DevTools Network 面板 |
| 断网可用 | 100% 功能可用 | 离线模式（Network → Offline）游玩验证 |
| 落点正确性（v2.2） | 自动化断言下幽灵块位置 = 当前方块垂直下落到最大非碰撞深度的位置（偏差 0 格） | verify-game 纯函数断言 |
| 刷新延迟（v2.2） | 移动/旋转/软降后幽灵块刷新 ≤ 100ms（帧内即时） | 事件→重绘采样 |

## 2. 用户故事与验收标准

> 验收标准均为可执行测试项；测试在 Chrome/Edge 最新稳定版、`file://` 直接打开 `index.html` 场景下执行。
> **（v2.2）** 既有 AC-01 ~ AC-11 保留且语义不变（表述已压缩），为本版回归底线；新增 US-12 / AC-12（幽灵块落点预览）。

### US-01 开始游戏
作为玩家，我打开页面后可以立即开始游戏，无需任何配置。
**验收标准（AC-01）**
1. 双击 `index.html` 后 ≤ 2s 渲染完整游戏界面，无白屏。
2. 初始展示「开始」按钮与完整游戏板（10 列 × 20 行，可实测）。
3. 点击「开始」后 ≤ 300ms 进入进行态，首个方块出现并可操作。
4. 初始分数 0、等级 1、消除行数 0。

### US-02 移动与旋转方块
作为玩家，我可以用键盘控制当前方块。
**验收标准（AC-02）**
1. `←`/`→` 左右移动 1 格，按住不放以 ≥ 8 次/秒连续移动。
2. `↓` 软降 1 格，按住持续软降。
3. `↑`（或 `X`）顺时针旋转 90°。
4. 移动/旋转受边界与障碍阻挡：被拒时方块位置不变、游戏不报错。
5. 所有操作响应 ≤ 100ms（帧内即时响应）。

### US-03 自动下落与消行
作为玩家，方块自动下落，整行填满后消除并得分。
**验收标准（AC-03）**
1. 方块按等级间隔自动下落（§5 速度表，实测误差 ≤ 50ms）。
2. 一行 10 格全满时该行立即消失，上方行整体下移 1 行。
3. 一次填满多行按实际行数一次消除（2/3/4 行均可）。
4. 消除后按 §5 计分公式加分，消除行数同步增加。
5. 方块触底（障碍/地板）后 ≤ 500ms 固定，下一方块出现。

### US-04 暂停与恢复
作为玩家，我可以在游戏进行中暂停，之后恢复。
**验收标准（AC-04）**
1. PLAYING 态按 `P`（或 `Esc`）≤ 300ms 进入暂停态，显示「已暂停」遮罩。
2. 暂停期间方块不自动下落，除恢复键外所有按键不改变游戏状态。
3. PAUSED 态按 `P`（或 `Esc`）恢复，方块位置、分数、等级与暂停前完全一致。
4. 页面失去焦点时自动暂停；恢复焦点不自动恢复（需手动恢复或明确提示）。

### US-05 游戏结束与重新开始
作为玩家，方块堆到顶部时游戏结束，我可以重新开始。
**验收标准（AC-05）**
1. 新方块无法完整放入顶部出生区 → 结束态，显示「游戏结束」遮罩与最终分数。
2. 结束态方块停止运动，方向键不再产生效果。
3. 点击「重新开始」/按 `R` ≤ 300ms 重置：分数 0、等级 1、消除行数 0、棋盘清空、可立即游玩。
4. 连续 5 次「结束 → 重新开始」循环无报错、无状态残留。

### US-06 计分与升级
作为玩家，我能实时看到分数、等级、消除行数，且难度随等级提升。
**验收标准（AC-06）**
1. 信息面板实时显示分数、等级、消除行数、下一方块预览，刷新 ≤ 200ms。
2. 累计消除 10 行升 1 级（第 10 行 → L2；第 20 行 → L3）。
3. 升级瞬间下落间隔按 §5 速度表缩短（新旧间隔差值 ≤ 10ms）。
4. 升级时有可见反馈（LEVEL UP 提示，显示 800ms ± 200ms）。
5. 计分公式（§5）用自动化脚本对 1/2/3/4 行消除分别验证，与公式 100% 一致。

### US-07 视觉风格
作为玩家，我感受到统一的科技玻璃风格。
**验收标准（AC-07）**
1. 页面背景深色（背景主色亮度 ≤ 15%）。
2. 游戏板与信息面板毛玻璃：`backdrop-filter: blur()` 生效。
3. 当前/已固定方块、边框/按钮呈现 ≥ 1 种霓虹光效（`box-shadow`/`text-shadow`）。
4. 信息面板与游戏板在 1920×1080、1366×768 无错位、无遮挡。
5. 网格线可见，7 种方块色相可区分。

### US-08 自包含与离线
作为玩家，我在无网络环境下双击文件即可游玩。
**验收标准（AC-08）**
1. 仅由 `index.html`（内联）或 `index.html + 本地 css/js` 组成，无任何 `http(s)://` 外部引用。
2. DevTools Network 面板显示 0 个请求。
3. 断网（Offline）状态完整游玩一轮，功能与联网一致。
4. Chrome/Edge/Firefox 最新版双击均可正常游玩。

### US-09 游戏音效（v2.0）
作为玩家，我在操作与关键事件发生时听到即时、可区分的合成音效，且不依赖任何外部音频文件。
**验收标准（AC-09）**
1. 七类事件各有独立音效（移动/旋转/软降/硬降/消行/升级/结束），任意两类可区分（基频差 ≥ 50Hz 或波形/包络参数不同）。
2. 每个事件触发且仅触发一次对应音效：单次成功移动 = 1 次；单次消行（含 2/3/4 行）= 1 次，不叠加；进入 GAME_OVER = 1 次。
3. 音效仅在操作成功时触发：被边界/障碍拒绝的移动/旋转不触发。
4. 触发时机与事件同步：消行与行消除同时；升级与 LEVEL UP 提示同时（≤ 200ms）；结束与 GAME_OVER 遮罩同时（≤ 300ms）；硬降在落底固定时触发。
5. Web Audio API 实时合成：无任何音频文件（.mp3/.wav/.ogg/.m4a）与 `<audio>`/`<source>`；Network 0 个音频请求；零外部音频依赖。
6. 自动播放：加载后、首次用户交互前不发声且 Console 0 报错；首次交互后 AudioContext 激活，此后音效正常。
7. 降级：浏览器不支持/未激活 Web Audio 时，玩法、计分、键盘 100% 正常、Console 0 报错，仅无声。
8. 性能：音效不阻塞游戏逻辑（操作仍 ≤ 100ms）；60s 高频操作后无报错、无音频节点泄漏（并发上限、超出丢弃）、FPS ≥ 55。

### US-10 音量控制与静音（v2.0）
作为玩家，我可以随时调整音量或静音，控制方式与界面遵循既有风格。
**验收标准（AC-10）**
1. 信息面板音量控件（静音按钮 + 音量调节）复用既有 token，不引入新视觉风格；1920×1080 / 1366×768 无错位、无遮挡（AC-07.4 仍成立）。
2. `M` 键在任意游戏态切换静音；按钮图标/文案与 `aria-pressed` ≤ 200ms 同步。
3. 静音后所有事件无可闻输出（增益 0 / muted 标志可编程验证 + 听测）；关闭立即恢复，无需重新激活 AudioContext。
4. 音量 0–100%、默认 80%、步进 ≤ 10%，即时生效；0% 与静音听觉等效；任意音量无爆音/削波（峰值 ≤ 1.0）。
5. 设置跨「结束 → 重新开始」保持（会话内）；刷新恢复默认（80%、静音关）。
6. 可访问性：按钮可 Tab 聚焦且有 `:focus-visible`；读屏可读出状态（`aria-label` + `aria-pressed`）；静音状态不只靠颜色表达。

### US-11 暂停/继续快捷键（v2.1）
作为玩家，我希望暂停与继续都能通过快捷键完成（`P` 双向切换、`空格` 从暂停恢复），且界面视觉与 v2.0 完全一致。
**验收标准（AC-11）**
1. PLAYING 态按 `P` ≤ 300ms 进入 PAUSED（遮罩出现）；PAUSED 态按 `P` 恢复，方块位置/分数/等级/消除行数与暂停前完全一致。
2. PAUSED 态按 `空格` ≤ 300ms 恢复 PLAYING，恢复后状态与暂停前完全一致；PLAYING 态按 `空格` 仍执行硬降（立即落底固定 + 每格 1 分 + 硬降音效），行为与 v2.0 一致（§5.1/AC-09.4）。
3. `空格` 仅在 PAUSED 态承担「继续」：恢复瞬间不触发硬降、不改变分数/等级/棋盘；暂停态连续按 `空格`（≥ 3 次）不产生报错或状态错乱。
4. 恢复后下落节拍不跳变、不叠加：恢复后首个自动下落间隔与等级表一致（实测偏差 ≤ 50ms，§5 速度表）。
5. 快捷键不依赖焦点位置：焦点位于游戏容器、信息面板按钮或页面空白处时，`P`/`空格` 均生效（window 级 keydown）。
6. READY/GAME_OVER 态按 `P` 无副作用（不改变状态、不报错）；GAME_OVER 态按 `空格` 保持既有「重新开始」语义不变。
7. 零视觉改动（v2.1 基线）：不新增/修改任何 DOM 元素、CSS 规则与图标（幽灵块除外，属 v2.2 本次变更，见 AC-12）。

### US-12 幽灵块（落点预览）（v2.2 新增）
作为玩家，我希望在当前下落方块正下方看到其垂直落点预览（半透明轮廓），并随移动/旋转/软降实时刷新，帮助预判固定位置，同时不改变任何既有操作与数值行为。
**验收标准（AC-12）**
1. **落点位置正确**：幽灵块所指示的落点 = 当前方块从当前位置（同 x、同 rot）沿 y 轴纯垂直下落、首次与已固定方块/地板碰撞前一刻所能到达的最大深度（即 `collides` 语义循环判断的最新非碰撞位置）；与「硬降实际固定位置」一致，偏差 0 格（自动化纯函数断言 + 硬降对照实测）。
2. **随左右移动实时刷新**：`←`/`→` 移动成功后，幽灵块落点在同一帧随新 x 重算并重绘（≤ 100ms），垂直投影随列变化正确（含侧边界限制）。
3. **随旋转实时刷新**：`↑`（或 `X`）旋转成功后，幽灵块按新 `rot` 的轮廓重算落点并刷新（≤ 100ms）；旋转 x 不变时垂直投影按新形状正确。
4. **随软降实时刷新**：`↓` 软降成功后幽灵块落点同步上移对应格数（≤ 100ms）；自动下落（AC-03.1）每步同样实时刷新。
5. **遮挡/边界语义一致**：幽灵块落点计算与 `collides`/硬降完全一致——遇到障碍物（上方掩体）时落在掩体之上一格，不会穿越；贴边移动后投影不越出 10 列边界。**无踢墙**：落点不因旋转产生任何侧向踢墙。
6. **不参与逻辑**：幽灵块为纯显示，不参与碰撞/消行/计分/固定判定；其存在与否对自动下落、硬降、旋转、移动、状态机行为零影响（回归 AC-02/AC-03/AC-09）。
7. **不改变既有接口行为**：本迭代不得改动既有数值（§5）、状态机（四态迁移）、快捷键映射（`keyAction` 语义）与音效触发（AC-09 全项）；以上仅新增幽灵块计算/渲染，不修改既有函数签名语义（新增纯函数 + 渲染调用，`collides` 语义复用不改）。
8. **渲染可辨识且不干预操作**：幽灵块以半透明轮廓呈现（同色系、暗色玻璃基调下可视可辨识，轮廓/填充透明度可编程测量）；幽灵块不响应输入、不遮挡现有方块/面板关键信息，1920×1080 / 1366×768 无错位。
9. **状态覆盖**：PLAYING 态幽灵块实时可见；PAUSED 态冻结（幽灵块原地静止，随恢复继续）；READY/GAME_OVER 态不显示幽灵块（无当前下落方块）。
10. **性能**：幽灵块每帧或每次状态刷新额外开销可忽略——移动/旋转/软降后刷新 ≤ 100ms、包含幽灵块渲染时 FPS ≥ 55（回归 AC-09.8 性能量级）。
11. **人工补测（v2.2 新增，环境限制非缺陷）**：真机目测确认幽灵块在暗色玻璃基调下的可辨识度（透明度/轮廓粗细/色相辨识）；旋转后复杂形状（如 I/S/Z）落点目测；1920×1080 与 1366×768 双分辨率目测无错位；与其他块体相邻时边界可辨识。以上归入人工补测清单，自动化无法替代。

## 3. 功能范围与非目标

### 3.1 功能范围
| 模块 | 说明 |
|---|---|
| 核心玩法 | 7 种标准方块（I/O/T/S/Z/J/L）、移动/旋转/软降/硬降、边界与碰撞检测、自动下落 |

| 状态管理 | 待开始 / 进行中 / 暂停 / 结束，四态完整迁移 |
| 信息面板 | 分数、等级、消除行数、下一个方块预览 |

## 4. 交互流程概述

```
[待开始 READY] --点击"开始"/回车--> [进行中 PLAYING]
[进行中] --按 P/Esc/失焦--> [暂停 PAUSED]
[暂停] --按 P/Esc/空格--> [进行中]
[进行中] --方块堆顶--> [结束 GAME_OVER] --点击"重新开始"/按 R/空格--> [待开始或直接进行中]
```

- **READY**：展示游戏板、开始按钮、空面板；方块不活动；**不显示幽灵块**（AC-12.9）。
- **PLAYING**：自动下落循环运行，键盘操作生效；当前方块正下方**实时显示幽灵块**（随移动/旋转/软降/自动下落同帧刷新，AC-12.2~12.4）；`空格` = 硬降。
- **PAUSED**：下落定时器停止；显示遮罩；**幽灵块原地冻结**（AC-12.9）；恢复键（`P`/`Esc`/`空格`）生效。
- **GAME_OVER**：所有方块停止；显示最终分数；**不显示幽灵块**（无当前下落方块，AC-12.9）。

**v2.2 新增交互**：
1. PLAYING 态当前方块正下方常显半透明**幽灵块**轮廓，指示其垂直落点。
2. 幽灵块随**左右移动、旋转、软降、自动下落**实时刷新，位置始终等于「垂直直线下落到最大非碰撞深度」（AC-12.1）。
3. 幽灵块为纯显示层：不响应输入、不参与碰撞/消行/计分/固定；状态机、快捷键、数值、音效零改动（AC-12.6/12.7）。

页面布局（自上而下/自左而右）：顶部标题 → 中部（左：信息面板：分数/等级/行数/下一个方块/音量控件）→ 中：游戏板（**叠加半透明幽灵块**）→ 右/下：操作说明与控制按钮。所有面板采用毛玻璃卡片，霓虹描边（幽灵块仅叠加于游戏板内，不改变既有布局结构）。

## 5. 游戏规则与数值规格（实现基准）

### 5.1 既有规格（v1.0/v2.0/v2.1，**v2.2 全部保持，零改动**）

| 项目 | 规格 |
|---|---|
| 游戏板 | 10 列 × 20 行 |
| 方块种类 | 7 种标准 Tetromino（I/O/T/S/Z/J/L），每方块 4 格 |
| 出生位置 | 顶部中间（列 4–5 区域），方块完全可见 |
| 旋转 | 顺时针 90°，单点旋转（无踢墙高级规则） |
| 硬降（空格） | PLAYING 态：方块立即落底固定，并按硬降格数加分（每格 +1）；PAUSED 态：空格 = 继续（v2.1），不触发硬降 |
| 计分公式 | 单次消行：1 行=100、2 行=300、3 行=500、4 行=800；乘以当前等级倍率（等级 L 倍率 = L） |
| 升级阈值 | 累计消除行数每满 10 行升 1 级（L1→L2 需 10 行，L2→L3 需 20 行，依此类推） |
| 下落速度 | 等级 L 下落间隔 = `max(100, 1000 × 0.85^(L−1))` ms（L1≈1000ms，L2≈850ms，L3≈723ms，下限 100ms） |
| 游戏结束 | 新方块出生即与已固定方块碰撞 |
| 输入映射 | ←/→ 移动，↑/X 旋转，↓ 软降，空格 硬降（PLAYING）/ 继续（PAUSED），P 暂停/继续，Esc 暂停/继续，R 重新开始 |

> **v2.2 声明**：上表数值与映射**不得改动**；本迭代仅在其上叠加幽灵块计算与渲染。

### 5.2 音效规格（v2.0/v2.1，**本次不改**）

| 项目 | 规格 |
|---|---|
| 事件集 | 移动、旋转、软降、硬降、消行、升级、游戏结束（7 类） |
| 合成方式 | Web Audio API 实时合成（OscillatorNode/BufferSource + GainNode 包络），**禁止外部音频文件** |
| 触发时机 | 见 AC-09.4；操作被拒绝不触发（AC-09.3） |
| 可区分性 | 7 类音效基频/音色互不相同（AC-09.1 可测量） |
| 并发上限 | 同时发声实例 ≤ 4，超出丢弃新请求（防堆叠/泄漏，AC-09.8） |
| 默认音量 | 80%（范围 0–100%，步进 ≤ 10%，AC-10.4） |
| 静音默认 | 关；`M` 键任意态切换；静音 = 主输出增益 0（AC-10.3） |
| 会话保持 | 音量/静音跨「结束 → 重新开始」保持，页面刷新重置默认（AC-10.5） |

### 5.3 幽灵块规格（v2.2 新增）

| 项目 | 规格 |
|---|---|
| 核心纯函数 | `ghostY(board, piece)`（或同义导出）：返回当前方块（type/rot/x/y）垂直下落可到达的最大 y（复用 `collides` 语义，垂直直线、无踢墙）；`collides` 本身**不改**，仅在其上增加循环 |
| 计算语义 | 从 `piece.y` 开始，逐步 `y+1` 直至 `collides(board, {…y+1})` 为真，取最后一个非碰撞 y 为落点；与硬降（AC-03.5/硬降路径）位置一致 |
| 渲染 | 半透明轮廓（同色系、暗色玻璃基调下可辨识；透明度/线宽可编程测量），叠加于游戏板当前方块正下方；不响应输入 |
| 刷新时机 | 移动/旋转/软降/自动下落成功后同帧重算重绘（≤ 100ms，AC-12.2~12.4） |
| 状态覆盖 | PLAYING 实时可见；PAUSED 冻结；READY/GAME_OVER 不显示（AC-12.9） |
| 落点一致性 | 幽灵块位置与「硬降实际固定位置」偏差 0 格（AC-12.1，自动化断言 + 硬降对照实测） |
| 非目标 | 无踢墙/侧滑、无可配置开关/透明度设置、不参与逻辑 |

## 7. 依赖与风险

### 7.1 依赖
- **运行时**：现代浏览器（Chrome/Edge ≥ 90、Firefox ≥ 95、Safari ≥ 15），依赖 `backdrop-filter`、`requestAnimationFrame`、ES6 语法。
- **引擎既有 `collides`**：幽灵块落点计算复用 `game.js` 已导出的 `collides(board, piece)` 纯函数语义（v2.2 不改其实现）。
- **零外部依赖**：不引入任何 CDN 库、字体、图片、音频文件；全部资源内联或本地相对路径。

### 7.2 风险与缓解
| 风险 | 影响 | 缓解 |
|---|---|---|
| 老浏览器不支持 `backdrop-filter` | 毛玻璃失效 | 半透明背景色兜底，核心玩法不受影响 |
| `file://` 下模块加载受限（ES Module/CORS） | 游戏无法运行 | 全部代码内联于单个 `index.html`，禁用模块加载 |
| 页面失焦导致定时器漂移/堆叠 | 下落节奏错乱 | 基于 `performance.now()` 差值计时 + 失焦自动暂停 |
| 键盘焦点丢失（点击按钮后方向键失效） | 操作失灵 | 全局 `keydown` 监听于 `window`，或点击后回焦游戏容器 |
| 高速下落下碰撞边界竞态 | 方块越界/穿透 | 单一时钟循环内「移动→碰撞→固定」原子处理 |
| 帧率不足 | 体验卡顿 | 渲染仅用 Canvas/单层 DOM 重绘，逻辑与渲染分离，目标 ≥ 55 FPS |
| 浏览器自动播放策略阻止 AudioContext | 无声/报错 | 首次用户交互时创建并 resume；失败则无声降级、0 报错 |
| 高频操作导致音效堆叠/节点泄漏 | 爆音、卡顿、内存增长 | 并发上限 ≤ 4，节点用后即 stop+disconnect，`dispose()` 统一清理 |
| 音效阻塞主线程 | 帧率下降、操作延迟 | 合成器纯函数化、事件回调内同步调度（≤ 50ms） |
| **幽灵块计算/渲染改动引入回归（v2.2 新增）** | 破坏碰撞/状态机/快捷键/音效 | 落点计算为**新增纯函数**（不改 `collides` 实现），渲染为**新增叠加层**；E2E 补 AC-12 断言，回归 AC-01~11 全绿 |
| **幽灵块落点与硬降不一致（v2.2 新增）** | 玩家误判 | 复用 `collides` 语义、垂直直线同循环；自动化断言落点 = 硬降位置偏差 0 格（AC-12.1）+ 硬降对照实测 |
| **旋转后形状轮廓致落点歧义（v2.2 新增）** | 视觉错位 | 严格按 piece 旋转后 `rot` 的边界格集合计算投影，单测覆盖 I/S/Z 旋转样例（AC-12.3） |
| **幽灵块可辨识度不足（v2.2 新增）** | 暗色玻璃下看不清 | 同色系半透明轮廓 + 边框反衬（可编程测透明度/线宽）；目测归人工补测（AC-12.11，环境限制非缺陷） |
