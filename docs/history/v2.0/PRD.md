## 1. 背景与目标

### 1.1 背景
v1.0 已交付完整游戏闭环（开始 → 游玩 → 得分 → 难度升级 → 结束 → 重新开始）并通过 QA 功能验收。
本次为 AGENTS.md §6 登记的 P2 待办「音效」的迭代落地：为关键操作与事件提供即时、可区分的听觉反馈，提升沉浸感与可玩性；同时严格保持产品自包含、零外部依赖的交付约束。

### 1.2 目标
1. **流程闭环**：开始、暂停、结束、重新开始四个状态完整可切换，无死锁状态。
2. **得分系统**：按消除行数计分，分数实时可见且计算正确。
3. **难度递进**：消除行数达到阈值后升级，等级越高下落速度越快。
4. **科技玻璃风格 UI**：深色背景、毛玻璃质感、霓虹光效、信息面板，视觉风格统一。
5. **自包含交付**：双击 `index.html` 即可在 `file://` 协议下离线游玩，无网络请求、无构建步骤。
6. **操作音效反馈（v2.0 新增）**：移动/旋转/软降/硬降/消行/升级/游戏结束七类事件均有 Web Audio API 实时合成的音效，**零外部音频文件**。
7. **音量可控（v2.0 新增）**：提供音量调节与静音开关（`M` 键 + 信息面板按钮），UI 遵循既有 DESIGN token 的最小改动。
8. **回归零破坏（v2.0 新增）**：不改变既有玩法、计分、难度数值与键盘操作，AC-01 ~ AC-08 语义不变。

### 1.3 成功指标（可量化）
| 指标 | 目标值 | 测量方式 |
|---|---|---|
| 首屏可玩时间 | ≤ 500ms（本地加载） | DevTools Performance 面板 |
| 游戏运行帧率 | ≥ 55 FPS（普通 PC，Chrome/Edge） | DevTools FPS 计数 |
| 控制台报错 | 0 条（完整游玩 5 分钟，含高频操作） | DevTools Console |
| 外部网络请求 | 0 个（含 0 个音频请求） | DevTools Network 面板 |
| 断网可用 | 100% 功能可用 | 离线模式（Network → Offline）游玩验证 |
| 音效触发延迟（v2.0） | ≤ 50ms（事件发生 → 发声） | 事件回调内同步调度合成器，Performance 采样 |
| 静音输出（v2.0） | 静音开启后 0 个可闻输出 | 输出节点增益置 0 / muted 标志可编程验证 + 听测 |
| 音频资源（v2.0） | 0 个外部音频文件 | 仓库文件审计（无 .mp3/.wav/.ogg/.m4a）+ Network 面板 |

## 2. 用户故事与验收标准

> 验收标准均为可执行测试项；测试在 Chrome/Edge 最新稳定版、`file://` 直接打开 `index.html` 场景下执行。
> **（v2.0）** 新增 US-09 / US-10（AC-09 / AC-10）；既有 AC-01 ~ AC-08 保留且语义不变，为本版回归底线。

### US-01 开始游戏
作为玩家，我打开页面后可以立即开始游戏，无需任何配置。
**验收标准（AC-01）**
1. 双击 `index.html` 后页面在 2 秒内渲染出完整游戏界面，无白屏。
2. 页面初始展示"开始"按钮与完整游戏板（10 列 × 20 行，行/列数可实测）。
3. 点击"开始"后 300ms 内进入游戏进行态，首个方块在游戏板顶部出现并可操作。
4. 初始分数为 0，初始等级为 1，消除行数为 0。

### US-02 移动与旋转方块
作为玩家，我可以用键盘控制当前方块。
**验收标准（AC-02）**
1. 方向键 `←`/`→` 将方块左右移动 1 格，按住不放时以 ≥ 8 次/秒的重复速率连续移动。
2. 方向键 `↓` 使方块加速下落 1 格（软降），按住持续软降。
3. 方向键 `↑`（或 `X`）使方块顺时针旋转 90°。
4. 方块移动/旋转受边界与已堆积方块阻挡：紧贴左右墙或障碍时操作被拒绝，方块位置不变，游戏不报错。
5. 所有操作响应延迟 ≤ 100ms（帧内即时响应）。

### US-03 自动下落与消行
作为玩家，方块会自动下落，整行填满后消除并得分。
**验收标准（AC-03）**
1. 方块按当前等级对应间隔自动下落（见 §5 速度表，实测误差 ≤ 50ms）。
2. 一行 10 格全部被方块占据时，该行立即消失，上方所有行整体下移 1 行。
3. 一次下落同时填满多行时，按实际行数一次性消除（2/3/4 行均可）。
4. 消除后分数按 §5 计分公式增加，消除行数计数同步增加。
5. 方块触底（下方为障碍或地板）后 500ms 内固定，下一个方块出现。

### US-04 暂停与恢复
作为玩家，我可以在游戏进行中暂停，之后恢复。
**验收标准（AC-04）**
1. 游戏进行中按 `P`（或 `Esc`）在 300ms 内进入暂停态，界面显示"已暂停"遮罩。
2. 暂停期间方块不自动下落，所有按键（除恢复键）不改变游戏状态。
3. 暂停期间按 `P`（或 `Esc`）恢复，方块位置、分数、等级与暂停前完全一致。
4. 页面失去焦点（切换标签页）时自动暂停；恢复焦点不自动恢复（需玩家手动恢复或明确提示）。

### US-05 游戏结束与重新开始
作为玩家，方块堆到顶部时游戏结束，我可以重新开始。
**验收标准（AC-05）**
1. 新方块无法完整放入顶部出生区域时，游戏进入结束态，显示"游戏结束"遮罩与最终分数。
2. 结束态下所有方块停止运动，方向键不再产生效果。
3. 结束态点击"重新开始"按钮（或按 `R`）后 300ms 内重置：分数 0、等级 1、消除行数 0、游戏板清空、可立即游玩。
4. 连续执行 5 次"结束 → 重新开始"循环，无任何报错、无状态残留（旧方块不可见）。

### US-06 计分与升级
作为玩家，我能实时看到分数、等级、消除行数，且难度随等级提升。
**验收标准（AC-06）**
1. 信息面板实时显示：分数、等级、消除行数、下一个方块预览，数值刷新延迟 ≤ 200ms。
2. 消除行数累计达到 10 的整数倍时等级 +1（实测：第 10 行 → 等级 2；第 20 行 → 等级 3）。
3. 升级瞬间下落间隔按 §5 速度表缩短，实测新旧间隔差值 ≤ 10ms 偏差。
4. 升级时界面给出可见反馈（如"LEVEL UP"提示，显示时长 800ms ± 200ms）。
5. 计分公式（见 §5）用自动化脚本对 1/2/3/4 行消除分别验证，结果与公式 100% 一致。

### US-07 视觉风格
作为玩家，我感受到统一的科技玻璃风格。
**验收标准（AC-07）**
1. 页面背景为深色（背景主色亮度 ≤ 15%），非纯白/浅色。
2. 游戏板与信息面板使用毛玻璃效果：CSS `backdrop-filter: blur()` 生效（实测面板背后内容呈模糊）。
3. 当前方块、已固定方块、边框/按钮呈现 ≥ 1 种霓虹光效（`box-shadow` 或 `text-shadow` 发光）。
4. 信息面板与游戏板在 1920×1080、1366×768 两种分辨率下无错位、无遮挡。
5. 游戏板网格线可见，方块颜色按 7 种方块类型可区分（色相不同）。

### US-08 自包含与离线
作为玩家，我在无网络环境下双击文件即可游玩。
**验收标准（AC-08）**
1. 整个游戏仅由 `index.html`（内联全部 CSS/JS）构成，或 `index.html + 本地 css/js` 组成，不存在任何 `http(s)://` 外部资源引用。
2. DevTools Network 面板显示 0 个网络请求。
3. 断网（Network → Offline）状态下完整游玩一轮（开始 → 结束 → 重新开始），功能与联网一致。
4. 双击文件在 Chrome/Edge/Firefox 最新版均可正常游玩。

### US-09 游戏音效（v2.0 新增）
作为玩家，我在操作与关键事件发生时听到即时、可区分的合成音效，且游戏不依赖任何外部音频文件。
**验收标准（AC-09）**
1. 七类事件各有独立音效：移动（←/→ 成功移动）、旋转、软降、硬降、消行、升级、游戏结束；任意两类音效可区分（听辨可分辨，且基频实测差值 ≥ 50Hz 或波形/包络参数不同）。
2. 每个事件触发且仅触发一次对应音效：单次成功移动 = 1 次移动音效；单次消行动作（含一次消 2/3/4 行）= 1 次消行音效，不叠加；进入 GAME_OVER 态 = 1 次结束音效。
3. 音效仅在操作"成功"时触发：被边界/障碍拒绝的移动或旋转不触发音效。
4. 触发时机与事件同步：消行音效与行消除同时；升级音效与 LEVEL UP 提示同时（≤ 200ms）；结束音效与 GAME_OVER 遮罩出现同时（≤ 300ms）；硬降音效在方块落底固定时触发。
5. 音效为 Web Audio API 实时合成：项目中不存在任何音频文件（无 .mp3/.wav/.ogg/.m4a）与 `<audio>`/`<source>` 元素；DevTools Network 面板 0 个音频请求；无任何外部音频依赖。
6. 自动播放策略：页面加载后、首次用户交互前不发声且控制台 0 报错；首次交互（任意按键/点击）后 AudioContext 激活，此后音效正常。
7. 降级：浏览器不支持或未激活 Web Audio 时，游戏玩法、计分、键盘操作 100% 正常，控制台 0 报错，仅无声。
8. 性能：音效播放不阻塞游戏逻辑（操作响应仍 ≤ 100ms，AC-02.5）；60 秒高频连续操作（持续移动/软降/硬降）后无控制台报错、无音频节点泄漏（并发发声实例有上限、超出丢弃）、FPS 保持 ≥ 55（§1.3）。

### US-10 音量控制与静音（v2.0 新增）
作为玩家，我可以随时调整音量或静音，控制方式与界面遵循既有风格。
**验收标准（AC-10）**
1. 信息面板新增音量控件区：静音切换按钮 + 音量调节（−/+ 步进或滑块），复用既有玻璃面板/按钮 token（DESIGN §5.1/§5.3），不引入新视觉风格；控件加入后 1920×1080 / 1366×768 布局无错位、无遮挡（AC-07.4 仍成立）。
2. 按 `M` 键在任意游戏态（READY/PLAYING/PAUSED/GAME_OVER）切换静音；切换后按钮图标/文案与 `aria-pressed` 状态在 ≤ 200ms 内同步。
3. 静音开启后所有事件不产生可闻输出（可编程验证：主输出增益为 0 或 muted 标志生效；听测确认无声）；关闭后立即恢复，无需重新激活 AudioContext。
4. 音量范围 0–100%，默认 80%，调节步进 ≤ 10%；调节即时生效（下一次音效即按新音量）；音量 0% 与静音态听觉等效；任意音量下无爆音/削波（输出峰值 ≤ 1.0）。
5. 音量与静音设置跨"结束 → 重新开始"保持（会话内持续）；页面刷新后恢复默认（音量 80%、静音关）。
6. 控件可访问性：按钮可 Tab 聚焦并有 `:focus-visible` 焦点环；读屏可读出状态（`aria-label` + `aria-pressed`）；静音状态不只靠图标颜色表达（图标形态变化 + 文本/aria 双信号）。

## 4. 交互流程概述

```
[待开始 READY] --点击"开始"/回车--> [进行中 PLAYING]
[进行中] --按 P/Esc/失焦--> [暂停 PAUSED]
[暂停] --按 P/Esc--> [进行中]
[进行中] --方块堆顶--> [结束 GAME_OVER] --点击"重新开始"/按 R--> [待开始或直接进行中]
```

- **READY**：展示游戏板、开始按钮、空面板；方块不活动；音量控件可用。
- **PLAYING**：自动下落循环运行，键盘操作生效；成功操作与事件触发音效。
- **PAUSED**：下落定时器停止；显示遮罩；仅恢复键生效；失焦自动暂停。
- **GAME_OVER**：所有方块停止；显示最终分数；结束音效已触发；仅"重新开始"生效。

**v2.0 新增交互**：
1. 首次用户交互（点击/按键）时创建并激活 AudioContext（满足浏览器自动播放策略）；激活前不发声、不报错。
2. `M` 键在任意游戏态切换静音；静音态下事件不发声，按钮状态同步。
3. 信息面板新增音量控件区（静音按钮 + 音量调节），沿用玻璃卡片与按钮样式；点击后焦点归还游戏容器（与既有控制按钮一致，防止方向键误触发）。

页面布局（自上而下/自左而右）：顶部标题 → 中部（左：信息面板：分数/等级/行数/下一个方块/音量控件）→ 中：游戏板 → 右/下：操作说明与控制按钮。所有面板采用毛玻璃卡片，霓虹描边。

## 5. 游戏规则与数值规格（实现基准）

### 5.1 既有规格（v1.0，不变）

| 项目 | 规格 |
|---|---|
| 游戏板 | 10 列 × 20 行 |
| 方块种类 | 7 种标准 Tetromino（I/O/T/S/Z/J/L），每方块 4 格 |
| 出生位置 | 顶部中间（列 4–5 区域），方块完全可见 |
| 旋转 | 顺时针 90°，单点旋转（无踢墙高级规则） |
| 硬降（空格） | 方块立即落底固定，并按硬降格数加分（每格 +1） |
| 计分公式 | 单次消行：1 行=100、2 行=300、3 行=500、4 行=800；乘以当前等级倍率（×1/×2/×3…，等级 L 倍率 = L） |
| 升级阈值 | 累计消除行数每满 10 行升 1 级（L1→L2 需 10 行，L2→L3 需 20 行，依此类推） |
| 下落速度 | 等级 L 下落间隔 = `max(100, 1000 × 0.85^(L−1))` ms（L1≈1000ms，L2≈850ms，L3≈723ms，下限 100ms） |
| 游戏结束 | 新方块出生即与已固定方块碰撞 |
| 输入映射 | ←/→ 移动，↑/X 旋转，↓ 软降，空格 硬降，P/Esc 暂停，R 重新开始 |

### 5.2 音效规格（v2.0 新增）

| 项目 | 规格 |
|---|---|
| 事件集 | 移动、旋转、软降、硬降、消行、升级、游戏结束（7 类） |
| 合成方式 | Web Audio API 实时合成（OscillatorNode/BufferSource + GainNode 包络），**禁止外部音频文件** |
| 触发时机 | 见 AC-09.4；操作被拒绝不触发（AC-09.3） |
| 可区分性 | 7 类音效基频/音色互不相同（AC-09.1 可测量） |
| 并发上限 | 同时发声实例 ≤ 4，超出丢弃新请求（防堆叠/泄漏，AC-09.8） |
| 默认音量 | 80%（范围 0–100%，步进 ≤ 10%，AC-10.4） |
| 静音默认 | 关；`M` 键任意态切换；静音 = 主输出增益 0（AC-10.3） |
| 会话保持 | 音量/静音跨"结束 → 重新开始"保持，页面刷新重置默认（AC-10.5） |
| 具体合成参数 | 波形/基频/时长/包络由技术方案定义并落盘 `docs/technical/TECHNICAL.md`，须满足 AC-09 全部验收 |

> 说明：本 PRD 只钉行为与可测约束；具体合成参数（波形、基频、时长、包络）属技术方案范畴，不在本 PRD 内定死。

## 7. 依赖与风险

### 7.1 依赖
- **运行时**：现代浏览器（Chrome/Edge ≥ 90、Firefox ≥ 95、Safari ≥ 15），依赖 `backdrop-filter`、`requestAnimationFrame`、ES6 语法。
- **Web Audio API（v2.0 新增）**：上述浏览器均支持 `AudioContext`（Safari 15 起支持无前缀）；不引入任何第三方音频库/音频文件。
- **零外部依赖**：不引入任何 CDN 库、字体、图片、音频文件；字体使用系统字体栈；全部资源内联或本地相对路径。

### 7.2 风险与缓解
| 风险 | 影响 | 缓解 |
|---|---|---|
| 老浏览器不支持 `backdrop-filter` | 毛玻璃失效 | 提供降级（半透明背景色兜底），核心玩法不受影响 |
| `file://` 下模块加载受限（ES Module/CORS） | 游戏无法运行 | 全部代码内联于单个 `index.html`，禁用模块加载 |
| 页面失焦导致定时器漂移/堆叠 | 下落节奏错乱 | 使用基于 `performance.now()` 的差值计时 + 失焦自动暂停 |
| 键盘焦点丢失（点击按钮后方向键失效） | 操作失灵 | 全局监听 `keydown` 于 `window`，或点击后回焦到游戏容器 |
| 高速下落下碰撞边界竞态 | 方块越界/穿透 | 统一单一时钟循环内完成"移动→碰撞→固定"原子处理 |
| 帧率不足 | 体验卡顿 | 渲染仅用 Canvas/单层 DOM 重绘，逻辑与渲染分离，目标 ≥ 55 FPS |
| 浏览器自动播放策略阻止 AudioContext（v2.0） | 无声/报错 | 首次用户交互（点击/按键）时创建并 resume AudioContext；失败则无声降级、0 报错（AC-09.6/7） |
| 高频操作导致音效堆叠/节点泄漏（v2.0） | 爆音、卡顿、内存增长 | 并发实例上限 ≤ 4，节点用后即 stop+disconnect，`dispose()` 统一清理（AC-09.8） |
| 音效阻塞主线程（v2.0） | 帧率下降、操作延迟 | 合成器纯函数化、事件回调内同步调度（≤ 50ms），逻辑/渲染分离不受影响（§1.3 复测） |
| 音量控件破坏既有布局（v2.0） | 分辨率适配回归 | 控件并入左信息面板底部，复用既有 token 与栅格，回归 AC-07.4 |
