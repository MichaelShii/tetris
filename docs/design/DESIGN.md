## 0. 现状与约束（先读）

1. **工作区无既有代码/设计系统**：`tetris/` 下仅有 `PRD.md`。因此不存在可复用的既有 token 或组件规范，本文档从零定义一套 token（见 §6），以 CSS 自定义属性形式交付，前端直接采用即可。
2. **PRD 硬约束（不可协商）**：
   - 视觉风格为「科技玻璃」：深色背景（背景主色亮度 ≤ 15%）、毛玻璃 `backdrop-filter: blur()` 生效、霓虹光效 ≥ 1 种、信息面板（AC-07）。
   - 零外部依赖：禁止 CDN 库/字体/图片，字体用系统字体栈（§7.1）。
   - 单文件内联：不使用 ES Module、不发起任何网络请求（AC-08）。
   - 仅键盘操作、桌面优先；兼容 Chrome/Edge ≥ 90、Firefox ≥ 95、Safari ≥ 15。
   - 运行帧率 ≥ 55 FPS、操作响应 ≤ 100ms、数值刷新 ≤ 200ms（§1.3、AC-02/AC-06）。
3. **设计定位**：玻璃与霓虹是 PRD 强制项，但按「product register」克制使用——毛玻璃仅用于静态面板与遮罩（不做动画、不做全屏铺满），霓虹光效用于「状态与反馈」，不用于装饰堆砌。游戏的记忆点来自「深空黑 + 靛紫/琥珀双辉光 + 7 色霓虹方块」的组合，而非玻璃本身。
4. **【v2.2】本次变更边界**：幽灵块为**纯显示增强**（AC-12），设计上严格零回归：
   - 不改变既有**布局结构**（仍为 §2.1 三列 grid，幽灵块仅叠加于游戏板 Canvas 内，不新增 DOM 层）；
   - 不改变既有**视觉 token**（§5.1 全部颜色/字号/间距/间距原样保留），幽灵块复用方块同色系 + 既有 `--board-bg` 暗底对比；
   - 不改变既有**值/状态机/快捷键/音效**（引擎新增纯函数 `ghostY`，不改 `collides`/`keyAction`/数值/音效）。
5. **【v2.2】幽灵块视觉定位**：幽灵块遵循「product register」克制原则——它是「可辨识的落点提示」而非装饰。采用**同色系低饱和半透明轮廓**（空心描边 + 极低填充），亮度与饱和度**低于**实体方块（P1 界面让位于方块），但仍保证暗色玻璃底上清晰可辨（AC-12.8）。无动画、无辉光脉冲、无独立层级，绝不抢走玩家对实体块/消行/状态的注意力。

## 1. 设计定位与原则

### 1.1 氛围一句话（调色板锚点）

> 「深夜霓虹街机厅：近乎纯黑的空间里，玻璃面板折射靛紫与琥珀金双色辉光，方块如霓虹灯管逐格点亮。」

依据：玩家在昏暗环境、专注单机游玩、追求沉浸与即时反馈。该场景强制选择**深色主题**；配色策略为「UI 层克制（近黑中性 + 靛紫/琥珀金 ≤ 15% 点缀），游戏对象层全彩（7 种方块即调色板本体）」。

### 1.2 设计原则（5 条）

| # | 原则 | 落地 |
|---|---|---|
| P1 | **界面让位于方块** | 板面是唯一焦点；面板/按钮只承担信息与操作，亮度与饱和度均低于方块 |
| P2 | **状态即光效** | 霓虹只表达状态与反馈：当前方块发光、固定方块弱光、消行闪白、升级金光、结束红光 |
| P3 | **毫秒级响应** | 所有操作反馈 ≤ 100ms 内完成（帧内处理），数值变化 ≤ 200ms 可见（AC-02/AC-06） |
| P4 | **动效服务于节奏** | 动效时长 ≤ 800ms，缓动用 ease-out 指数曲线；`prefers-reduced-motion` 时全部降级为瞬时/淡化 |
| P5 | **自包含即优雅** | 系统字体栈 + 内联资源 + 逐项降级（backdrop-filter、OKLCH、网格），老浏览器核心玩法不失效 |

## 2. 页面/模块清单与信息架构

### 2.1 信息架构（单页应用结构树）

```
┌─ <body>
│  ├─ 背景层（page-bg）         静态径向渐变 + 微弱网格纹理（非装饰性，提供玻璃可折射的"背后内容"）
│  ├─ 顶部标题区（header）
│  │   ├─ 标题 "TETRIS"（霓虹字效）
│  │   └─ 状态指示灯（READY/PLAYING/PAUSED/GAME OVER 四态小圆点 + 文本）
│  ├─ 主区（main，3 列 CSS Grid）
│  │   ├─ 左信息面板（panel-left）
│  │   │   ├─ 统计块：分数（score）
│  │   │   ├─ 统计块：等级（level）
│  │   │   ├─ 统计块：消除行数（lines）
│  │   │   └─ 下一个方块预览（next-well）
│  │   ├─ 游戏板（board）        Canvas：10×20 网格、当前方块、已固定方块、网格线、**【v2.2】幽灵块落点轮廓**
│  │   └─ 右操作面板（panel-right）
│  │       ├─ 操作说明（key-hints：←→ ↑ X ↓ 空格 P/R 键位图例）
│  │       └─ 控制按钮组（btn-start / btn-pause / btn-restart）
│  ├─ 遮罩层（overlay）
│  │   ├─ READY 遮罩（开始）
│  │   ├─ PAUSED 遮罩（已暂停）
│  │   └─ GAME OVER 遮罩（结束 + 最终分数 + 重新开始）
│  └─ 反馈层（feedback）
│      ├─ LEVEL UP toast（升级提示，800ms）
│      └─ 分数变化高亮（由左面板内联触发，非独立层）
```

### 2.2 模块清单

| 模块 | 职责 | 技术实现 | 交互状态 |
|---|---|---|---|
| page-bg | 提供深色底与玻璃折射源 | CSS 渐变 + 重复线性网格（极低透明度） | 静态 |
| header | 标题 + 游戏状态指示 | DOM + CSS 霓虹字效 | 随游戏态变化文字/颜色 |
| panel-left | 分数/等级/行数/下一个方块 | DOM（数值）+ 迷你 Canvas（预览） | 分数变化时高亮动效 |
| board | 网格、当前/固定方块渲染 + **【v2.2】幽灵块落点轮廓** | 单个 `<canvas>`（唯一渲染层） | PLAYING 实时重绘；PAUSED 冻结 |
| panel-right | 键位图例 + 控制按钮 | DOM | 按钮随状态启用/禁用 |
| overlay | 三态遮罩（开始/暂停/结束） | DOM + 玻璃面板 + 焦点管理 | READY/PAUSED/GAME_OVER |
| feedback | LEVEL UP 提示 | DOM toast | 升级瞬间，800ms |

### 2.3 状态机视图（四态 × 模块可见性）

| 模块 \ 状态 | READY 待开始 | PLAYING 进行中 | PAUSED 暂停 | GAME_OVER 结束 |

| 开始按钮 | 可用（主） | 隐藏/禁用 | 隐藏/禁用 | 隐藏/禁用 |

- 三列固定宽度：`240px | 340px | 240px`，水平居中，列间距 24px；总宽约 868px，1366×768 与 1920×1080 均无遮挡（AC-07.4）。
- 游戏板宽高：10 列 × 28px = 280px + 内边距 16×2 = 312px，置于 340px 列中；20 行 × 28px = 560px + 内边距 32px = 592px，加 header 64px 与上下留白，768px 高度内完整容纳。
- 窗口 ≤ 1100px 时（非验收范围，兼容处理）：右面板折叠至游戏板下方成单列堆叠，面板保持同宽。

```
┌─────────────────────────────┐
│         TETRIS              │
│   ◉ READY                   │
│  ┌───────────────────────┐  │
│  │                       │  │

│  │                       │  │
│  │   ┌─────────────┐     │  │

│  │   │  回车 / 空格  │     │  │
```

- 遮罩覆盖**游戏板区域**（非全页），毛玻璃 + 轻微模糊，露出空板与面板数值（分数 0、等级 1、行数 0，AC-01.4）。

- 遮罩打开时焦点落在「开始游戏」按钮上（键盘回车即可开始）。

### 3.3 PAUSED 态

```
┌─────────────────────────────┐
│         TETRIS              │
│   ◉ PAUSED                  │
│  ┌───────────────────────┐  │
│  │      ▓▓▓▓▓▓▓▓▓▓       │  │
│  │    ║  已暂停          ║  │  ← 半透明遮罩 + blur，当前棋盘冻结
│  │    ║  P / Esc 继续    ║  │
│  │    ║  [继续游戏]      ║  │
```

- 触发：PLAYING 中按 `P`/`Esc`，或页面失焦（`visibilitychange`/`window blur`）自动暂停（AC-04.1/4）。
- 遮罩内显示「已暂停」+ 恢复提示；按 `P`/`Esc` 或点「继续游戏」恢复，状态与暂停前完全一致（AC-04.3）。
- 恢复后焦点回到游戏容器，方向键立即可用。

```

│         TETRIS              │
│   ◉ GAME OVER               │
│  ┌───────────────────────┐  │
│  │      ▓▓▓▓▓▓▓▓▓▓       │  │
│  │    ║  GAME OVER       ║  │  ← 红光描边 + 玻璃遮罩
│  │    ║  最终分数 012340  ║  │
│  │    ║  [重新开始]       ║  │
```

- 触发：新方块出生即碰撞（AC-05.1）；方向键全部失效（AC-05.2）。
- 遮罩含「最终分数」（大号霓虹数字）+ 主按钮「重新开始」；按 `R` 或回车等效（AC-05.3）。
- 重新开始 = 分数 0、等级 1、行数 0、棋盘清空、立即进入 PLAYING；连续 5 轮无状态残留（AC-05.4）。

| 组件 | 结构 | 状态 |

| 下一个预览 | 迷你 Canvas（4×2 格，格 12px），外框琥珀金细描边 | 有方块 / 空（READY 时） |
| 主按钮 | 玻璃底 + 靛紫描边 + 靛紫辉光；主操作占位 | 默认/悬停/按下/聚焦/禁用 |

### 3.6 【v2.2】幽灵块（落点预览）线框

幽灵块并非新页面/新 DOM 层，而是**游戏板 Canvas 内部的叠加渲染**（§2.1 结构不变）。它表现为：当前下落方块**正下方**、以其**垂直落点**为基准的**同色系半透明空心轮廓**（见下）。

```
┌──────────────────────────────┐
│   ▣▣                        │
│     ▣▣                      │   ← 当前方块（实体，含辉光）
│                              │
│                              │
│                              │
│   ╭╮                          │
│   ╰╯                        │   ← 幽灵块轮廓（半透明、同色、无辉光）
│   ╭╮                          │      与当前方块同 x、同轮廓，垂直投影
│   ╰╯                        │      落点 = 垂直直线下潜最大非碰撞深度
└──────────────────────────────┘
```

| 属性 | 规范（对应 AC-12） |
|---|---|
| 位置 | 与当前方块**同 x、同 rot、同形状轮廓**，y = `ghostY(board, piece)`（引擎纯函数返回值）；与「硬降实际固定位置」**偏差 0 格**（AC-12.1） |
| 形态 | 空心描边轮廓（不填充实体），复用方块同色系（§5.6）；明显区别于实体方块（AC-12.8） |
| 刷新 | 随移动/旋转/软降/自动下落**同帧**重绘（AC-12.2~12.4）；位置始终 = 当前方块垂直下潜最大深度 |
| 状态 | PLAYING 实时可见；PAUSED 冻结（随恢复继续）；READY/GAME_OVER 不显示（AC-12.9） |
| 交互 | 纯显示，不响应输入、不参与碰撞/消行/计分/固定（AC-12.6） |
| 层级 | 绘制在**已固定方块之上、当前实体方块之下**（或先于实体块绘制），确保实体方块不被遮挡（AC-12.8） |

> 设计决策：纵深参考「当前方块上方是否存在掩体」——当上方有已固定方块掩体时，幽灵块落点即掩体之上（AC-12.5），此时幽灵块与掩体可能相邻，轮廓描边需足够清晰以区分（人工补测项，§8）。

## 4. 交互与动效说明

### 4.1 输入映射（全局 `window` 级 `keydown`，`preventDefault` 拦截方向键/空格防页面滚动）

| 按键 | 行为 | 参数/规格（对应 PRD §5、AC-02） |
|---|---|---|
| ← / → | 左右移动 1 格 | 按住 DAS：初始延迟 170ms，重复间隔 100ms（≥8 次/秒，AC-02.1）；移动受边界与障碍阻挡时保持原位不报错（AC-02.4） |
| ↑ / X | 顺时针旋转 90° | 单点旋转（无踢墙），碰撞即拒绝（AC-02.3/4） |
| ↓ | 软降 1 格 | 按住重复 50ms；触底 500ms 内固定（AC-02.2、AC-03.5） |
| 空格 | 硬降（PLAYING，每格 +1 分）/ 继续（PAUSED，v2.1）/ 重开（GAME_OVER，v2.1） | 立即落底固定，每格 +1 分（PRD §5）；PAUSED 态按 phase 分流为「继续」（AC-11.2）；GAME_OVER 态为「重新开始」（AC-11.6/D-01 甲） |
| P / Esc | 暂停/恢复 | 300ms 内状态切换（AC-04.1）；暂停中 P/Esc/R/空格 生效（空格=继续，v2.1；AC-04.2/AC-11.2） |
| R | 重新开始 | READY/PAUSED/GAME_OVER 均可用；PLAYING 中按 R 也直接重开（明确提示文案） |
| 回车 | READY 开始 / GAME_OVER 重开 | 与主按钮等效 |

> 失焦自动暂停：`document.visibilitychange` 隐藏 或 `window` 失焦 → 自动进入 PAUSED；恢复焦点不自动恢复，遮罩内提示（AC-04.4）。

### 4.2 关键交互时序

1. **开始**：点击「开始游戏」→ 遮罩淡出 160ms → 状态置 PLAYING → 首个方块出生 → 下落时钟启动（首个方块即可操作，AC-01.3）。
2. **暂停/恢复**：按 P → 时钟停止 + 遮罩淡入 160ms；按 P 恢复 → 时钟续跑，下落间隔从暂停前位置继续（差值计时，不重置）。
3. **消行反馈**：整行填满 → 该行闪白 140ms → 上方行下移；同时分数/行数刷新并高亮（AC-03.2/4）。
4. **升级反馈**：累计行数达 10 的倍数 → 下落间隔切换（按 `max(100, 1000×0.85^(L−1))`，AC-06.3）+ LEVEL UP toast 800ms ± 200ms（AC-06.4）+ 板框辉光脉冲一次。
5. **结束/重开**：堆顶碰撞 → 状态 GAME_OVER → 板框红光 → 遮罩淡入；按 R 或点按钮 → 全量重置 → 直接 PLAYING（AC-05.3）。

### 4.4 【v2.2】幽灵块交互与刷新时机（对应 AC-12）

幽灵块为**纯显示叠加**，不新增任何键盘映射、不改变任何既有按键语义（`keyAction` 零改动，AC-12.7）。它仅在既有快照（`getSnapshot()`/`onSnapshot`）基础上于渲染层**追加**计算与绘制：

| 触发 | 幽灵块行为 | 对应 AC |
|---|---|---|
| 游戏进入 PLAYING / 出生新方块 | 首次按当前块计算落点并渲染 | AC-12.9 |
| `←`/`→` 移动成功 | 同帧随新 x 重算落点并重绘（≤ 100ms） | AC-12.2 |
| `↑`/`X` 旋转成功 | 同帧按新 `rot` 轮廓重算落点并重绘（≤ 100ms；x 不变时投影随新形状变化） | AC-12.3 |
| `↓` 软降成功（1 格） | 同帧落点**上移 1 格**重绘（≤ 100ms） | AC-12.4 |
| 自动下落每步 | 同帧随 y 增长上移重绘（AC-03.1 联动） | AC-12.4 |
| 触底/锁定瞬间 | 幽灵块随当前块消失（块已固定，下次重算归属新块） | AC-12.6 |
| 进入 PAUSED | 幽灵块**原地冻结**（不重算、不重绘，随恢复继续） | AC-12.9 |
| READY / GAME_OVER | 幽灵块**不显示**（无当前下落方块） | AC-12.9 |

- **刷新机制**：幽灵块计算在渲染指令内联完成——每次 `renderAll(s)` 时用快照 `s.board + s.piece` 调用引擎纯函数 `ghostY` 得到落点，在 Canvas 绘制序列中先画已固定块 → 再画幽灵块 → 最后画当前实体块。因每次操作/下落必然触发 `emit → onSnapshot → renderAll`，天然满足「同帧刷新、帧内即时（≤ 100ms）」（AC-12.2~12.4、§1.3）。
- **不参与逻辑**：幽灵块不进行任何 `move/rotate/softDrop/hardDrop/clearLines/score` 写入，仅用于渲染（AC-12.6）。其存在与否对状态机、自动下落、硬降、音效触发零影响（AC-12.7）。
- **动效**：幽灵块**无独立动效、无动画、无辉光脉冲**（保持静态轮廓，避免与「方块固定/消行」动效混淆）。`prefers-reduced-motion` 下无需额外处理（本就无动画）。

> 性能红线（支撑 ≥55 FPS，PRD §7.2）：**不动画 `box-shadow` / `backdrop-filter` / `filter`**；辉光一律用「伪元素 + opacity 过渡」实现，交由合成器处理；游戏板为唯一逐帧重绘层（Canvas），面板 DOM 仅在数值变化时更新。**【v2.2】幽灵块为 Canvas 内静态绘制（同帧 drawImage/stroke），非动画层，不触发额外布局/合成开销（AC-12.10）**。

## 5. 视觉规范

> 全部色值以 **OKLCH** 为准（本文档为唯一事实来源）；同时给出近似 hex 作降级兜底。实现时先写 hex，再用 `@supports (color: oklch(...))` 覆盖为 OKLCH（兼容 Chrome/Edge ≥ 90、Firefox ≥ 95、Safari ≥ 15 中不支持 OKLCH 的旧版本）。

### 5.1 设计 Token（CSS 自定义属性）

```css
  --muted:         oklch(0.66 0.020 270);      /* ≈ #9a9aac  次级文字（对 bg 对比 ≈ 4.6:1 ≥ 3.5:1） */
```

### 5.4 响应式与分辨率适配（AC-07.4）

- **1920×1080**：三列居中，列间留白均匀，四周留白 ≥ 48px。
- **1366×768**：整体垂直方向刚好容纳（592px 板 + 64px header + 上下各 ~40px），无滚动条；若浏览器 UI 挤压高度，允许整页出现纵向滚动，但**游戏板与面板不得错位/遮挡**。
- 视口 ≤ 1100px：右面板移到板下方（单列堆叠），键盘玩法不变（仅作健壮性处理，非验收范围）。
- 不用流体字号（product register），仅用固定 rem + 布局级断点。

### 5.5 兼容性与降级（PRD §7.2 风险缓解的视觉侧）

| 能力 | 降级链 |
|---|---|
| `backdrop-filter` | `@supports (backdrop-filter: blur(1px))` 用毛玻璃；否则近实底半透明色（核心玩法不受影响，AC-07.2 在目标浏览器成立） |

### 5.6 【v2.2】幽灵块视觉规范（同色系半透明轮廓，对应 AC-12.8）

幽灵块绘制在**游戏板 Canvas 内**，复用方块的**同色系填色**（§5.2 `COLORS[type].fill`），以「空心描边 + 极淡填充」呈现；**无辉光**。数值以渲染层 hex 常量给出（Canvas 不消费 CSS 变量；CSS token `--ghost-*` 仅作规范记录）。

| 属性 | 规范 | 说明 |
|---|---|---|
| 描边色 | `COLORS[type].fill`（同色系） | 每型沿用自身霓虹色，色相不引入新色（AC-12.8 同色系） |
| 描边不透明度 | `0.75` | 暗底上仍清晰（测量项，AC-12.8）；与实体块高亮区分 |
| 描边线宽 | `2px`（css px，随 DPR 缩放） | 空心轮廓可辨识（AC-12.8） |
| 内部填充 | 同 `fill`，不透明度 `0.16` | 约为实体块（不透明）的 1/5，强化「空心/未落定」语义 |
| 辉光 | **无**（`--ghost-glow: none`） | 唯一发光者为实体块与固定块（P2 状态即光效），幽灵块刻意无光以区分「未落定」 |
| 顶部高光 | **无** | 实体块有 1px 白 25% 顶部灯管高光；幽灵块省略，避免与实体混淆 |
| 视觉层级 | 置于已固定块之上、当前实体块之下 | 实体方块永不被幽灵块遮挡（AC-12.8） |

> **优先级声明（P1 界面让位于方块）**：幽灵块亮度与饱和度均**严格低于**实体方块，保证「落点提示」被感知为「预测」而非「当前块」。若某分辨率下描边与实体辨识冲突，以**实体块优先、幽灵块降透明**为原则（人工补测项，§8）。

> **多边形/旋转覆盖**：旋转后 S/Z/I 等形状轮廓（对角无格）以「边界格集合描边」呈现，非整格填充——即只描 4 格单元的外沿，内部镂空，确保与实体块的旋转形状一一对应（AC-12.3；人工补测，§8）。

## 7. 性能注意（支撑 ≥ 55 FPS / 响应 ≤ 100ms，PRD §1.3）

1. **单一渲染层**：游戏板用**一个** `<canvas>`，逻辑与渲染分离；每帧仅重绘「脏区域或全板（200 格代价可控）」；面板为 DOM，仅在数值变化时更新（AC-06.1 ≤ 200ms 满足）。
2. **辉光实现**：所有辉光用「元素/伪元素 + `opacity` 过渡」，禁止逐帧动画 `box-shadow`/`filter`/`backdrop-filter`。
3. **计时**：基于 `performance.now()` 差值计时驱动下落（非 `setInterval` 堆叠），失焦自动暂停防漂移（PRD §7.2）。
4. **初始化**：首屏仅 1 个 Canvas + 少量 DOM，无字体/图片/网络加载（AC-01.1 ≤ 2s、§1.3 ≤ 500ms 均富余）。
5. **【v2.2】幽灵块性能**：落点计算 `ghostY` 为 O(ROWS) 纯循环（复用 `collides`，最多 20 步），渲染为 Canvas 内单次 `stroke/alpha` 绘制（非动画层、无布局/合成开销）；计算+重绘与既有渲染同栈，移动/旋转/软降/自动下落刷新 ≤ 100ms、含幽灵块渲染时 FPS ≥ 55（AC-12.10 回归 AC-09.8 量级）。
